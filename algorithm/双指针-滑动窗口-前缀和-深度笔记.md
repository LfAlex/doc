## 0. 全局地图：三者其实是同一件事

### 0.1 共同本质：用单调性消灭一层枚举

暴力解法的共同特征是"枚举所有候选对/候选区间"：

| 问题形态 | 暴力复杂度 | 优化后 |
|---|---|---|
| 所有区间 `[l, r]` | O(n²) 个区间，O(n³) 带求和 | O(n) / O(n²) |
| 所有二元组 `(i, j)` | O(n²) | O(n) |
| 所有三元组 | O(n³) | O(n²) |

三种技巧各自"消灭"哪一层枚举：

```
暴力：for l in 0..n-1: for r in l..n-1: 检查/计算 [l,r]
                    │
      ┌─────────────┼──────────────────┐
      ▼             ▼                  ▼
  区间内求和       枚举候选对          检查合法性
      │             │                  │
      ▼             ▼                  ▼
  前缀和折叠      双指针剪枝        滑动窗口 + 增量维护状态
  (O(1) 得和)   (证明被丢的不优)    (窗口状态 O(1) 更新)
```

一句话记忆：

- **双指针 = 剪枝**，核心是「证明被我丢掉的那一部分候选一定不可能更优」，这是**数学证明题**，不是技巧题。
- **滑动窗口 = 双指针 + 增量状态**，核心是「窗口状态的进入/退出都是 O(1)」+「左指针永不回退」。
- **前缀和 = 折叠**，核心是「区间信息 = 两个端点信息之差」，把 O(n) 的区间求和摊平成 O(1)，再用哈希/单调性把"找配对前缀"降到 O(1) 或均摊 O(1)。

### 0.2 决策树：看到题先问自己 5 个问题

```
Q1 数组有序吗？或排序的代价可接受吗（O(n log n) 不劣于目标复杂度）？
   └─ 是 → 相向双指针（LC 15 / 167 / 11 / 16）

Q2 求的是"子数组/子串"的某种最长/最短/计数吗？
   ├─ 是 → Q2.1 窗口的合法性对"扩大/缩小"是单调的吗？
   │        ├─ 单调（如：正数数组的和、字符计数、不同字符个数）
   │        │    └─ 是 → 变长滑动窗口（LC 3 / 76 / 209 / 438 / 1004 / 159）
   │        └─ 不单调（含负数、含"恰好 K"约束）
   │             └─ 是 → 转前缀和 + 哈希（LC 560 / 930 / 1248 / 974 / 523）
   └─ 否 → 继续

Q3 题目出现"区间和 / 区间加 / 区间查询"吗？
   ├─ 静态查询 → 前缀和（LC 303 / 304 / 560 / 363）
   └─ 批量离线修改后统一查询 → 差分（LC 1109 / 370 / 1094）

Q4 需要"前缀和之间的最值关系"吗（和至少为 K / 区间和落在 [L,R]）？
   └─ 是 → 前缀和 + 单调队列 / 树状数组 / 归并（LC 862 / 327 / 209 的负数版）

Q5 都不是？→ 回到哈希表 / 单调栈 / 二分 / DP 四个方向重判
```

### 0.3 三条"不能滑窗"的红线（面试官最爱追问的点）

| 红线 | 为什么失效 | 反例题 | 正确替代 |
|---|---|---|---|
| **数组含负数** | 窗口扩张后 `sum` 可能减小，左指针右移不一定让 `sum` 变小 → 单调性破坏，滑窗会漏解 | LC 209 的负数版（变 862） | 前缀和 + 单调队列 |
| **约束是"恰好"而非"最多/最少"** | "恰好 K 个"不具单调性：扩张可能刚好命中也可能跳过 | LC 560 / 930 / 1248 | 前缀和 + 哈希计数 |
| **需要同时枚举多个起点结构** | 窗口只能维护一个连续区间 | LC 30 串联所有单词 | 多起点（按单词长度分组）+ 定长窗口 |

> **面试话术**（很重要）：被问"这题能不能用滑动窗口"时，不要只说"能/不能"，要说
> 「滑动窗口成立的前提是"窗口状态关于左右端点单调"：右端点右移状态单调增、左端点右移状态单调减（或反过来）。本题 `nums[i]` 可能为负，右移不保证 `sum` 增大，所以左指针不能只增不减，滑窗失效，要改用前缀和 + 哈希。」

## 1. 双指针体系

### 1.1 三种形态与适用场景

#### 形态 A：相向双指针（对撞指针）

两个指针从两端向中间收缩，**每一步都必须能判定"某一侧的候选可以整体丢弃"**。

适用前提（三者至少满足一个）：

1. **有序性**：排序后 `nums[l] + nums[r]` 关于 `l` 单调增、关于 `r` 单调减 → 可二分式收缩。
2. **两端决策可剪枝**：如 LC 11（短板效应）、LC 42（水位由较小一侧决定）。
3. **对称性**：回文判断、双端队列类。

```java
// 通用骨架：相向双指针
int l = 0, r = n - 1;
while (l < r) {                 // 注意是 < 还是 <=：取决于是否允许同一元素用两次
    // 1. 用当前 (l, r) 计算/判断
    // 2. 依据单调性决定移动哪一侧（这是全部难点）
    if (shouldMoveLeft) l++;
    else r--;
}
```

#### 形态 B：同向双指针（快慢指针）

两个指针同方向移动，`[0, slow)` 是不变量所描述的"已处理区"。

典型用途：

| 用途 | 不变量 | 题目 |
|---|---|---|
| 原地删除 / 去重 | `[0, slow)` 是已确定的合法结果 | LC 26 / 27 / 283 / 80 |
| 链表判环 | 快指针每次 2 步，若有环必相遇 | LC 141 / 142 / 287 |
| 找中点 / 倒数第 k 个 | 快慢速度差固定 | LC 876 / 19 |
| 子序列匹配 | 慢指针只在匹配成功时前进 | LC 392 |
| 窗口左右端点 | `[l, r]` 是当前窗口 | 全部滑动窗口题 |

```java
// 同向模板：原地去重（LC 26）
int slow = 0;
for (int fast = 0; fast < n; fast++) {
    if (fast == 0 || nums[fast] != nums[slow - 1]) {
        nums[slow++] = nums[fast];   // [0, slow) 始终是"已确定的合法答案"
    }
}
return slow;
```

> **不变量的写法**是面试加分项：`[0, slow)` 内的元素 = 已处理的、去重后的结果。写代码前先把不变量说出来，面试官会认为你在"设计"而不是"试"。

#### 形态 C：分离双指针（双序列）

两个指针在不同序列（或同一序列的两个不同分区）上各自前进。

| 场景 | 移动规则 | 题目 |
|---|---|---|
| 归并两个有序数组 | 谁小移谁 | 剑指 25 / LC 88 |
| 判断子序列 | 匹配则两指针都动，否则只动长串 | LC 392 |
| 求交集/差集 | 谁小移谁 | LC 349 / 350 |
| 相交链表 | 走完自己换到对方头部 | LC 160 |

```java
// LC 160 相交链表：双指针 + 路程补偿
ListNode p = headA, q = headB;
while (p != q) {
    p = (p == null) ? headB : p.next;
    q = (q == null) ? headA : q.next;
}
return p;
```

**原理**：设 A 独有 `a` 个、B 独有 `b` 个、公共 `c` 个。指针 p 走 `a + c + b`、q 走 `b + c + a`，路程相同 → 必在交点（或 null）相遇。这是"用指针路径长度抵消差值"的经典思想。

### 1.2 双指针的唯一判据：剪枝不漏解

这是本专题最容易被面试官打穿的地方。**任何双指针算法的合法性都可以用同一句话表达**：

> 设候选集合为 C，算法实际评估的集合为 E ⊆ C。算法正确 ⟺ 对每个被丢弃的候选 `x ∈ C \ E`，都存在一个已评估的候选 `y ∈ E`，使得 `value(y) ≥ value(x)`（求最大值时）或 `value(y) ≤ value(x)`（求最小值时）。

三种经典证明（后面 4.3/4.4/4.5 会完整展开）：

| 题目 | 丢弃的候选 | 覆盖它的候选 | 证明工具 |
|---|---|---|---|
| LC 11 | 以 `l` 为左边界、右边界 `< r` 的全部组合 | 当前 `(l, r)` | 短板效应 + 宽度单调 |
| LC 15 | 固定 `i` 后 `(l, r)` 的一整片 | 单步收缩后的 `(l±1, r)` 或 `(l, r∓1)` | 排序后的单调性 |
| LC 42 | 一次移动中被越过的柱子 | 该柱子在"较小一侧最大值"确定时已结算 | 归纳不变量 |

### 1.3 双指针常见的四个坑

1. **`l < r` vs `l <= r`**：LC 15 三数之和必须 `l < r`（三个不同下标）；LC 167 两数之和要求不同下标也是 `l < r`；但 LC 344 反转字符串可 `l < r`（成对交换）；**二分查找**才用 `l <= r`。判据是"是否允许两指针指向同一元素"。
2. **去重跳过的位置**：跳过必须在"找到一组解之后"，且跳过的是"与当前值相同的下一个位置"，不是"跳过整段后还要再判断"。
3. **指针变量复用**：把 `l` 用作循环变量后又在内层修改，导致外层状态错乱。建议内层用 `lo/hi`。
4. **忘记先排序**：LC 15 / 16 / 18 的 `O(n²)` 全部依赖排序，`O(n log n)` 的排序开销必须交代清楚。

## 2. 滑动窗口体系

### 2.1 两类窗口：定长 vs 变长

| | 定长窗口 | 变长窗口 |
|---|---|---|
| 特征 | 窗口长度 `k` 由题目给定 | 长度由"合法性条件"决定 |
| 移动方式 | 每次右移一格，进一个、出一个 | 右指针扩张，`while` 收缩左指针 |
| 状态更新 | 进入 + 退出，各 O(1) | 进入 + 退出，各 O(1)，退出次数均摊 O(n) |
| 典型题 | LC 438 / 567 / 1456 / 30 / 239 | LC 3 / 76 / 209 / 1004 / 159 / 340 |

### 2.2 变长窗口的两个方向（务必区分，这是最容易写错的地方）

**方向一：求"最长"** —— 窗口**不合法时收缩**，合法时记录答案。

```java
// 求最长：while (窗口非法) 收缩左边界
int l = 0, ans = 0;
for (int r = 0; r < n; r++) {
    add(nums[r]);                       // 1. 右端点进入，更新状态
    while (!valid()) {                  // 2. 窗口非法 → 收缩
        remove(nums[l]);
        l++;
    }
    ans = Math.max(ans, r - l + 1);     // 3. 此时窗口必合法，更新答案
}
```

**方向二：求"最短"** —— 窗口**合法时收缩并记录**，非法时扩张。

```java
// 求最短：while (窗口合法) 收缩左边界，并在收缩过程中记录答案
int l = 0, ans = INF;
for (int r = 0; r < n; r++) {
    add(nums[r]);
    while (valid()) {                   // 1. 窗口合法 → 尝试收缩
        ans = Math.min(ans, r - l + 1); // 2. 记录当前合法窗口
        remove(nums[l]);
        l++;
    }
}
```

> **一句话区分**：
> **求最长 → `while` 管"非法"；求最短 → `while` 管"合法"。**
> 记不住的可以用"矛盾"记忆法：最长要的是尽量不收缩，所以只有被迫（非法）才收缩；最短要的是尽量收缩，所以只要合法就立刻收缩。

### 2.3 核心引理：左指针永不回退（正确性 + 复杂度）

这是滑动窗口的"定理"，面试必须能讲清。

**引理（单调性）**：设 `f(l, r)` 为窗口 `[l, r]` 的状态（如"是否存在重复字符"、"是否覆盖 t"、"和是否 ≥ target"），若 `f` 满足：

- 固定 `r`，`f(l, r)` 关于 `l` **单调**（`l` 增大，约束从"不满足"变为"满足"，即窗口变短更容易满足）；
- 固定 `l`，`f(l, r)` 关于 `r` **单调**（`r` 增大，窗口变长更不容易满足）。

那么"对每个 `r`，最优的 `l` 单调不减"，即左指针无需回退。

**证明（反证法）**：假设处理到 `r` 时最优左端点是 `l*`，而 `r+1` 时的最优左端点是 `l' < l*`。则窗口 `[l', r+1]` 合法，由 `f` 关于 `r` 的单调性（`r` 减小窗口更短更容易合法），`[l', r]` 也合法。那么在处理 `r` 时，`l'` 也是合法左端点，且 `l' < l*`，这与 `l*` 是该 `r` 下"最优（最短或最长）"的左端点矛盾（最短时更小的 `l'` 窗口更长，不优；最长时窗口会更长，说明 `l*` 也不是最优）。故 `l` 单调不减。∎

**推论（复杂度）**：`l` 只在 `[0, n)` 内单调移动，总共移动 ≤ n 次；`r` 移动 n 次。因此**总操作次数 O(n)，均摊每次 O(1)**。

> 这个"均摊"是面试官最常追问的技术点：不是"每个 `r` 的 while 循环 O(n) 所以总 O(n²)"，而是"`l` 全程只走 n 步，`while` 的总迭代次数 ≤ n，与 `r` 的循环无关"。这叫**势能分析（potential analysis）**：把 `l` 的位置看作势能，总势能 ≤ n，每次操作势能至多 +1，故总代价 O(n)。

### 2.4 窗口状态怎么维护：四种结构

| 状态类型 | 数据结构 | 更新方式 | 适用 |
|---|---|---|---|
| **计数** | `int[26]` / `int[128]` / `int[128]` + `distinct` | 进入 `cnt[c]++`，退出 `cnt[c]--` | LC 3 / 76 / 438 / 159 / 340 / 1004 |
| **数值和** | `int/long sum` | 进入 `+=`，退出 `-=` | LC 209 / 1658 / 1208 |
| **满足条件的种类数** | `int valid`（配 `need[]`） | 计数跨过 0 时增减 `valid` | LC 76 / 438 / 567 |
| **窗口内最大值** | 单调队列 `Deque` | 进入时弹尾部小的，退出时弹过期头部 | LC 239 / 1438 |

**关键技巧：把"O(Σ) 的判等"变成"O(1) 的计数"**

朴素做法每次都遍历 26/128 个字符比较计数数组 → `O(n·Σ)`，虽然 Σ 是常数但面试官会追问"能不能 O(n)"。正确做法是维护 `valid`（或 `diff`）：

- 加入字符 `c`：`cnt[c]++`；若 `cnt[c]` 从 `0` 变 `非 0`（说明"这一种字符"从满足变不满足，或从未满足变满足，取决于 `cnt` 的语义）→ 调整 `valid`。
- 退出字符 `c`：`cnt[c]--`；若从 `非 0` 变 `0` → 调整 `valid`。

**只有"计数跨越 0"这一刻才需要改动 `valid`**，这是 `O(1)` 更新的本质。

### 2.5 十大易错点（按出错率排序）

1. **`while` 条件写反**（求最长写成了 `while(valid())`）→ 答案永远是 0 或 1。
2. **`ans` 更新位置错**：求最长必须在 `while` **之后**更新；求最短必须在 `while` **内部**更新。
3. **先移指针还是先改状态**：退出窗口时必须"先 `remove` 再 `l++`"，否则状态与窗口错位。
4. **`need[]` 出现负数没处理**：LC 76 中 `need[c]` 可以为负（表示多余），判断"满足"必须用 `== 0` 而不是 `<= 0`。
5. **忘记 `valid` 维护**：直接每次比较数组，复杂度退化。
6. **空串 / `n < m` 边界**：LC 76 若 `s` 比 `t` 短直接返回 `""`；LC 438 若 `n < m` 直接返回空列表。
7. **字符集假设错误**：`int[26]` 只能处理小写；`int[128]` 只能处理 ASCII；若题面是"字符"而非"小写字母"，用 `HashMap` 或用 `char` 位运算（`1 << (c - 'A')` for 52 个字母）。
8. **`sum` 溢出**：`sum` 类窗口在 `n` 大、值大时用 `long`。
9. **窗口长度为 0 的退化**：求最短时若 `remove` 后窗口空，`while` 判断要能正确处理空窗口。
10. **窗口内"恰好 K"的误用**：把 `>= K` 的滑窗思路套到"恰好 K"，忘记减去 `> K` 的部分（LC 1248 优雅解法：`cnt[odd]` 计数相减）。

### 2.6 定长窗口的"滑动"技巧

```java
// LC 438：先填满前 m 个，再整体右滑
// 这种写法比"for r: if (r >= m) 出窗口"更直观，两种都可
for (int i = 0; i < m; i++) add(s.charAt(i));
if (ok()) record(0);
for (int i = m; i < n; i++) {
    add(s.charAt(i));          // 进
    remove(s.charAt(i - m));   // 出
    if (ok()) record(i - m + 1);
}
```

**为什么定长窗口不能直接套变长模板**：变长窗口的 `while` 依赖"合法性单调"，而"长度必须为 m"这个约束对扩张不单调（扩张后长度必然非法），所以只能显式进出。

## 3. 前缀和与差分体系

### 3.1 一维前缀和

**定义**：`P[0] = 0`，`P[i] = a[0] + a[1] + ... + a[i-1]`（长度 `n+1`，这是最不容易出错的写法）。

**区间和**：`sum(l, r) = P[r+1] - P[l]`（左闭右闭 `[l, r]`）。

```java
long[] P = new long[n + 1];
for (int i = 0; i < n; i++) P[i + 1] = P[i] + a[i];
// 查询 [l, r]
long s = P[r + 1] - P[l];
```

**为什么要 `P[0] = 0`**：让 `sum(0, r) = P[r+1] - P[0]` 无需特判；这也是 LC 560 中 `map.put(0, 1)` 的来源——**"空前缀"是一个合法的、出现过 1 次的前缀和**。

**时间复杂度**：预处理 O(n)，单次查询 O(1)。若查询 q 次，总 O(n + q)，优于每次 O(n) 的暴力。

### 3.2 二维前缀和（容斥原理）

**定义**：`P[i][j] = 矩阵 (0,0) 到 (i-1,j-1) 的子矩阵和`。

```java
// 递推：P[i][j] = P[i-1][j] + P[i][j-1] - P[i-1][j-1] + a[i-1][j-1]
for (int i = 1; i <= m; i++)
    for (int j = 1; j <= n; j++)
        P[i][j] = P[i-1][j] + P[i][j-1] - P[i-1][j-1] + a[i-1][j-1];

// 查询子矩阵 (r1,c1) 到 (r2,c2) 的和（含端点）
// S = P[r2+1][c2+1] - P[r1][c2+1] - P[r2+1][c1] + P[r1][c1]
```

**记忆法（容斥）**：
```
大块 = P[r2+1][c2+1]
减去上方一条： - P[r1][c2+1]
减去左方一条： - P[r2+1][c1]
补回被减两次的左上角： + P[r1][c1]
```

一句话：**"大减小、减左、补左上"**。

**为什么用 `+1` 偏移**：与一维同理，避免 `i-1` 的边界判断。面试时若面试官问"为什么不用 `P[i][j]` 表示 `(0,0)` 到 `(i,j)`"，答"因为 `r1 = 0` 时会出现下标 `-1`，需要额外特判，偏移一位能把边界统一"。

### 3.3 差分：区间加的 O(1) 武器

**定义**：`d[0] = a[0]`，`d[i] = a[i] - a[i-1]`。差分是前缀和的**逆运算**：`a` 是 `d` 的前缀和，`d` 是 `a` 的差分。

**核心操作**：对 `[l, r]` 全部加 `v`，只需两步：

```java
d[l] += v;
d[r + 1] -= v;    // 注意 r+1 可能越界，数组开 n+1，或判断 r+1 < n
```

**原理**：`d[l] += v` 使 `l` 之后的所有元素都 `+v`（因为前缀和会累积）；`d[r+1] -= v` 抵消 `r+1` 之后的累积。两次单点修改让"区间加"变成 O(1)。

**还原**：`for (i = 1; i < n; i++) d[i] += d[i-1];` 后 `d` 即为结果数组。

```java
// LC 1109 航班预订统计（模板题）
public int[] corpFlightBookings(int[][] bookings, int n) {
    int[] diff = new int[n + 1];
    for (int[] b : bookings) {
        int l = b[0] - 1, r = b[1] - 1, v = b[2];
        diff[l] += v;
        diff[r + 1] -= v;
    }
    int[] res = new int[n];
    int cur = 0;
    for (int i = 0; i < n; i++) {
        cur += diff[i];
        res[i] = cur;
    }
    return res;
}
```

### 3.4 二维差分

对子矩阵 `(r1,c1)-(r2,c2)` 整体加 `v`：

```java
d[r1][c1]         += v;
d[r1][c2 + 1]     -= v;
d[r2 + 1][c1]     -= v;
d[r2 + 1][c2 + 1] += v;   // 补回被减两次的角
```

还原：二维前缀和（两次方向累积）。

```java
// 还原：先按行累积，再按列累积
for (i) for (j) d[i][j] += d[i][j-1];
for (i) for (j) d[i][j] += d[i-1][j];
```

**对照记忆**：
- 一维：区间加 → 两个点；还原 → 前缀和。
- 二维：矩形加 → **四个角**；还原 → 二维前缀和。
- 二维前缀和查询 → 四个角（容斥）；二维差分修改 → 四个角。**同一组四角公式，一个用于查询，一个用于修改。**

### 3.5 前缀和的五种变体（这一节是"延伸深入"的重点）

#### 变体 1：前缀异或

`X[i] = a[0] ^ ... ^ a[i-1]`，区间异或 `X[r+1] ^ X[l]`。因为异或的逆运算还是异或 `x ^ x = 0`。

常用于：LC 1310（子数组异或查询）、LC 1442、LC 1738（第 K 大异或坐标值，配 Trie）。

#### 变体 2：前缀乘积

`P[i] = a[0]*...*a[i-1]`，区间乘积 `P[r+1] / P[l]`（需用逆元或浮点）。**陷阱：遇到 0 就断链**，需要记录 0 的位置或分段处理。

#### 变体 3：前缀最值（**不能相减**）

`maxPre[i] = max(a[0..i])` 只能回答"`[0, r]` 的最大值"，**不能回答任意 `[l, r]`**——因为最大值不可逆。要回答任意区间最值必须用 **RMQ（ST 表 / 线段树 / 单调栈预处理）**。这是面试常设的"陷阱追问"。

> 但"前缀最大值的**累计**信息"是另一种用法：LC 42 中的 `leftMax[i]` 就是"前缀最大值"，它不用于相减，而用于"每个位置的水位判定"。**关键区别：前缀和用于"求区间的和"，前缀最值用于"给出每个位置的边界"**。

#### 变体 4：前缀和 + 哈希表（把"找配对"降到 O(1)）

这是 LC 560 的本质：

```
sum(l, r) = k
⟺ P[r+1] - P[l] = k
⟺ P[l] = P[r+1] - k
```

于是"枚举 `l`"变成"查表 `P[r+1] - k` 出现过几次"。**因为 `P[l]` 可能重复出现（负数、0），所以哈希表存的是"次数"而不是"下标"。**（若要求"最长区间"则存"最早/最晚下标"，见变体 6。）

#### 变体 5：前缀和 + 单调队列（"和至少为 K 的最短子数组"，LC 862）

当数组含负数时，`P` 不单调，`P[l] = P[r] - k` 无法二分。此时把"候选的 `l` 集合"用**单调队列**维护：

- 队列内 `P` 单调递增（新元素进队前弹出所有 `≥` 它的队尾，因为它们更"差"：下标更晚、值更大，永远不会成为最优 `l`）；
- 每次用队头判断 `P[i] - P[front] >= k`，满足就弹出并更新答案（弹出的 `l` 以后也不会再优，因为 `i` 在增大、区间只会更长）。

```java
// LC 862 和至少为 K 的最短子数组（含负数，滑窗失效的标准解法）
public int shortestSubarray(int[] nums, int k) {
    int n = nums.length;
    long[] P = new long[n + 1];
    for (int i = 0; i < n; i++) P[i + 1] = P[i] + nums[i];
    Deque<Integer> dq = new ArrayDeque<>();   // 下标，P 单调递增
    int ans = Integer.MAX_VALUE;
    for (int i = 0; i <= n; i++) {
        // 1. 用队头结算：满足条件就更新答案并弹出
        while (!dq.isEmpty() && P[i] - P[dq.peekFirst()] >= k) {
            ans = Math.min(ans, i - dq.pollFirst());
        }
        // 2. 维护单调性：比 P[i] 大的队尾全部淘汰
        while (!dq.isEmpty() && P[dq.peekLast()] >= P[i]) dq.pollLast();
        dq.addLast(i);
    }
    return ans == Integer.MAX_VALUE ? -1 : ans;
}
```

**时间复杂度 O(n)**（每个下标进出队各一次）；**空间 O(n)**。这是"前缀和 + 单调性"家族的核心题，也是 209 的"进阶版"。

#### 变体 6：前缀和 + 同余（可整除类）

`(P[r] - P[l]) % K == 0 ⟺ P[r] % K == P[l] % K`。于是"找同余"变成"计数同余类"。

| 题 | 约束 | 关键点 |
|---|---|---|
| LC 974 和可被 K 整除的子数组 | 计数 | `(P % K + K) % K` 处理负数；`map[0]=1` |
| LC 523 连续的子数组和 | 长度 ≥ 2 | 存**最早下标**，`i - first >= 2` |
| LC 1590 使数组和能被 P 整除的最短子数组 | 最短 | 存**最晚下标**，`i - last` 最小 |

**同一个模板，存"次数"→ 计数；存"最早下标"→ 求最长；存"最晚下标"→ 求最短。** 这是把 560 举一反三的关键。

### 3.6 前缀和的五个陷阱

1. **溢出**：`n = 2e5`、`a[i] = 1e9` 时 `int` 必炸，一律 `long`。（LC 560 官方数据用 `int` 勉强能过，但面试要主动说"我会用 long"。）
2. **负数取模**：Java 中 `-7 % 5 == -2`，必须 `(x % K + K) % K`。
3. **空前缀**：`map.put(0, 1)` 不能忘，否则"从下标 0 开始的子数组"全部漏掉。
4. **下标体系混用**：`P` 长 `n+1`，`P[i]` 对应"前 i 个元素"；若用 `P[i]` 表示"前 i+1 个"，所有公式都要重新推。**建议永远用 `P[0]=0`、`P[i]` = 前 i 个。**
5. **把"计数"与"最值"混用**：560 要次数，523 要最早下标，1590 要最晚下标。用错 `Map` 的语义会静默错答案。

### 4.1 LC 3 无重复字符的最长子串

#### 1）题意

给定字符串 `s`，找出其中不含重复字符的**最长子串**的长度。

例：`s = "abcabcbb"` → 3（`"abc"`）；`s = "bbbbb"` → 1；`s = "pwwkew"` → 3（`"wke"`，注意是子串不是子序列）。

#### 2）暴力

枚举左端点 `l`，右端点 `r` 从 `l` 开始扩张，用一个 `Set` 判重，遇到重复就停。复杂度 O(n²)（甚至 O(n³)，取决于判重方式）。瓶颈：`l` 每次右移一格，`r` 都要重新从 `l` 开始。

#### 3）关键洞察

**当 `[l, r]` 出现重复字符 `c` 时，任何包含 `[l, r]` 的更长窗口都必然非法**，因为重复一旦出现就不会自己消失。所以在 `l` 右移时，`r` 不需要回退——这就是滑动窗口的单调性。

进一步利用"重复字符必然成对"这一结构，还能做更强的优化：**左指针直接跳到 `上一次出现 c 的位置 + 1`**，而不是一格一格挪。这是本题的最优写法。

需要证明的一点：**跳过去不会漏掉更长的解**。设 `c` 上次出现在 `p`（`l ≤ p < r`）。任何以 `l' ∈ (l, p]` 为左端点、`r' ≤ r` 的窗口都包含下标 `p` 和 `r` 两个 `c`，必然非法；而任何 `r' > r` 的窗口同样包含这两个 `c`（`p` 和 `r` 都在窗口内），也非法。所以 `l` 可以直接跳到 `p + 1`。∎

#### 4）算法（跳跃版，推荐）

```java
class Solution {
    public int lengthOfLongestSubstring(String s) {
        int n = s.length();
        int[] last = new int[128];          // 每个字符上次出现的下标
        Arrays.fill(last, -1);
        int l = 0, ans = 0;
        for (int r = 0; r < n; r++) {
            char c = s.charAt(r);
            if (last[c] >= l) {             // 上次出现的位置在窗口内 → 冲突
                l = last[c] + 1;            // 左指针直接跳到冲突字符之后
            }
            last[c] = r;
            ans = Math.max(ans, r - l + 1);
        }
        return ans;
    }
}
```

**注意 `last[c] >= l` 不能写成 `last[c] != -1`**：若 `c` 上次出现的位置已经被 `l` 甩在窗口外（`last[c] < l`），说明窗口内没有它，不构成冲突，此时 `l` 不能动。

#### 5）算法（计数数组版，通用模板）

```java
class Solution {
    public int lengthOfLongestSubstring(String s) {
        int[] cnt = new int[128];
        int l = 0, ans = 0;
        for (int r = 0; r < s.length(); r++) {
            char c = s.charAt(r);
            cnt[c]++;
            while (cnt[c] > 1) {            // 窗口非法 → 收缩左边界
                cnt[s.charAt(l)]--;
                l++;
            }
            ans = Math.max(ans, r - l + 1);
        }
        return ans;
    }
}
```

两版对比：

| | 跳跃版 | 计数版 |
|---|---|---|
| 左指针移动 | 一次跳到 `last+1` | 一格一格挪 |
| 复杂度 | O(n)，常数极小 | O(n)（均摊），`while` 总次数 ≤ n |
| 适用性 | 仅适合"重复即失效"的单约束 | 模板通用（可扩展"最多 k 次重复"等） |
| 面试建议 | 先说计数版（体现模板思维），再说跳跃版（体现优化意识） | — |

#### 6）正确性证明（计数版）

**不变量**：外层循环第 `r` 次迭代结束时，`[l, r]` 内无重复字符，且 `ans` 是"以 `0..r` 为右端点的所有合法窗口"的最大长度。

- 收缩终止时 `cnt[c] == 1`，而进入前窗口内无重复、只加了 `c` 一个字符，所以窗口内所有字符计数为 1 → 合法。
- 窗口 `[l, r]` 是在保证"无重复"前提下能取到的最长（因为 `l` 是满足 `[l, r]` 无重复的最小左端点）。
- 更长的合法窗口若存在，其右端点 ≤ r 的某个值，已被之前的迭代覆盖。∎

#### 7）复杂度

- 时间 O(n)：`r` 前进 n 次，`l` 全程至多前进 n 次。
- 空间 O(Σ)：Σ = 字符集大小（128 或 26）。若用 `HashMap` 则是 O(min(n, Σ))。

#### 8）易错点

1. `last[c] >= l` 误写成 `last[c] != -1`。
2. 忘记在 `last[c] = r` 之后再算长度，导致 `r - l + 1` 少算。
3. `ans` 在 `if` 分支里提前更新（跳跃后窗口变短，无意义）。
4. 把"子串"当"子序列"（`"pwwkew"` 的答案是 3 不是 5）。

#### 9）变形与延伸

| 变形 | 变化 | 做法 |
|---|---|---|
| LC 159 至多含 2 个不同字符的最长子串 | 约束从"无重复"变为"不同字符数 ≤ 2" | 计数数组 + `distinct` 变量 |
| LC 340 至多含 K 个不同字符 | 同上，K 可变 | 同上 |
| LC 424 替换后的最长重复字符 | 允许替换 K 个字符 | 窗口内"非最多字符的个数 ≤ K" |
| LC 1004 最大连续 1 的个数 III | 允许翻转 K 个 0 | 窗口内 0 的个数 ≤ K |
| LC 395 至少有 K 个重复字符的最长子串 | 约束不单调（"至少"要求每个字符都达标） | 分治（按不达标字符切分）或枚举"字符种类数"做滑窗 |
| 允许"最多重复 k 次" | 计数上限从 1 变 k | `while (cnt[c] > k)` |

**LC 395 的深入**（这是本题最容易被追问的延伸）：`"至少有 K 个重复字符"` 这个约束**对窗口扩张不单调**——扩张可能让某字符从达标变不达标？不，扩张只会让计数变大，达标的更达标。真正的麻烦是"收缩时可能让某字符从不达标变达标"——即约束在 `l` 方向不单调，滑窗的"左指针只增"引理不成立。

- 正确做法一：**分治**。统计全串中频次 < k 的字符，这些字符不可能出现在答案中，用它们把串切开，递归求各段。
- 正确做法二：**枚举窗口内的字符种类数 `t`（1..26）**，在 `t` 固定的前提下，约束变成"窗口内恰有 t 种字符且每种都 ≥ k"，此时对 `t` 单调，可滑窗。这也叫"枚举维度把非单调约束变单调"，是滑动窗口的高级技巧。

**面试追问**：为什么 LC 3 不需要 `while` 循环回到 `l` 之前？→ 因为冲突一旦产生，任何包含冲突位置的长窗口都非法，这是"单调性"。

### 4.2 LC 76 最小覆盖子串

#### 1）题意

给定字符串 `s` 和 `t`，在 `s` 中找出**涵盖 `t` 中所有字符（含重复次数）的最短子串**，不存在返回 `""`。

例：`s = "ADOBECODEBANC"`, `t = "ABC"` → `"BANC"`。

#### 2）暴力

枚举 `l`、`r`，每次检查 `[l, r]` 是否覆盖 `t`：O(n²) 次检查 × O(Σ) 比较 = O(n²·Σ)。即便用计数增量维护，枚举所有 `O(n²)` 个区间仍是 O(n²)。

#### 3）关键洞察

三点：

1. **求最短 → 用"合法即收缩"的窗口**。窗口一旦覆盖 `t`，就应该尽量往右缩左边界，因为更短的才可能更优。
2. **"覆盖"的判定必须 O(1)**。做法：`need[c]` 表示"还需要几个 `c`"，`valid` 表示"已经完全满足的字符种类数"。**只有 `need[c]` 跨越 0 时才更新 `valid`**。
3. **`need[c]` 可以为负**（表示 `s` 中该字符多余）。这是最容易写错的地方：判断"该类字符是否满足"必须用 `need[c] == 0`，不能用 `need[c] <= 0`（后者在负值时也真，会把"多余"错判成"刚好"）。

#### 4）算法

```java
class Solution {
    public String minWindow(String s, String t) {
        int n = s.length(), m = t.length();
        if (n < m) return "";

        int[] need = new int[128];
        for (char c : t.toCharArray()) need[c]++;

        int required = 0;                       // t 中有多少种不同字符
        for (int i = 0; i < 128; i++) if (need[i] > 0) required++;

        int l = 0, valid = 0;                   // valid = 已"恰好满足"的种类数
        int bestL = 0, bestLen = Integer.MAX_VALUE;

        for (int r = 0; r < n; r++) {
            char c = s.charAt(r);
            need[c]--;                          // 需求 -1（可为负）
            if (need[c] == 0) valid++;           // 该类字符刚刚被满足

            while (valid == required) {          // 窗口已覆盖 t → 尝试收缩
                if (r - l + 1 < bestLen) {
                    bestLen = r - l + 1;
                    bestL = l;
                }
                char d = s.charAt(l);
                if (need[d] == 0) valid--;       // 即将移出的字符是"恰好满足"的 → 将不再满足
                need[d]++;
                l++;
            }
        }
        return bestLen == Integer.MAX_VALUE ? "" : s.substring(bestL, bestL + bestLen);
    }
}
```

**四个"顺序敏感"的位置**（面试可以主动指出来，非常加分）：

1. `need[c]--` 必须在 `if (need[c] == 0) valid++` **之前**。
2. 记录答案必须在 `while` **内部**、且在收缩**之前**。
3. 判断 `need[d] == 0` 必须在 `need[d]++` **之前**。
4. `l++` 必须在状态更新**之后**。

#### 5）正确性证明

**引理 1（合法性判定正确）**：`valid == required` ⟺ 窗口覆盖 `t`。
- 因 `valid` 只在 `need[c]` 跨越 0 时变化，故 `valid` 恒等于"`need[c] == 0` 的种类数"。而 `need[c] == 0` 表示该类字符"恰好用掉全部需求（含多余时 `need[c] < 0` 不算）"。若所有 `required` 种都 `== 0`，则恰好覆盖；若某类 `< 0`，它不计入 `valid`，但覆盖依然成立（多余不影响覆盖）。反之若 `valid < required`，则存在某类 `need[c] > 0`，即缺字符 → 未覆盖。∎

**引理 2（不漏解）**：对每个右端点 `r`，`while` 收缩结束时 `l` 是"使 `[l, r]` 覆盖 `t` 的最小左端点"。因此该 `r` 下的最短覆盖窗口被记录。由滑动窗口单调性，其他更优解必在某次 `r` 迭代中被覆盖。∎

**引理 3（复杂度 O(n)）**：`l` 单调增 ≤ n 次，`r` 前进 n 次。

#### 6）复杂度

- 时间 O(n + m)：建 `need` 为 O(m + Σ)，扫描 O(n)，`l` 总移动 O(n)。
- 空间 O(Σ) = O(128) = O(1)。

#### 7）易错点

1. `valid` 判断写成 `need[c] <= 0`。
2. `bestLen` 初始化为 0 而非 `MAX_VALUE`。
3. `while (valid == required)` 写成 `>=`（永远不会 >，但语义混淆）。
4. 忘记 `n < m` 特判（虽然循环会自然返回 `""`，但早期返回更清晰）。
5. 用 `Map<Character,Integer>` 并 `remove` key，导致"多余字符"信息丢失。

#### 8）变形与延伸

| 变形 | 差异 | 关键 |
|---|---|---|
| LC 567 字符串的排列 | 固定长度、判断"排列" | 定长窗口 + 计数 |
| LC 438 字母异位词 | 同上，求所有起点 | 定长窗口 + `diff` |
| LC 30 串联所有单词的子串 | `t` 变成单词列表、长度固定、多起点 | 按 `wordLen` 分组起点，窗口内是"单词级"计数 |
| LC 727（会员题）最小窗口子序列 | `t` 是子序列而非覆盖 | 贪心匹配 + 双指针 |
| "至少覆盖 t 中 k 种字符" | 约束放松 | 把 `required` 改成 k |
| 返回**最长**覆盖子串 | 目标反转 | 求最长模板：`while (!valid)` 收缩 |

**LC 30 的深入**（难度明显更高，值得单独理解）：
`s` 要按"单词长度 `L`"切分成 `n/L` 个块，但起点可以是 `0..L-1` 中任意一个，所以要跑 `L` 轮外层循环，每轮窗口按"一个单词"为单位滑动。窗口内维护 `Map<String,Integer>` 与 `t` 的差异计数 `diff`。总复杂度 O(L · n/L · 单词比较) = O(n · L)（`L` 为单词长度）。

**面试追问**：如果 `t` 里字符数远少于 `s`，能不能只考虑 `s` 中出现过的字符？→ 可以，用 `HashMap` 或对 `need` 数组做"有效种类"裁剪，空间从 O(Σ) 降到 O(|t| 的不同字符数)。这体现"按数据规模选结构"的意识。

### 4.3 LC 15 三数之和

#### 1）题意

给定数组 `nums`，找出所有和为 0 的**不重复三元组** `(a, b, c)`，`a + b + c = 0`，且三元组不能重复。

例：`[-1,0,1,2,-1,-4]` → `[[-1,-1,2], [-1,0,1]]`。

#### 2）暴力

三重循环 O(n³)，加哈希去重。`n = 3000` 时 2.7e10 次，必超时。

#### 3）关键洞察

**排序是本题的"降维器"**：排序后（O(n log n)），固定第一个数 `i`，问题退化为"在 `[i+1, n-1]` 中找两数之和 = `-nums[i]`"，而**有序数组的两数之和可以用相向双指针 O(n) 解**。总复杂度 O(n²)。

三个必须交代的剪枝：

1. **`nums[i] > 0` 直接 break**：排序后最小的数都 > 0，后面不可能凑出 0。
2. **`i` 去重**：`if (i > 0 && nums[i] == nums[i-1]) continue`（跳过"与前一个相同"的 `i`）。
3. **找到解后 `l`/`r` 各自跳过相同值**：否则会产生重复三元组。

#### 4）算法

```java
class Solution {
    public List<List<Integer>> threeSum(int[] nums) {
        Arrays.sort(nums);
        int n = nums.length;
        List<List<Integer>> res = new ArrayList<>();

        for (int i = 0; i < n - 2; i++) {
            if (nums[i] > 0) break;                              // 剪枝 1
            if (i > 0 && nums[i] == nums[i - 1]) continue;       // 剪枝 2

            int l = i + 1, r = n - 1;
            int target = -nums[i];
            while (l < r) {
                int sum = nums[l] + nums[r];
                if (sum < target) {
                    l++;
                } else if (sum > target) {
                    r--;
                } else {
                    res.add(Arrays.asList(nums[i], nums[l], nums[r]));
                    // 剪枝 3：跳过重复的 l / r，避免重复三元组
                    int lv = nums[l], rv = nums[r];
                    while (l < r && nums[l] == lv) l++;
                    while (l < r && nums[r] == rv) r--;
                }
            }
        }
        return res;
    }
}
```

#### 5）正确性证明

**引理（双指针完备性）**：在有序数组 `A[l..r]` 中，若 `A[l] + A[r] < target`，则对所有 `r' ≤ r` 都有 `A[l] + A[r'] ≤ A[l] + A[r] < target`，故以 `l` 为左端点的候选全部无效 → 可丢弃 `l`，即 `l++`。对称地，`A[l] + A[r] > target` 时丢弃 `r`。

**完备性**：每次丢弃的是一片"必然无解"的候选（上面引理），保留的候选在收缩方向上是"尚未排除"的，且两个指针相向而行必然遍历所有"尚未被排除"的配对。∎

**去重的正确性**：外层跳过相同 `i`，保证"第一个数"只枚举一次；内层跳过相同 `l` / `r`，保证在同一个 `i` 下"第二、三个数"的组合只出现一次。三处合起来 → 任意三元组唯一。∎

#### 6）复杂度

- 时间 O(n²)：外层 O(n)，内层双指针 O(n)，排序 O(n log n) 被 O(n²) 主导。
- 空间 O(1)（不计结果），排序用 O(log n) 栈空间。

#### 7）易错点

1. `while (l < r)` 写成 `l <= r` → 同一元素被用两次。
2. 去重跳过的位置错了：必须在**加入结果后**跳过，否则会漏解。
3. 只对 `i` 去重，忘了对 `l`/`r` 去重 → 重复三元组。
4. `nums[i] > 0 break` 写成 `nums[i] >= 0 break`（`0,0,0` 会漏）。
5. 用 `Set<List<Integer>>` 去重 → 虽然能过，但复杂度与常数都差，面试会被扣分。

#### 8）变形与延伸

| 变形 | 差异 | 关键点 |
|---|---|---|
| LC 1 两数之和 | 无序、求一组、返回下标 | 哈希 O(n)，**不能**用双指针（下标不能排序） |
| LC 167 两数之和 II（有序） | 有序、返回下标 | 相向双指针 O(n)，空间 O(1) |
| LC 16 最接近的三数之和 | 求最接近 target | 双指针 + 维护最小差 |
| LC 18 四数之和 | 四个数 | 双层枚举 + 双指针，O(n³)；注意 `long` 防溢出 |
| LC 259 三数之和小于 target（会员） | 计数 | `A[l]+A[r] < target` 时，`r-l` 个解一次累加，再 `l++` |
| LC 611 有效三角形个数 | 计数 | 排序后固定最大边，双指针判 `a+b > c` 并**批量计数** |
| LC 923 三数之和的多种可能 | 计数（含重复视为不同） | 双指针 + 乘法计数 |

**LC 611 / LC 259 的"批量计数"技巧（高频追问）**：
求"满足 `A[l] + A[r] < target` 的配对数"时，双指针找到 `l` 后，若 `A[l] + A[r] < target`，则 `r' ∈ (l, r]` 全部满足，一次加 `r - l`，再 `l++`。这把"逐个枚举"变成"整段累加"，是"计数型双指针"的标准写法，比"找到解再挪一格"快一个量级（虽然同阶复杂度，但常数差很多）。

**面试追问**：
- "为什么不能先去重（`Set`）再排序双指针？" → 可以去重，能缩减规模，但最坏情况（全不重复）无收益，且"含重复元素的三元组"（如 `[-1,-1,2]`）需要保留重复值，去重会漏解。所以**必须保留重复元素**。
- "如果要求三元组的下标不能重复但值可以，怎么做？" → 记录下标而非值，去重逻辑改为"按值跳"但要保证下标不同，实现更复杂，通常改用"排序 + 枚举 + 哈希"。

### 4.4 LC 11 盛最多水的容器

#### 1）题意

给定 `height[0..n-1]`，选两条线 `i < j`，容量 = `min(height[i], height[j]) * (j - i)`，求最大容量。

例：`[1,8,6,2,5,4,8,3,7]` → 49。

#### 2）暴力

枚举所有 `(i, j)`，O(n²)。`n = 1e5` 时 5e9 次，超时。

#### 3）关键洞察（本题的灵魂，也是"双指针证明"的教科书）

把容器看成"两堵墙 + 底部宽度"，容量由**较矮的那堵墙**决定（短板效应）。

假设当前 `(l, r)`，且 `height[l] < height[r]`。此时**所有以 `l` 为左边界、右边界 `r' < r` 的候选，全部不可能超过当前容量**：

- 新容量 `= min(height[l], height[r']) * (r' - l)`
- 宽度 `r' - l < r - l`（更窄）
- 高度 `min(height[l], height[r']) ≤ height[l]`（因为 `height[l] < height[r]`，且 `min` 的取值不可能超过 `height[l]`）

所以新容量 `≤ height[l] * (r - l) = 当前容量`。**以 `l` 为边界的所有候选都被当前 `(l, r)` 支配（dominated）** → 可以安全地丢弃 `l`，`l++`。

对称地，`height[l] >= height[r]` 时可以丢弃 `r`。

**这就是"剪枝不漏解"的完整证明**：被丢弃的候选集合，被当前已评估的候选"支配"（不优于它）。

> **对照思考（面试官爱问）**：如果移动**较高**的一侧会怎样？
> 以 `l` 为例，若 `height[l] >= height[r]` 却移动 `l`，则被丢弃的候选 `(l, r')` 中，`r'` 可能远小于 `r` 但 `height[r']` 很高（比如 `r'` 是峰值），此时 `min(height[l], height[r']) * (r'-l)` 可能**大于**当前容量 → 丢弃它会漏解。所以**必须移动矮的一侧**，这不是启发式，而是被支配关系决定的。

#### 4）算法

```java
class Solution {
    public int maxArea(int[] height) {
        int l = 0, r = height.length - 1, ans = 0;
        while (l < r) {
            int h = Math.min(height[l], height[r]);
            ans = Math.max(ans, h * (r - l));
            if (height[l] < height[r]) l++;
            else r--;
        }
        return ans;
    }
}
```

#### 5）正确性证明（形式化）

**不变量**：任意时刻，`ans` ≥ 所有"已被丢弃的候选"的容量（因为每个丢弃动作都由支配关系保证）。

**归纳**：
- 初始 `ans = 0`，无丢弃。
- 若 `height[l] < height[r]`，丢弃集合 `D = {(l, r') : r' < r}`。对任意 `(l, r') ∈ D`，`cap(l, r') ≤ height[l] * (r-l) = cap(l, r) ≤ ans`（最后一步由 `ans` 已包含 `(l, r)`）。故不变量保持。
- 对称处理另一支。
- 终止时 `l == r`，所有候选或被评估、或被丢弃且不优于 `ans` → `ans` 为最优。∎

#### 6）复杂度

- 时间 O(n)：每次迭代必有一个指针移动，共 `n-1` 次迭代。
- 空间 O(1)。

#### 7）易错点

1. 移动高的一侧（最典型错误）。
2. `h * (r - l)` 溢出（`h ≤ 1e4`，`n ≤ 1e5`，`1e9` 刚好在 `int` 边界内，保险起见用 `long`）。
3. 循环条件 `l < r` 写成 `l <= r`（宽为 0，无意义但不影响结果）。
4. `ans` 更新放在移动之后（会漏掉某次组合）。

#### 8）变形与延伸

| 变形 | 差异 | 关键 |
|---|---|---|
| LC 42 接雨水 | 求"每个柱子上的水量之和"而非"一个容器" | 见 4.5，完全不同的问题 |
| LC 84 柱状图中最大的矩形 | 求"最大矩形面积"（高度由最矮柱决定） | **单调栈**，不是双指针 |
| 容量定义为 `min(h) * (j-i)^2` | 非线性宽度 | 双指针失效（支配关系破坏），需凸包/三分 |
| 允许选 3 条线（两个容器） | 多容器 | DP / 双指针分段 |

> **LC 11 vs LC 84 vs LC 42 三者区别**（极高频的"概念辨析"追问）：
> - **LC 11**：两根柱子围成一个容器，容量由**两端较矮者**决定 → 相向双指针。
> - **LC 84**：连续柱子围成一个矩形，高度由**区间内最矮者**决定 → 单调栈（找每个柱子的左右第一个更矮）。
> - **LC 42**：每根柱子上方能存多少水，由**左右两侧最大值中的较小者**决定 → 双指针 / 单调栈 / DP。
> 一句话：**11 是"两端"，84 是"区间最矮"，42 是"左右两侧最大值"。**

#### 9）面试追问

- "为什么时间复杂度是 O(n) 而不是 O(n²)？" → 每次迭代至少移动一个指针，指针总移动 ≤ n。
- "能不能用二分？" → 不能，容量关于 `(i, j)` 不是单峰的。
- "如果 `height` 有负数？" → 容器高度取 `min` 会出现负容量，需要 `max(0, ...)`，但支配关系仍成立。

### 4.5 LC 42 接雨水

#### 1）题意

给定 `n` 个非负整数表示柱子高度，每根柱子宽度为 1，求这些柱子总共能接多少雨水。

例：`[0,1,0,2,1,0,1,3,2,1,2,1]` → 6。

#### 2）暴力

对每个位置 `i`，向左扫到最大值 `L[i]`、向右扫到最大值 `R[i]`，水量 `= min(L[i], R[i]) - h[i]`。O(n²)。

#### 3）关键洞察（三层递进）

**第一层（定义）**：位置 `i` 的水位 = `min(左侧最高, 右侧最高)`，因为水会从较低的一侧溢出。这是所有解法的共同基础。

```
        水位线 = min(L[i], R[i])
        ┌──────────────┐
        │   ↑ 水量      │
   h[i] ┤   ↓          │
        └──────────────┘
```

**第二层（三种实现）**：

| 解法 | 空间 | 思想 |
|---|---|---|
| DP 预处理左右最大值 | O(n) | 先算出 `L[]`、`R[]`，再统一累加 |
| 单调栈 | O(n) | 按"横向分层"累加，找每个凹槽的左边界 |
| 双指针 | **O(1)** | 边扫边维护 `leftMax`、`rightMax`，一次遍历 |

**第三层（双指针的正确性，本题最难的一步）**：

当 `h[l] < h[r]` 时，可以断言：**位置 `l` 的水位由 `leftMax` 唯一决定，与右侧的具体形状无关**。

直觉：右侧至少存在一根不低于 `h[l]` 的柱子（`h[r]` 本身），所以右侧最大值必然 ≥ `h[l]`，右侧不会成为"限制水位"的那一侧。

严格证明（归纳不变量）：

> **不变量**：任意时刻，`L_l = max(h[0..l]) ≤ R_l = max(h[l..n-1])`（当算法推进左指针时）；对称地，推进右指针时 `R_r ≤ L_r`。

- **推进左指针时**（条件 `h[l] < h[r]`）：要证 `L_{l+1} ≤ R_{l+1}`。
  由归纳假设 `L_l ≤ R_l = max(h[l], R_{l+1})`。若 `L_l > R_{l+1}`，则必有 `L_l = h[l]`（唯一可能），即 `h[l] > R_{l+1} ≥ h[r] > h[l]`，矛盾。故 `L_l ≤ R_{l+1}`；又 `h[l] < h[r] ≤ R_{l+1}`，所以 `L_{l+1} = max(L_l, h[l]) ≤ R_{l+1}`。
- 于是 `water(l) = min(L_l, R_l) - h[l] = L_l - h[l]`（因 `L_l ≤ R_l`），只与左侧有关，可以立刻结算并丢弃 `l`。
- **推进右指针时**对称。∎

> **为什么不能反过来（`h[l] < h[r]` 时推进 `r`）？**
> 若推进 `r`，被越过的位置 `r` 的水位是 `min(L_r, R_r) - h[r]`。此时 `h[r] > h[l]`，无法保证 `R_r ≤ L_r`——右侧可能有比左侧更高的墙，那么 `r` 的水位就由右侧 `R_r` 决定，而不是左侧。此时用 `leftMax` 结算会**低估**。所以必须先处理"被限制的那一侧"。

#### 4）算法（双指针，最优）

```java
class Solution {
    public int trap(int[] h) {
        int l = 0, r = h.length - 1;
        int leftMax = 0, rightMax = 0, ans = 0;
        while (l < r) {
            if (h[l] < h[r]) {
                leftMax = Math.max(leftMax, h[l]);
                ans += leftMax - h[l];       // 该位置水量由 leftMax 唯一决定
                l++;
            } else {
                rightMax = Math.max(rightMax, h[r]);
                ans += rightMax - h[r];
                r--;
            }
        }
        return ans;
    }
}
```

注意：这里的 `leftMax` 是"`[0..l]` 的最大值"，且 `ans += leftMax - h[l]` 在 `l` 位置上永不为负（因为 `leftMax ≥ h[l]`）。

#### 5）算法（DP 预处理，最易懂）

```java
class Solution {
    public int trap(int[] h) {
        int n = h.length;
        if (n == 0) return 0;
        int[] L = new int[n], R = new int[n];
        L[0] = h[0];
        for (int i = 1; i < n; i++) L[i] = Math.max(L[i - 1], h[i]);
        R[n - 1] = h[n - 1];
        for (int i = n - 2; i >= 0; i--) R[i] = Math.max(R[i + 1], h[i]);
        int ans = 0;
        for (int i = 0; i < n; i++) ans += Math.min(L[i], R[i]) - h[i];
        return ans;
    }
}
```

#### 6）算法（单调栈，横向分层）

```java
class Solution {
    public int trap(int[] h) {
        Deque<Integer> st = new ArrayDeque<>();   // 单调递减栈，存下标
        int ans = 0;
        for (int i = 0; i < h.length; i++) {
            while (!st.isEmpty() && h[st.peek()] < h[i]) {
                int bottom = st.pop();            // 凹槽底部
                if (st.isEmpty()) break;
                int left = st.peek();             // 凹槽左边界
                int width = i - left - 1;
                int height = Math.min(h[left], h[i]) - h[bottom];
                ans += width * height;            // 这一"层"的水量
            }
            st.push(i);
        }
        return ans;
    }
}
```

**理解方式**：栈里存的是"还没找到右边界的高柱子"。当遇到更高的 `h[i]` 时，栈顶成为"凹槽底部"，栈顶之下的元素成为"左边界"，`h[i]` 是右边界，这一层的水量是 `(右边界 - 左边界 - 1) × (min(左边高, 右边高) - 底部高)`。**这是"按层横着算"，双指针是"按列竖着算"**。

#### 7）复杂度

| 解法 | 时间 | 空间 |
|---|---|---|
| 暴力 | O(n²) | O(1) |
| DP | O(n) | O(n) |
| 单调栈 | O(n) | O(n) |
| 双指针 | O(n) | **O(1)** |

#### 8）易错点

1. 双指针 `if` 分支写成 `h[l] > h[r]`（方向搞反）。
2. `leftMax`/`rightMax` 初始化为 `h[0]`/`h[n-1]` 但没在循环外先赋值，导致首个元素漏算或负数。
3. 单调栈忘记 `if (st.isEmpty()) break`（左右没有更高的柱子，形不成凹槽）。
4. 单调栈中 `width` 算成 `i - left`（多了 1）。
5. 把 LC 11 的"移动矮的一侧"直接套用到 42 而**没有理解为什么**——两题虽然都移动矮的一侧，但原因不同（11 是"支配"，42 是"水位由已结算一侧唯一决定"）。

#### 9）变形与延伸

| 变形 | 差异 | 做法 |
|---|---|---|
| LC 407 接雨水 II（二维） | 三维柱体 | **优先队列 + BFS**：从边界入队（最外圈是边界），每次弹出最矮的格子向内扩展，水位 = `max(当前水位, 邻格高)` |
| LC 84 柱状图最大矩形 | 求最大矩形 | 单调栈（与 42 的栈思路同源） |
| LC 11 盛水容器 | 一个容器 | 相向双指针（见 4.4） |
| LC 755（会员）最终波浪高度 | 类似但需模拟 | 双指针 + 填充 |

**LC 407 的核心思想（高频延伸）**：木桶效应 → 水位由"边界上最矮的点"决定。用最小堆维护"当前边界上的高度"，每次取最小的向内扩展，新的水位 = `max(堆顶高度, 邻格高度)`。这是 Dijkstra/最短路思想在网格上的变体，也是"从边界向内的多源 BFS"的经典应用。

#### 10）面试追问

- "双指针为什么能 O(1) 空间？" → 因为每次只需知道"已结算那一侧的最大值"，不需要另一侧的完整信息。
- "如果要求输出每一列的蓄水量数组？" → 双指针可以直接输出（每次移动时记录 `leftMax - h[l]`）；单调栈需要额外累加到数组。
- "42 和 11 的共同点与区别？" → 共同：都维护两侧最大值/决策；区别：11 求"一个容器的最大容量"，一次决策丢弃一片候选；42 求"逐列累加"，每列独立结算。

### 4.6 LC 560 和为 K 的子数组

#### 1）题意

给定整数数组 `nums`（**可含负数**）和整数 `k`，求**和恰好为 `k` 的连续子数组的个数**。

例：`nums = [1,1,1], k = 2` → 2；`nums = [1,-1,0], k = 0` → 3。

#### 2）暴力

枚举 `l, r` 并求和：O(n²)（带前缀和）或 O(n³)（每次重新求）。`n = 2e4`，O(n²) 勉强能过，但面试要求 O(n)。

#### 3）关键洞察（三个"为什么"）

**为什么不能用滑动窗口？**
`nums` 含负数 → `sum` 关于 `r` 不单调。窗口右移时 `sum` 可能变小；左移时 `sum` 可能变大。左指针"只增不减"的引理失效，会漏解。**这是本题最重要的考点**。

**为什么用前缀和？**
`sum(l..r) = k ⟺ P[r+1] - P[l] = k ⟺ P[l] = P[r+1] - k`。
把"枚举 `l`"换成"查表：`P[r+1] - k` 这个值在之前出现过几次"。

**为什么哈希表存"次数"而不是"下标"？**
因为 `P` 中同一个值可能多次出现（负数、0 会造成"回头"），每个出现都对应一个不同的起点 → 贡献不同个数的区间。若存下标，只能回答"是否存在"或"最长/最短"，无法计数。

#### 4）算法

```java
class Solution {
    public int subarraySum(int[] nums, int k) {
        Map<Long, Integer> cnt = new HashMap<>();
        cnt.put(0L, 1);                    // 空前缀，对应"从下标 0 开始"的子数组
        long pre = 0;
        int ans = 0;
        for (int x : nums) {
            pre += x;
            ans += cnt.getOrDefault(pre - k, 0);
            cnt.merge(pre, 1, Integer::sum);
        }
        return ans;
    }
}
```

**三个顺序铁律**：

1. `cnt.put(0, 1)` 必须在循环**前**。
2. 必须先 `ans +=` 再把当前 `pre` 放进表。**若顺序反了，会把 `[l..r]` 中 `l == r+1` 的空区间算进去**（即把"自己减自己"当成合法解）。
3. `pre` 用 `long`（`n = 2e4` 时 `int` 可能溢出，虽然本题数据不会，但要主动说）。

#### 5）正确性证明

**完备性**：对每个右端点 `r`，所有以 `r` 结尾的合法子数组的起点 `l` 满足 `P[l] = P[r+1] - k`。哈希表中恰好记录了"所有 `l ≤ r` 的 `P[l]` 出现次数"（因为按顺序插入），所以 `ans` 累加的是所有合法起点数。∎

**无重复**：每个子数组由其 `(l, r)` 唯一确定，且 `l` 只在 `r` 的那一轮被计入一次。∎

#### 6）复杂度

- 时间 O(n)（哈希均摊 O(1)）。
- 空间 O(n)（最坏前缀和全不同）。

#### 7）易错点

1. `map.put(0, 1)` 忘记 → 漏掉"从头开始"的子数组。
2. 先 `put` 后 `get` → 把空区间算入。
3. 用 `int` 存 `pre` → 溢出（`n` 大、值大时）。
4. 试图用滑动窗口（含负数时会 WA，这是最典型的错误）。
5. `k` 为负、`nums` 全负时不特判也没关系（哈希对称），但若用滑窗就必错。

#### 8）变形与延伸（**这一族题必须能一眼识别**）

| 题目 | 变换 | 做法（本质同 560） |
|---|---|---|
| LC 930 和相同的二元子数组 | 01 数组，求和为 `goal` | 前缀和 + 计数 |
| LC 1248 统计优美子数组 | 求"恰好 `k` 个奇数"的子数组 | 前缀"奇数个数" + 计数（把 `odd[]` 当 `P[]`） |
| LC 974 和可被 K 整除 | 同余 | `cnt[(pre % K + K) % K]` |
| LC 523 连续子数组和 | 长度 ≥ 2 | 存**最早下标**，判断 `i - first >= 2` |
| LC 1590 使和能被 P 整除的最短子数组 | 最短 | 存**最晚下标** |
| LC 525 连续数组 | 0/1 等量 → 把 0 记 -1，求和为 0 | 前缀和 + 最早下标（求最长） |
| LC 1371 每个元音包含偶数次的最长子串 | 5 个元音奇偶性 → 状态压缩成 32 种 | 前缀"奇偶掩码" + 最早下标 |
| LC 1658 将 x 减到 0 的最小操作数 | 两端删除 → 反向求"和为 `sum-x` 的最长中间段" | 前缀和 / 滑窗（因元素为正） |

**LC 1248 的"前缀和"抽象（很好的思维训练）**：把"子数组里奇数的个数"看作一种"前缀和"——`odd[i]` = 前 `i` 个数中奇数的个数。要求 `odd[r] - odd[l] == k` → `odd[l] == odd[r] - k` → 完全同构于 560。**"前缀和"不一定是数值求和，任何"可减的累计量"（奇偶计数、异或、掩码）都构成前缀和。**

**LC 1371 的状态压缩（进阶）**：要求每个元音出现偶数次 → 用 5 位掩码记录"每个元音当前是奇数次还是偶数次"，区间合法 ⟺ 两端掩码相同。于是问题变成"找相同掩码的最远下标差"，用 `HashMap<掩码, 最早下标>`。这是"前缀 + 哈希 + 状态压缩"三者合体，面试中属于高分项。

#### 9）面试追问

- "如果数组全为正数，能用滑窗吗？" → 可以，而且更快（O(1) 空间）。**此时才可以用 209 的模板**。
- "如果要返回所有子数组而不只是计数？" → 哈希表存"下标列表"，输出时遍历列表，最坏 O(n²)（因为答案本身可能 O(n²)）。
- "如果 `k = 0` 且数组有 0？" → 模板天然正确（`pre - 0 = pre` 会把自己之前的相同前缀都算上），但注意「必须先查后插」这条铁律，否则会把空区间算入。

### 4.7 LC 209 长度最小的子数组

#### 1）题意

给定**正整数**数组 `nums` 和 `target`，求"和 ≥ target 的最短连续子数组"的长度，不存在返回 0。

例：`target = 7, nums = [2,3,1,2,4,3]` → 2（`[4,3]`）。

#### 2）暴力

枚举所有区间求和：O(n²)（前缀和）或 O(n³)。

#### 3）关键洞察

**"正整数"是本题的命门**：所有元素 > 0 → `sum` 关于 `r` 单调不减，关于 `l` 单调不增。于是：

- 窗口 `sum` 不够 → 只能扩张 `r`（扩张一定让 `sum` 变大）。
- 窗口 `sum` 够了 → 立刻收缩 `l`（收缩一定让窗口变短，且可能仍满足）。

这正是"求最短"模板：**合法就缩，缩的时候记答案**。

**为什么求最短要"合法即缩"**：因为固定 `r` 时，使 `[l, r]` 满足 `sum ≥ target` 的最大 `l` 对应最短窗口；一旦 `sum < target` 就不能再缩了，此时 `l` 再往右也不会有更短解（更短的窗口和更小）。所以每个 `r` 只需找到"最后一个合法 `l`"。

#### 4）算法

```java
class Solution {
    public int minSubArrayLen(int target, int[] nums) {
        int l = 0, sum = 0, ans = Integer.MAX_VALUE;
        for (int r = 0; r < nums.length; r++) {
            sum += nums[r];
            while (sum >= target) {                  // 合法 → 收缩并记录
                ans = Math.min(ans, r - l + 1);
                sum -= nums[l];
                l++;
            }
        }
        return ans == Integer.MAX_VALUE ? 0 : ans;
    }
}
```

另一写法（二分 + 前缀和，O(n log n)）：因为前缀和单调递增，可对每个 `r` 二分找"最大的 `l` 使 `P[r+1] - P[l] ≥ target`"。**面试中提一句"若要求 O(n log n) 也可以用前缀和二分"能体现思路宽度。**

#### 5）正确性证明

**不变量**：处理完 `r` 后，`l` 是"使 `[l, r]` 满足 `sum ≥ target` 的最大左端点"，且 `ans` 已包含所有以 `0..r` 结尾的最短合法窗口。

- 收缩终止时 `sum < target`，再往右只会更小，故 `l` 已是最大合法左端点。
- 以 `r` 结尾的最短合法窗口恰为 `[l, r]`（`l` 最大 → 窗口最短），已被记录。
- 其他以 `r' < r` 结尾的窗口在之前的迭代中已处理。∎

#### 6）复杂度

- 时间 O(n)：`r` 前进 n 次，`l` 前进 ≤ n 次。
- 空间 O(1)。

#### 7）易错点

1. `ans` 更新放在 `while` 外面 → 永远是 1 或错值。
2. 忘记 `sum -= nums[l]` → 死循环或错答案。
3. 认为"含负数也能滑窗" → 必错（这是最高频的追问）。
4. 返回 0 的条件写错（`ans` 未更新时应返回 0）。
5. 用 `ans = 0` 初始化 → `Math.min` 永远得 0。

#### 8）变形与延伸

| 变形 | 差异 | 做法 |
|---|---|---|
| LC 862 和至少为 K 的最短子数组 | **含负数** | 前缀和 + 单调队列（见 3.5 变体 5） |
| LC 713 乘积小于 K 的子数组 | 乘积约束、求**个数** | 滑窗：每次 `r` 贡献 `r - l + 1` 个 |
| LC 2302 统计得分小于 K 的子数组 | 得分 = 长度 × 和 | 滑窗（正数保证单调） |
| LC 1004 最大连续 1 的个数 III | 求最长、约束为"0 的个数 ≤ K" | 求最长模板 |
| LC 1658 将 x 减到 0 的最小操作数 | 两端删除 | 反向求"和为 `sum-x` 的最长中间段" |
| LC 1208 尽可能使字符串相等 | 代价约束 | 滑窗或前缀和 + 二分 |

**LC 713 的"计数型滑窗"技巧（高频）**：求"满足条件的子数组**个数**"时，固定 `r`，若 `[l, r]` 满足且以 `l` 为左端点的所有 `[l', r]`（`l' ≥ l`）都满足（单调性），则一次贡献 `r - l + 1`。这是"滑窗计数"的标准套路，与 611 的"批量计数"思想一致。

**"正数"这个前提有多重要？（务必能讲）**
设 `nums = [1, -1, 5], target = 5`。滑窗会得到 `[5]`（长度 1），看似正确；但 `nums = [5, -10, 5], target = 5` 时，滑窗从 `l=0` 开始，`sum = 5` 满足，收缩后 `l=1`，`sum = -10`，`r=2` 时 `sum = -5`，永不再满足 → 漏掉 `[5]`（下标 2）这个解。**根因：`sum` 不再单调，"收缩后可能重新变大"这一情形被滑窗的"左指针只增"假设排除了。**

#### 9）面试追问

- "为什么滑动窗口的复杂度是 O(n) 而不是 O(n²)？" → 势能分析：`l` 单调，总移动 ≤ n。
- "如果要求返回该子数组本身？" → 记录 `bestL, bestLen`。
- "如果 `target` 很大、无解？" → 返回 0，注意 `ans` 的哨兵值。

### 4.8 LC 438 找到字符串中所有字母异位词

#### 1）题意

给定 `s` 和 `p`，找出 `s` 中所有是 `p` 的**字母异位词**的子串起始下标（子串长度必须等于 `p` 的长度，且字符计数完全相同）。

例：`s = "cbaebabacd", p = "abc"` → `[0, 6]`。

#### 2）暴力

枚举所有长度 `|p|` 的子串，排序后与 `p` 比较：O(n · m log m)。或每次重建计数数组：O(n · (m + Σ))。

#### 3）关键洞察

**"异位词"= 长度相同 + 每种字符计数相同** → 这是**定长窗口**问题。

朴素做法：每个窗口都比较 26 个计数 → O(26n)。虽然 26 是常数，但面试官会问"能不能只 O(1) 判断"。优化方案：维护 `diff` = "计数数组中非零位置的个数"。

- 加入字符：若该位置计数从 `0` 变非 `0`，`diff++`；若从非 `0` 变 `0`，`diff--`。
- 移出字符同理反向。
- `diff == 0` ⟺ 计数数组全 0 ⟺ 是异位词。

这样每次窗口移动 2 次 O(1) 更新，判定 O(1)。

**关键实现技巧**：让 `cnt[c] = 窗口内计数 - p 中计数`。初始时把 `p` 的计数**减去**，于是"全 0"就表示匹配。

#### 4）算法

```java
class Solution {
    public List<Integer> findAnagrams(String s, String p) {
        List<Integer> res = new ArrayList<>();
        int n = s.length(), m = p.length();
        if (n < m) return res;

        int[] cnt = new int[26];
        for (char c : p.toCharArray()) cnt[c - 'a']--;    // 需求为负

        int diff = 0;                                     // 非零位置个数
        for (int i = 0; i < 26; i++) if (cnt[i] != 0) diff++;

        for (int i = 0; i < n; i++) {
            // 进入 s[i]
            int x = s.charAt(i) - 'a';
            if (cnt[x] == 0) diff++;
            cnt[x]++;
            if (cnt[x] == 0) diff--;

            // 移出 s[i - m]
            if (i >= m) {
                int y = s.charAt(i - m) - 'a';
                if (cnt[y] == 0) diff++;
                cnt[y]--;
                if (cnt[y] == 0) diff--;
            }

            if (diff == 0) res.add(i - m + 1);
        }
        return res;
    }
}
```

**"先判断再改"的细节**：`if (cnt[x] == 0) diff++` 必须在 `cnt[x]++` 之前（判断的是"改动前的状态"）；`if (cnt[x] == 0) diff--` 必须在之后（判断"改动后是否归零"）。**这个"跨 0 才更新"的模式在所有 `diff`/`valid` 型滑窗里通用。**

#### 5）正确性证明

**引理**：`diff == 0 ⟺ cnt` 数组全 0 ⟺ 当前窗口的字符计数与 `p` 完全相同 ⟺ 窗口是 `p` 的异位词。

**完整性**：`i >= m - 1` 时窗口长度恰为 `m`，每个可能的起点 `i - m + 1` 恰好被检查一次。∎

#### 6）复杂度

- 时间 O(n + m)：每步 O(1) 更新，共 n 步。
- 空间 O(Σ) = O(26)。

**对比**：不做 `diff` 优化时，每步 O(26) 比较，总 O(26n) —— 常数差 26 倍，在大数据量下会被卡常。

#### 7）易错点

1. `if (cnt[x] == 0) diff++` 与 `cnt[x]++` 的顺序反了。
2. 移出窗口时下标算成 `i - m + 1`（应为自己那一轮的起点 `i - m`）。
3. `n < m` 未特判 → 数组越界或错答案。
4. 用 `Map<Character,Integer>` 每次 `equals` 比较 → O(Σ) 每步，慢。
5. 字符集写死 26 但题目可能是大写字母 / 混合（应改用 `int[128]`）。

#### 8）变形与延伸

| 变形 | 差异 | 做法 |
|---|---|---|
| LC 567 字符串的排列 | 只判断"是否存在" | 同模板，`diff == 0` 时返回 `true` |
| LC 30 串联所有单词的子串 | 单位从"字符"变"单词"，且起点有 `L` 种 | 外层枚举 `0..L-1` 起点，内层按单词滑窗 |
| LC 1456 定长元音最大数目 | 定长窗口求最大 | 只维护元音计数 |
| LC 2461 长度为 K 子数组中的最大和 | 定长窗口 + 去重约束 | 定长窗口 + `HashSet` 维护窗口内不同元素 |
| LC 239 滑动窗口最大值 | 定长 + 求窗口最值 | **单调队列**（不是计数） |
| LC 643 子数组最大平均数 | 定长 + 求和 | 定长窗口维护 `sum` |

**LC 30 的完整思路（面试常考，属于"438 的加强版"）**：

```
设每个单词长度 L，单词个数 m = |words|
对 start ∈ [0, L-1]:                     ← 必须枚举 L 个起点
    以 L 为步长滑窗，窗口内含 m 个"单词块"
    用 Map<String,Integer> 维护窗口内单词计数与 words 的差异 diff
    diff == 0 → 记录 start + 当前块起点偏移
```

**为什么必须枚举 `L` 个起点？** 因为子串的起始位置不一定是 `L` 的倍数（`s` 的分块有 `L` 种相位）。这是"定长窗口 + 多相位"的关键，也是本题比 438 难的根本原因。复杂度 O(L × (n/L) × L) = O(nL)（单词比较 O(L)）。

#### 9）面试追问

- "用 `int[26]` 和 `HashMap` 的差别？" → 数组 O(1) 且常数小，但要求字符集有限；`HashMap` 通用但有哈希开销。
- "如果 `p` 很长、`s` 很短？" → `n < m` 直接返回空。
- "如果要返回所有异位词的**字符串**？" → 记录后 `substring`，注意 O(n·m) 的输出代价。

#### 组 1｜字节一面：LC 3 + "允许重复 k 次"

**问**：写一下无重复字符的最长子串。

**答（口语版）**：
> 「这是变长滑动窗口求最长。窗口 `[l, r]` 的约束是"无重复字符"，这个约束对窗口扩张单调——扩一定可能变非法，缩一定可能变合法，所以左指针可以不回退。我用一个 `int[128]` 记窗口内计数，右指针进入后如果当前字符计数 > 1 就收缩左指针直到它回到 1。总复杂度 O(n)，因为 `l` 和 `r` 各自单调前进，均摊下来每次 O(1)。」

**追问 1**：为什么左指针可以直接跳到"上次出现位置 + 1"，而不是一格一格挪？

**答**：
> 「设字符 `c` 上次出现在 `p`（`l ≤ p < r`）。任何左端点 `l' ∈ (l, p]` 的窗口都同时包含 `p` 和 `r` 两个 `c`，一定非法；任何 `r' > r` 的窗口也包含这两个 `c`，同样非法。所以以 `l' ∈ (l, p]` 为起点的候选全部无效，`l` 可以安全跳到 `p + 1`。这是"跳跃"版的正确性依据。」

**追问 2**：如果允许"每个字符最多重复 k 次"，怎么改？

**答**：
> 「把判据从 `cnt[c] > 1` 改成 `cnt[c] > k`，仍然成立，因为约束对扩张的单调性没变（扩只会让计数更大）。跳跃版就不适用了——因为一个字符可能在窗口内出现多次，跳一次不够，需要循环跳或者直接用计数版。」

```java
// 最多重复 k 次的最长子串
int l = 0, ans = 0;
int[] cnt = new int[128];
for (int r = 0; r < n; r++) {
    char c = s.charAt(r);
    cnt[c]++;
    while (cnt[c] > k) {
        cnt[s.charAt(l)]--;
        l++;
    }
    ans = Math.max(ans, r - l + 1);
}
```

**追问 3**：如果字符集是 Unicode（不止 128 个）？

**答**：
> 「`int[128]` 假设了 ASCII。Unicode 用 `HashMap<Character,Integer>`，空间 O(窗口内不同字符数)；或者按码点用 `int[65536]`（空间换时间）。面试里我会先问"字符集范围"，因为这直接影响结构选择。」

#### 组 2｜字节二面：LC 76 + `valid` 的 O(1) 之谜

**问**：最小覆盖子串。

**答**：先讲"求最短 → 合法即缩"的模板，再讲 `need[] + valid` 的 O(1) 判定，最后强调 `need[c]` 可以为负、必须用 `== 0` 判断。

**追问 1**：`valid == required` 为什么等价于"窗口覆盖 t"？

**答**：
> 「`need[c]` 表示"还需要几个 `c`"，`need[c] == 0` 表示这一类刚好满足（`< 0` 表示多余）。`valid` 维护的是"`need[c] == 0` 的种类数"。因为 `need` 只在每次加减 1 时变化，所以"是否归零"只需要在跨越 0 的那一步判断，这就是 O(1) 更新的本质。当所有 `required` 种都归零，就是覆盖；反之有任一 `need[c] > 0` 就缺字符。」

**追问 2**：`valid` 为什么会漏判"多余字符"?

**答**：
> 「不会漏判。若 `need[c] < 0`，说明窗口里该字符比需求多，覆盖依然成立，但此时 `valid` 不把它计入——可是"覆盖"需要的是"每一种都够"，多余的字符不影响"够不够"。所以只要所有种类的 `need[c] ≤ 0`（等价于都 `== 0` 被计入或 `< 0` 不计入但已够），就覆盖。严格地说：`valid == required` 是"每种都够"的充要条件，因为 `need[c] > 0` 的种数 = `required - valid`。」

（面试官如果深挖，这里可以补一句：**`need[c] < 0` 时该种类"够"，只是没被计入 `valid`；但"够"的充要条件是 `need[c] ≤ 0`，而 `valid` 统计的是 `== 0`。这两者是否会不一致？** 答案：当 `need[c] < 0` 时它已经先经历过 `== 0`，`valid` 已经 +1 了，所以 `valid` 计入过它。因此 `valid` 精确等于"`need[c] ≤ 0` 的种数"。**这是最漂亮的一句话**。）

**追问 3**：如果 `t` 有 1e5 个字符（不只是 26 个小写）？

**答**：
> 「`int[128]` 换成 `HashMap`，或按"只统计 `t` 中出现过的字符"裁剪。`required` 用 `Map.keySet().size()`。空间从 O(Σ) 降到 O(|t| 的不同字符数)，时间不变。」

#### 组 3｜阿里：LC 560 与"前缀和家族"

**问**：和为 K 的子数组，要求 O(n)。

**答**：前缀和 + 哈希计数，`map[0] = 1`，先查后插。

**追问 1（核心）**：为什么这题不能用滑动窗口？

**答（这是必须答满分的题）**：
> 「滑动窗口成立的前提是"窗口状态关于左右端点单调"：右端点右移，状态单向变化；左端点右移，状态反向变化。本题 `nums` 可以含负数，右移不保证 `sum` 增大、左移不保证 `sum` 减小，单调性被破坏。举个反例：`nums = [5, -10, 5], k = 5`，从 `l=0` 开始 `sum=5` 满足，收缩到 `l=1` 后 `sum=-10`，`r=2` 时 `sum=-5`，永远不再满足，但 `nums[2]=5` 本身就是解，滑窗会漏掉。所以必须用前缀和 + 哈希。」

**追问 2**：如果保证数组全是正数，能不能滑窗？复杂度？

**答**：
> 「可以。求"和为 k 的子数组个数"时，正数下 `sum` 单调，可以滑窗，时间 O(n)、空间 O(1)，比哈希更优。但注意"恰好等于 k"在正数下依然要求精确命中，滑窗写法是：`sum < k` 扩张、`sum > k` 收缩、`sum == k` 计数并收缩——因为可能有多个窗口和相同。这道题在正数下是 209 的"等式版"变体。」

**追问 3**：改成"和能被 K 整除的子数组个数"？

**答**：
> 「同余前缀和。`(P[r] - P[l]) % K == 0 ⟺ P[r] % K == P[l] % K`。用 `HashMap<Integer,Integer>` 统计同余类，注意 Java 里负数取模为负，要 `(x % K + K) % K` 归一化。`map[0] = 1` 仍然要保留（空前缀）。」

```java
public int subarraysDivByK(int[] nums, int k) {
    Map<Integer, Integer> cnt = new HashMap<>();
    cnt.put(0, 1);
    int pre = 0, ans = 0;
    for (int x : nums) {
        pre = ((pre + x) % k + k) % k;
        ans += cnt.getOrDefault(pre, 0);
        cnt.merge(pre, 1, Integer::sum);
    }
    return ans;
}
```

**追问 4**：如果是"长度至少为 2 且和能被 K 整除"？

**答**：
> 「LC 523。哈希表存"该余数**最早**出现的下标"，遍历到 `i` 时若 `i - first >= 2` 则存在解。注意这里求"是否存在"而非"计数"，所以存下标而不是次数。」

**追问 5**：如果要"最短"的、和能被 P 整除的子数组？

**答**：
> 「LC 1590。把"存最早下标"改成"存**最晚**下标"，`i - last` 才是最短。**同一个模板，存次数 → 计数，存最早 → 最长，存最晚 → 最短。** 这是这道题最有价值的迁移点。」

#### 组 4｜美团：LC 209 与"含负数"的进阶

**问**：长度最小的子数组。

**答**：正数前提 → 滑窗，合法即缩。

**追问 1**：为什么元素必须是正数？

**答**：给出 4.7 中的反例 `[5, -10, 5], target = 5`，说明左指针收缩后 `sum` 可能"重新变大"，滑窗的"左指针只增"假设失效。

**追问 2**：如果含负数，怎么做？（→ LC 862）

**答**：
> 「前缀和 + 单调队列。要 `P[r] - P[l] ≥ K` 且 `r - l` 最小。因为 `P` 不单调，不能二分，但可以把"候选的 `l`"用一个**单调递增的双端队列**维护：新来的 `P[i]` 若比队尾小，说明它下标更晚、值更小，队尾永远不可能成为最优 `l`，直接弹掉；每次用队头判断 `P[r] - P[front] ≥ K`，满足就更新答案并弹出（因为后面的 `r` 更大，这个 `l` 不会给出更短的区间）。每个下标进出队各一次，O(n)。」

**追问 3**：为什么可以从**队头**弹？弹掉不会漏解吗？

**答**：
> 「队头是当前"最小前缀和"，它给出的区间最短。一旦 `P[r] - P[front] ≥ K` 成立，说明以 `front` 为起点、`r` 为终点的区间已经合法，且长度是 `r - front`。之后 `r` 只会更大，同一个 `front` 给出的长度只会更长，不会更优，所以可以安全弹出。这是"越早的起点越短"的单调性。」

**追问 4**：为什么可以从**队尾**弹？

**答**：
> 「设队尾下标 `j`，新下标 `i > j` 且 `P[i] ≤ P[j]`。对任意未来的 `r`，若 `P[r] - P[j] ≥ K` 则 `P[r] - P[i] ≥ K` 也成立，且 `i` 给出的长度更短。所以 `j` 被 `i` 完全支配，可以弹掉。这就是"单调队列"的标准支配论证。」

#### 组 5｜腾讯：LC 15 三数之和与"三处去重"

**问**：三数之和。

**答**：排序 + 固定 `i` + 相向双指针。三处去重：`i`、`l`、`r`。

**追问 1**：三处去重分别是防什么重复？

**答**：
> 「`i` 去重：防"同一个三元组的第一个数被枚举两次"（如 `[-1,-1,0,1]` 中两个 `-1` 都作为 `i`）。
> `l`/`r` 去重：防"在固定 `i` 时，同一个 `(第二数, 第三数)` 组合被多次产出"（如 `[0,0,0,0]`）。
> 三处合起来保证解集唯一。注意 `l`/`r` 的跳过必须在**加入结果之后**，否则会漏掉合法解。」

**追问 2**：为什么 `i` 循环到 `n-2` 就够？

**答**：因为 `l = i+1`、`r = n-1` 至少要两个元素，`i ≤ n-3`；写成 `i < n-2` 且 `n-2` 一开始的 `if (nums[i] > 0) break` 会挡掉大部分，但边界必须正确。

**追问 3**：四数之和怎么做？复杂度？

**答**：
> 「LC 18。两层枚举 `i, j`（各带去重）+ 内层双指针，O(n³)。两个坑：一是 `nums[i] + nums[j] + nums[l] + nums[r]` 溢出，要转 `long`；二是双层去重的写法容易漏，标准写法是 `if (i > 0 && nums[i] == nums[i-1]) continue;` 和 `if (j > i + 1 && nums[j] == nums[j-1]) continue;`。」

**追问 4**：求"三数之和小于 target 的个数"？

**答**：
> 「LC 259/611 型。排序后固定 `i`，双指针：若 `nums[l] + nums[r] < target`，则 `r' ∈ (l, r]` 全部满足，一次累加 `r - l`，然后 `l++`；否则 `r--`。这是"批量计数"，比逐个判断快。O(n²)。」

**追问 5**：如果要求三元组**下标**不重复但**值**可以重复？

**答**：
> 「排序后会丢失下标，所以要么额外记录原始下标，要么改用"枚举 `i` + 哈希找第三个数"的 O(n²) 做法。面试里我会先确认"重复"的定义是"值重复"还是"下标重复"，这决定了去重策略。」

#### 组 6｜字节：LC 11 / 84 / 42 三题辨析（高频"概念关"）

**问**：11、84、42 三题有什么区别？

**答（一句话版，务必背熟）**：
> 「**11 是"两端"**：两根柱子围一个容器，容量由两端较矮者决定，相向双指针，一次决策丢弃一片候选。
> **84 是"区间最矮"**：连续柱子围一个矩形，高度由区间内最矮柱决定，需要找每个柱子左右第一个更矮的柱子，用单调栈。
> **42 是"左右两侧最大值"**：每个柱子上方能存多少水，由左右最大值的较小者决定，双指针 / 单调栈 / DP 都可以。」

**追问 1**：11 为什么移动矮的？移动高的一定错吗？

**答**：
> 「设 `h[l] < h[r]`。若移动 `r`，则被丢弃的候选是 `(l', r)` 其中 `l' > l`。这些候选的容量 `= min(h[l'], h[r]) * (r - l')`，宽度更小，但高度可能更高（`h[l']` 可能远大于 `h[l]`），所以**可能比当前容量更大** → 丢弃会漏解。而移动 `l` 时，被丢弃的 `(l, r')` 容量 `= min(h[l], h[r']) * (r' - l) ≤ h[l] * (r - l)`，一定不超过当前容量 → 安全。所以"移动矮的"不是启发式，是**支配关系**决定的。」

**追问 2**：42 的双指针为什么能 O(1) 空间？

**答**（用 4.5 的归纳不变量）：

> 「因为每次只需要结算"被限制的那一侧"。当 `h[l] < h[r]` 时，右侧至少存在 `h[r]` 这一根不低于 `h[l]` 的柱子，可以证明 `leftMax ≤ rightMax`，于是 `l` 处的水位完全由 `leftMax` 决定，与右侧具体形状无关，可以立即结算并丢弃。归纳地，被越过的那一侧的所有柱子都满足"当时另一侧有更高的柱子"，所以永远不需要知道另一侧的完整最大值数组。」

**追问 3**：24 小时降雨后，怎么求"哪一段积水最多"？

**答**：
> 「先求出每列的水量数组（双指针可在 O(n) 内直接产出），再对水量数组求"最大子段和"（Kadane / 前缀和最小前缀）。两步都是 O(n)。」

#### 组 7｜阿里：LC 42 的证明（难度天花板）

**问**：接雨水，双指针，讲清楚为什么是对的。

**答**（完整版，按 4.5 的归纳论证展开；面试里可以压缩成两句）：
> 「核心是：位置 `i` 的水量 `= min(L_i, R_i) - h[i]`，其中 `L_i`、`R_i` 是左右两侧的最大值。
> 双指针维护 `l`、`r` 和已扫过的两侧最大值。当 `h[l] < h[r]` 时，我断言 `L_l ≤ R_l` 成立，于是 `l` 处水量 `= L_l - h[l]`，只依赖左侧，可以立即结算。
> 这个断言的归纳证明是：若 `L_l > R_{l+1}`，则因 `L_l ≤ R_l = max(h[l], R_{l+1})`，必有 `L_l = h[l]`，即 `h[l] > R_{l+1} ≥ h[r] > h[l]`，矛盾。所以 `L_l ≤ R_{l+1}`，加上 `h[l] < R_{l+1}`，得到 `L_{l+1} ≤ R_{l+1}`。」

**追问 1**：单调栈的解法讲一下，和双指针等价吗？

**答**：
> 「不等价但是同一个量的两种算法。单调栈是"按层横着算"：栈里维护递减的柱高，遇到更高的柱子就弹出栈顶作为"凹槽底"，栈顶下面是"左边界"，当前是"右边界"，一次结算一层水量 `(右-左-1) * (min(左高,右高) - 底高)`。双指针是"按列竖着算"。两者都是 O(n)，栈版空间 O(n)，指针版 O(1)。」

**追问 2**：如果柱子宽度不为 1（有宽度数组 `w[i]`）？

**答**：
> 「把宽度也做前缀和，`widthSum(l, r) = W[r+1] - W[l]`。双指针版里每一列的水量乘上该列宽度；单调栈版里 `width = W[i] - W[left+1]`。本质是"把'个数'换成'加权和'"，需要前缀和辅助。」

**追问 3**：二维接雨水（LC 407）？

**答**：
> 「木桶效应升级为"边界最矮决定水位"。用最小堆把最外圈入堆，每次弹出最矮的格子向内扩展，新水位 `= max(当前水位, 邻格高度)`，把 `max(...) - 邻格高` 累加。本质是 Dijkstra/多源 BFS。O(mn log(mn))。」

#### 组 8｜快手：LC 438 与 LC 30

**问**：找到所有字母异位词。

**答**：定长窗口 + `cnt` 差异数组 + `diff` 计数。

**追问 1**：`diff` 到底省了什么？

**答**：
> 「省掉了"每步遍历 26 个字符比较计数"的 O(Σ)。`diff` 只在计数跨越 0 的瞬间变化，所以每次窗口移动只需两次 O(1) 判断。总复杂度从 O(26n) 降到 O(n)。」

**追问 2**：如果把"字符"换成"单词"（LC 30）？

**答**：
> 「这是本题的加强版，关键差异有三点：
> ① 单位从字符变成单词，窗口按"单词长度 L"为步长滑动；
> ② 起点有 L 种相位（子串起点不一定是 L 的倍数），所以外层要枚举 `0..L-1` 的起点，各跑一遍；
> ③ 窗口内用 `Map<String,Integer>` 记单词计数，用 `diff` 记"计数不符的单词种类数"。
> 复杂度 O(L × n/L × L) = O(nL)（`L` 是单词长度，最后那个 `L` 是字符串比较代价，实际可用哈希降为 O(n) 期望）。」

**追问 3**：为什么不能直接用"字符级"滑窗？

**答**：
> 「因为"由这些单词拼接"这个约束在字符粒度上不单调——字符窗口内可能有各种非法排列。必须在单词粒度上做窗口，且长度固定为 `m × L`，是**定长窗口**而不是变长。」

#### 组 9｜美团/字节：场景题"接口限流"

**问**：设计一个"每分钟最多 100 次"的限流器，讲清算法。

**答**：
> 「四种主流方案，本质区别就是"用哪种窗口"：
> ① **固定窗口计数**：按整分钟分桶，Redis `INCR` + `EXPIRE`。实现最简单，但有"临界突刺"问题（59 秒 100 次 + 下一秒 100 次 = 2 秒内 200 次）。
> ② **滑动窗口日志**：用 `ZSET` 存每次请求的时间戳，`ZREMRANGEBYSCORE` 清理窗口外的，`ZCARD` 判断。精确，但内存 O(请求数)。
> ③ **滑动窗口计数（分桶近似）**：把 1 分钟切成 6 个 10 秒的桶，用"前一个桶的加权 + 当前桶"估算。内存 O(桶数)，精度可调。这是"滑动窗口 + 前缀和"的工程变体——把"区间求和"变成"两个桶的加权差"。
> ④ **令牌桶 / 漏桶**：允许突发（令牌桶）或强制匀速（漏桶），用 `(now - last) * rate` 补令牌，O(1) 状态。」
> 「如果面试官强调"精确 + 低内存"，答案通常是 ③；强调"允许突发"，答案是 ④。」

**追问**：滑动窗口计数的"加权"怎么算？

**答**：
> 「设窗口 `W`、桶宽 `B`，当前时刻在桶 `k` 的第 `t` 秒。估算值 `= 桶[k-1] * (1 - t/B) + 桶[k] + ...`（对跨越窗口的所有桶加权求和）。本质上是**把"滑动窗口求和"近似为"分桶前缀和的线性插值"**，把 O(n) 的逐请求统计压到 O(桶数)。」

#### 组 10｜蚂蚁/京东数科：场景题"对账区间汇总"

**问**：T+1 对账，每天要把"某个商户某段时间的交易总额"和渠道方对平。数据量 1 亿条，怎么高效算区间和？

**答**（这题直接考查"前缀和/差分能不能落地"）：
> 「分三层回答：
> ① **单机内存版**：把交易按"账户 + 日期"排序，做前缀和数组 `P`，任意区间 `[l, r]` 的和 O(1)。适合"按日聚合后的百万级"。
> ② **大数据版**：不能全量物化前缀和（1 亿条 × 8 字节 = 800MB 起）。做法是"**按日预聚合 + 二级前缀和**"：先按 `(商户, 日期)` 聚合成日汇总表（通常只有百万行），对这百万行做前缀和/或按商户分区做前缀和。区间查询 = 两次查表相减。
> ③ **核对方向**：差异定位用**差分**思维——把"渠道流水"和"我方流水"按 `(商户, 日期)` 做 `full outer join`，差异 = 左 - 右。若要做"批量修正"（比如给某商户某区间统一调账），用差分在 O(1) 内标记区间，最后统一回放。
> 「关键结论：**前缀和解决"查询多、更新少"，差分解决"更新多、查询少"**。对账场景是"查询多、写入一次性"，所以选前缀和（预聚合）；调账场景是"批量区间修改"，所以选差分。」

**追问**：如果区间查询还要"按金额分档"（比如统计 > 1000 的交易额）？

**答**：
> 「前缀和失效（不可加性被分档破坏）。改用"按档位分别建前缀和"（每个档一个数组，空间 × 档数），或用树状数组/线段树做带条件的聚合，或走离线排序 + 分块。」

#### 组 11｜阿里：设计题"支持单点更新 + 区间求和"

**问**：前缀和能 O(1) 查区间和，但如果元素会变呢？

**答**：
> 「前缀和的弱点是"更新 O(n)"——改一个元素要重建其后所有前缀。这就需要**树状数组（BIT）**或**线段树**：单点更新 O(log n)，区间查询 O(log n)。
> 选择依据：只要"单点更新 + 区间和"→ BIT（常数小、代码短）；要"区间更新 + 区间查询"→ 线段树带 lazy；要"区间最值"→ 线段树（前缀最值不可减，不能用 BIT）。」

```java
// 树状数组（Fenwick）模板：单点加 + 前缀和
class BIT {
    long[] t; int n;
    BIT(int n) { this.n = n; t = new long[n + 1]; }
    void add(int i, long v) { for (i++; i <= n; i += i & -i) t[i] += v; } // i 从 0 开始传入
    long sum(int i) {          // [0, i] 的前缀和，i 传下标
        long s = 0;
        for (i++; i > 0; i -= i & -i) s += t[i];
        return s;
    }
    long range(int l, int r) { return sum(r) - (l == 0 ? 0 : sum(l - 1)); }
}
```

**追问**：BIT 的 `i & -i` 是什么原理？

**答**：
> 「`i & -i` 取出 `i` 的最低位 1（lowbit），它对应"这个下标管辖的区间长度"。`add` 向上跳（每次加 lowbit，跳到所有包含它的区间），`sum` 向下跳（每次减 lowbit，把前缀拆成若干个不重叠的管辖块）。所以两个操作都是 O(log n)。」

#### 组 12｜综合追问：把三块知识串起来

**问**：如果让你总结"什么时候用双指针、什么时候用滑窗、什么时候用前缀和"，你会怎么说？

**答（这是收尾的"体系化回答"，能显著加分）**：
> 「我会按"约束的形状"来分：
> ① 约束是"两个端点的比较关系"（有序、两端支配）→ **相向双指针**，本质是用支配关系一次丢弃一片候选。
> ② 约束是"一个连续区间的合法性"，且这个合法性对"扩张/收缩"单调 → **滑动窗口**，本质是左指针单调不回退。
> ③ 约束是"区间上的可加量"（和、异或、计数、奇偶掩码）→ **前缀和**，把区间变成两个端点的差；若需要"找配对"，再叠哈希（计数/最值下标）或单调队列（含负数）。
> ④ 约束是"批量区间修改"→ **差分**，是前缀和的逆运算。
> 一句话：**双指针靠"支配"，滑窗靠"单调"，前缀和靠"可减"。三者失效的场景也正好对应：没有支配关系 → 双指针错；不单调 → 滑窗错；不可减（最值、分档）→ 前缀和错。**」

**LC 53 的"前缀和视角"值得展开**（很多人只会 Kadane，不会这个视角）：
`max subarray sum = max over r of (P[r] - min(P[0..r-1]))`。即"扫描时维护出现过的最小前缀和"。这与 Kadane 完全等价，但**更容易解释**，而且能自然扩展到"求最大子段和的下标"。

```java
public int maxSubArray(int[] nums) {
    long pre = 0, minPre = 0, ans = Long.MIN_VALUE;
    for (int x : nums) {
        pre += x;
        ans = Math.max(ans, pre - minPre);
        minPre = Math.min(minPre, pre);
    }
    return (int) ans;
}
```

### 7.1 滑动窗口限流器（最经典落地）

**问题**：接口"任意连续 60 秒内最多 100 次"。

**方案对比**（已在 5.3 组 9 给出，这里给可运行代码）：

```java
// 方案 A：单机内存版——滑动窗口日志（精确，O(窗口内请求数) 内存）
class SlidingWindowLimiter {
    private final Deque<Long> log = new ArrayDeque<>();
    private final int limit;
    private final long windowMs;

    SlidingWindowLimiter(int limit, long windowMs) {
        this.limit = limit;
        this.windowMs = windowMs;
    }

    synchronized boolean tryAcquire(long now) {
        // 1. 清理窗口外的记录（滑动窗口的"左指针收缩"）
        while (!log.isEmpty() && now - log.peekFirst() >= windowMs) {
            log.pollFirst();
        }
        // 2. 判断窗口内的请求数
        if (log.size() >= limit) return false;
        log.addLast(now);
        return true;
    }
}
```

> **和算法题的对应关系**：`log` 就是"窗口"，`pollFirst` 就是"左指针右移"，`size()` 就是窗口状态。**限流器就是一道"求窗口内元素个数"的滑动窗口题**，只是数据是流式的。

```java
// 方案 B：滑动窗口计数（分桶近似）——把"区间求和"变成"两个桶加权"
class BucketLimiter {
    private final long bucketMs;      // 桶宽，例如 10s
    private final int buckets;        // 桶数 = 窗口/桶宽
    private final int limit;
    private final long[] cnt;
    private long lastBucket;

    BucketLimiter(int limit, long windowMs, int buckets) {
        this.limit = limit;
        this.bucketMs = windowMs / buckets;
        this.buckets = buckets;
        this.cnt = new long[buckets];
    }

    synchronized boolean tryAcquire(long now) {
        long cur = now / bucketMs;
        if (cur != lastBucket) {
            long diff = cur - lastBucket;
            // 清空跨过的桶（等价于"滑动窗口左指针跳过整段"）
            for (long i = 1; i <= Math.min(diff, buckets); i++) {
                cnt[(int) ((lastBucket + i) % buckets)] = 0;
            }
            lastBucket = cur;
        }
        // 近似：上一个桶按时间比例加权
        long used = 0;
        for (int i = 0; i < buckets; i++) used += cnt[i];
        if (used >= limit) return false;
        cnt[(int) (cur % buckets)]++;
        return true;
    }
}
```

### 7.2 监控指标：最近 N 秒错误率

**问题**：实时计算"最近 5 秒的错误率"，QPS 1e5。

**做法**：
- 把 5 秒切成 50 个 100ms 的桶，维护 `cntErr[i]`、`cntAll[i]`，每个桶滚动清空；
- 每次查询时对 50 个桶求和 → **这就是"定长滑动窗口 + 分桶前缀和"**；
- 若要求"精确"，则用 `滑动窗口日志`（内存代价大）；若要求"亚秒级新鲜度 + 低内存"，用分桶。

**为什么不用前缀和数组**：流式数据的前缀和无法增量维护（每天新增会改变所有后续前缀）。**流式场景的标准替代是"分桶 + 滚动"**，本质是用"分桶的近似"换"前缀和的精确 O(1)"。

### 7.3 对账场景：前缀和 / 差分的三种用法

| 场景 | 数据结构选择 | 原因 |
|---|---|---|
| 单商户某区间交易总额 | 按日预聚合 + 前缀和 | 查询多、写入一次性 |
| 批量调账（某商户某区间统一 +X） | 差分 | 更新多、区间加 O(1) |
| 差异定位（我方 vs 渠道） | 双表 full join + 差分对比 | 差分的"变化点"就是差异点 |
| 分档金额区间统计 | 树状数组/线段树（带条件） | 分档破坏可加性 |
| 日切后重算 | 重建前缀和（O(n)） | 前缀和的更新代价 O(n) |

**一个具体的对账落地思路（可以直接讲给面试官）**：

```
① 明细层：trade_detail(商户, 日期, 金额)  —— 亿级
② 聚合层：按 (商户, 日期) 聚合 —— 百万级，物化
③ 索引层：对每个商户，按日期做前缀和数组 P[商户][日期] —— 百万级
④ 查询：sum(商户, d1, d2) = P[商户][d2] - P[商户][d1-1]  —— O(1)
⑤ 调账：用差分数组记录"待调整区间"，日终统一回放 —— O(1) 标记，O(n) 回放
```

**关键取舍**：前缀和 = "空间换查询"（空间 O(n)，查询 O(1)）；差分 = "时间换修改"（修改 O(1)，查询 O(n) 回放）。**面试时把这句话说出来，基本就拿到这一问的分了。**

| 症状 | 大概率原因 | 定位方法 |

## 写在最后

这份笔记的"骨架"是三句话，其余都是血肉：

1. **双指针**：每一步丢弃的候选，必须被某个已评估的候选支配——这是**证明**，不是**技巧**。
2. **滑动窗口**：左指针不回退的合法性来自"约束关于端点单调"——一旦不单调（负数、恰好 K），立刻换工具。
3. **前缀和**：把区间折叠成端点之差；"可减"是它的边界，不可减的量（最值、分档）必须换数据结构。

把这三句话讲清楚，比刷 100 道题更能通过面试。
