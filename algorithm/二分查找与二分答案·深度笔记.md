## 0. 一页速览

### 0.1 二分家族全景

| 类别 | 搜索对象 | 成立前提 | 代表题 | 复杂度 |
|---|---|---|---|---|
| **索引二分** | 数组下标 | 有序 / 半有序 / 单峰 | 704、34、33、162 | `O(log n)` |
| **值域二分（二分答案）** | 答案的取值 | 可行性单调（P(x) 单调） | 875、1011、410、1482、1552、719 | `O(n log C)` |
| **实数二分** | 浮点答案 | 单调 + 精度可控 | 69、644、解方程、最大平均值 | `O(iter × check)` |
| **结构内二分** | 树 / 位 / 链表 | 结构可"随机导航" | TreeMap、权值 BIT 倍增、跳表 | `O(log n)` |

> `C` = 答案值域大小（capacity）。`log C` 对 `int` 值域约为 31，对 `long` 约为 63，**与实际 n 无关**，这是二分答案复杂度看起来"很大"但其实很轻的原因。

### 0.2 拿到题后 30 秒的决策流程

```
                题目要你「找一个值 / 求一个最优值」
                              │
        ┌─────────────────────┼─────────────────────┐
        │                     │                     │
 ① 数组有序 / 局部有序 /   ② 答案是一个整数，且    ③ 答案是实数 / 平均值 /
    存在单峰性？              「x 变大后更容易        比率？
        │                     满足」或反之？              │
        ▼                     ▼                     ▼
   索引二分              二分答案                 实数二分
   (模板 T1~T3)          (模板 T4/T5)            (模板 T6)
        │                     │                     │
        └─────────────────────┴─────────────────────┘
                              │
                    以上都不满足 → 快速选择(nth_element)
                                  堆 / DP / 单调栈 / 三分
```

**判断口诀：有序看索引，最优看单调，实数看精度。**

再补三个"反向信号"——出现这些词，八成是二分答案：

- 「**最小化**……的**最大值**」「**最大化**……的**最小值**」（minimax / maxmin）
- 「在 **D 天 / H 小时 / K 次** 内完成」「**至少**能装下」「**容量**」「**速度**」「**距离**」
- 正着求最优解没法贪心，但"给我一个阈值，问行不行"很容易判定

### 0.3 六个模板（背到肌肉记忆，其余都是变形）

| 编号 | 名称 | 循环条件 | mid 取整 | 收缩方式 | 返回 |
|---|---|---|---|---|---|
| **T1** | 经典查找（闭区间） | `l <= r` | 下取整 | `l=mid+1` / `r=mid-1` | 命中 `mid`，否则 `-1` |
| **T2** | `lower_bound`（首个 ≥ x） | `l < r` | 下取整 | `l=mid+1` / `r=mid` | `l ∈ [0,n]` |
| **T3** | `upper_bound`（首个 > x） | `l < r` | 下取整 | `l=mid+1` / `r=mid` | `l ∈ [0,n]` |
| **T4** | 二分答案·**最小可行** | `l < r` | 下取整 | `l=mid+1` / `r=mid` | `l`（首个可行） |
| **T5** | 二分答案·**最大可行** | `l < r` | **上取整** | `l=mid` / `r=mid-1` | `l`（最后可行） |
| **T6** | 实数二分 | 固定迭代 | `(l+r)/2` | `l=mid` / `r=mid` | `l`（或 `(l+r)/2`） |

> T2 / T4 结构完全同构：**"找第一个满足条件的位置"**。所以 `lower_bound` 不是特例，而是"单调布尔序列找边界"的一个实例——这一点想通，二分就通了一半。

## 1. 二分的本质：不是"有序"，而是"可判定地排除一半"

### 1.1 三个层次的认知

大多数人第一次学二分，理解停留在：**"有序数组里折半找数"**。这个理解会让你在 33（旋转数组）、162（峰值）、875（二分答案）面前全部卡住。真正要建立的是三层认知：

**第 1 层｜有序 → 折半**
`a[mid] < target` 说明 target 只可能在右半边。这一步依赖"有序"。

**第 2 层｜单调谓词 → 边界**
把"比较大小"抽象成"判定真假"。设 `P(i)` 是一个布尔谓词，且满足

```
i:   0  1  2  3  4  5  6
P:   F  F  F  F  T  T  T        ← 单调（先 false 后 true）
                ↑
            要求的边界
```

二分就是在**这个单调布尔序列上找 F→T 的翻转点**。`lower_bound` 是 `P(i) = (a[i] >= x)`；875 的二分答案是 `P(k) = (以速度 k 能在 h 小时内吃完)`。**索引二分和二分答案是同一个算法**，只是定义域从"数组下标"换成了"答案取值"。

**第 3 层｜只要"能排除一半"就能二分**
`P` 甚至不必全局单调，只要在每一步都能**证明**"答案不在被排除的那一半"。162 寻找峰值就是典型：

```
nums:  1   2   1   3   5   6   4
                  ↑ mid=3
        nums[3]=3 < nums[4]=5  →  右侧一定存在峰值（沿上升方向走到下降处必有局部最大）
```

数组整体无序，但"斜率方向"这个局部信息足以排除一半。**这就是"可判定性"比"有序性"更本质的证据。**

> **面试话术**：如果面试官问"二分的前提是有序吗？"，正确的回答是——"有序是充分条件，不是必要条件。二分真正需要的是：每一步都能根据 `mid` 处的信息，确定性地排除掉一半候选区间。162 峰值题就是反例。"

### 1.2 不变量（Loop Invariant）：正确性的唯一保证

写二分不要靠"试出来"，要靠**不变量**。三种区间写法对应三条不变量：

| 写法 | 初始化 | 不变量 | 循环条件 | 退出状态 |
|---|---|---|---|---|
| **闭区间** `[l, r]` | `l=0, r=n-1` | 答案（若存在）必在 `[l, r]` 内 | `l <= r`（区间非空） | `l > r`，区间空 |
| **左闭右开** `[l, r)` | `l=0, r=n` | 答案（若存在）必在 `[l, r)` 内 | `l < r`（区间非空） | `l == r`，区间空 |
| **开区间** `(l, r)` | `l=-1, r=n` | 答案必在 `(l, r)` 内 | `r - l > 1` | `r == l + 1` |

**工程上只用前两种。** 第三种（开区间）每步要写 `l = mid` / `r = mid`，且必须保证 `mid` 严格落在 `(l,r)` 内，否则死循环——只在实数二分里用得多。

三条铁律：

1. **初始化必须满足不变量**。所以 `[l, r)` 的 `r` 要写 `n` 而不是 `n-1`，因为 `n-1` 可能是答案（插入到末尾的情况）。
2. **每次收缩后不变量仍成立**。`r = mid` 之所以合法，是因为 `mid` 位置的元素"可能"是答案（如 `lower_bound` 中 `a[mid] >= x` 时 mid 可能就是第一个），所以保留它。
3. **循环结束时区间为空 → 答案只能落在边界上**。这就是为什么 `lower_bound` 返回 `l` 是对的：`[l, r)` 空时 `l == r`，而所有 `< x` 的元素都已被排除到 `l` 左边。

### 1.3 死循环与溢出的数学根源（最重要的细节）

**死循环的唯一来源：区间长度收敛到 2 时，`mid` 落在端点，而你的更新没有移动那个端点。**

考虑区间 `[l, r]`，长度 2，即 `r = l + 1`：

- **下取整** `mid = l + (r-l)/2 = l + 0 = l` → mid 落在**左端点**
- **上取整** `mid = l + (r-l+1)/2 = l + 1 = r` → mid 落在**右端点**

于是：

| mid 取整 | 若写 `l = mid` | 若写 `r = mid` |
|---|---|---|
| **下取整** | ❌ **死循环**（l 不动） | ✅ 安全（r 收缩到 l） |
| **上取整** | ✅ 安全（l 收缩到 r） | ❌ **死循环**（r 不动） |

**口诀：下取整，动左边必须 `+1`；上取整，动右边必须 `-1`。**
另一种记法：**mid 落在左半 → 可以让 `r = mid`；mid 落在右半 → 可以让 `l = mid`。**

这张表能解释 90% 的二分 bug。写代码时只要问自己一句：**"我的 mid 是往左倒还是往右倒？我更新的是不是那个不动的一侧？"**

**溢出**：

```java
int mid = (l + r) / 2;        // ❌ l、r 都接近 2^31-1 时 l+r 溢出成负数 → 数组越界
int mid = l + (r - l) / 2;    // ✅ 差值不会溢出（前提 r >= l）
int mid = (l + r) >>> 1;      // ✅ 无符号右移，等价于 (l+r)/2 但按位处理负数也安全
```

- 面试最爱在这里埋雷：`278. 第一个错误的版本` 题干明确提示 "`mid = (left + right) / 2` 会导致溢出"，就是在考这个。
- 二分答案时若值域到 `1e18`（如 `long`），全部变量必须用 `long`。

### 1.4 返回值语义表（照着查，不用现推）

| 需求 | 用哪个模板 | 写法 | 返回值 |
|---|---|---|---|
| 第一个 `>= x` | T2 | `a[mid] < x → l=mid+1; else r=mid` | `l`，范围 `[0, n]` |
| 第一个 `> x` | T3 | `a[mid] <= x → l=mid+1; else r=mid` | `l`，范围 `[0, n]` |
| 最后一个 `<= x` | T3 推论 | `upper_bound(x) - 1` | 可能 `-1`（不存在） |
| 最后一个 `< x` | T2 推论 | `lower_bound(x) - 1` | 可能 `-1` |
| `x` 出现次数 | T2+T3 | `upper_bound(x) - lower_bound(x)` | `≥ 0` |
| `x` 是否存在 | T2 | `l < n && a[l] == x` | `boolean` |
| 有序插入位置（保持有序） | T2 | `lower_bound` | `[0, n]` |
| 第一个可行（最小可行答案） | T4 | `check(mid) → r=mid; else l=mid+1` | `l` |
| 最后一个可行（最大可行答案） | T5 | `check(mid) → l=mid; else r=mid-1` | `l` |

> **一把尺子**：`lower_bound` 的结果 `l` 表示"**小于 x 的元素有 l 个**"。所有变体都能从这里推出来，不需要背。

### 1.5 复杂度与理论下界

**比较次数**：`⌈log₂(n+1)⌉`。`n = 10⁹` 时约 30 次。

**信息论下界（为什么二分是最优的）**：把二分过程看成一棵**判定树**，`n` 个元素有 `n+1` 种可能结果（命中某个下标，或"不存在"，共 n+1 种）。每次比较最多提供 1 bit 信息，树的叶子必须 ≥ n+1，所以树高 ≥ `⌈log₂(n+1)⌉`。二分正好达到这个下界，因此**在"仅比较"模型下，二分是不可改进的**。

**但这个下界不是绝对的**——它只对"比较模型"成立。一旦允许别的操作，还能更快：

- **哈希表**：`O(1)` 期望时间查值（预处理 `O(n)`），代价是失去序关系、不支持范围查询。
- **插值查找**（interpolation search）：均匀分布下 `O(log log n)`，最坏退化 `O(n)`。
- **B 树 / B+ 树**：把"二叉"改成"多路"，树高从 `log₂n` 降到 `log₃₀₀n`。这是数据库不用二分而用 B+ 树的根本原因（见 4.4）。

**空间**：迭代 `O(1)`，递归 `O(log n)`（尾递归可消除）。

### 1.6 递归 vs 迭代

```java
// 递归版（理解用，不要在生产写）
int bs(int[] a, int l, int r, int x) {
    if (l > r) return -1;
    int mid = l + (r - l) / 2;
    if (a[mid] == x) return mid;
    return a[mid] < x ? bs(a, mid + 1, r, x) : bs(a, l, mid - 1, x);
}
```

递归深度 `log n`，不会爆栈，但每层有函数调用开销、无法尾递归优化（Java 没有 TCO）。**一律写成迭代。**

## 2. 二分答案（Binary Search on Answer）

### 2.1 它到底在干什么：把"构造最优"降级为"判定阈值"

这是二分答案最值得讲清楚的一点。很多题的正解是"求最优解"，但最优解的直接构造极其复杂（要 DP、要贪心证明、要枚举组合）。二分答案做了一个**降维打击**：

```
原始问题：求最小的 x，使得某个复杂条件成立
              ↓  换个问法
降级问题：给定 x，问"条件成立吗？"   ← 这通常只要 O(n) 的贪心/双指针/前缀和
              ↓  如果"x 越大越容易成立"（单调）
答案：在 x 的取值范围内二分这个"是/否"
```

**代价**：多乘一个 `log C`（约 30 倍）。
**收益**：把一个 NP 味的最优化问题，变成一个线性可行性判定问题。

> **一句话总结**：二分答案是**用 log 的时间复杂度，换掉一次"最难的那步推导"**。所以当你发现"正着不会做、但给我一个数我会判"时，就该想到它。

### 2.2 四步法（每道二分答案题都按这四步走）

**第 1 步｜定答案（Identify）**
把"最优值"提炼成一个标量 `x`，并明确它的**物理含义和单位**：

| 题目 | 答案 x 的含义 | x 的取值范围 |
|---|---|---|
| 875 珂珂吃香蕉 | 每小时吃 `x` 根 | `[1, max(piles)]` |
| 1011 运包裹 | 船的载重 `x` | `[max(w), sum(w)]` |
| 410 分割数组 | 子数组和的上限 `x` | `[max(nums), sum(nums)]` |
| 1482 做花束 | 等待 `x` 天 | `[min(bloom), max(bloom)]` |
| 1552 放球 | 球间最小距离 `x` | `[1, max-min]` |
| 719 数对距离 | 第 k 小的距离值 `x` | `[0, max-min]` |

**第 2 步｜证单调（Prove Monotonicity）**
必须能严格说出：`x` 变大（或变小）时，可行性**只会**单向变化。标准证法有两种：

- **构造性**：若 `x` 可行，则把 `x` 换成 `x+1` 后，同一个方案仍然可行（如 875：吃得更多，用时只会更短）。
- **反证**：若 `x+1` 不可行，则 `x` 必不可行。

⚠️ **这一步不能跳**。check 不单调是二分答案最常见的错误来源（见 2.7）。

**第 3 步｜写 check（Predicate）**
要求三条：

1. **与命题等价**：`check(x) == true` ⟺ "答案为 x 时问题可解"；
2. **无副作用**：不能修改传入的数组/全局状态（否则下一次 check 被污染）；
3. **能早退**：一旦确定结论就 `return`，别跑满全程。

**第 4 步｜定边界（Bounds）**
最容易翻车的地方：

- **`hi` 必须天然可行**（用 T4 / T5 时）。若 `check(hi) == false`，说明整个值域无解，要先特判返回 `-1`。
- **`lo` 不一定要可行**。T4 的语义是"找第一个可行"，`lo` 可以是"必然不可行"的哨兵。
- **`lo` 绝不能被排除**。若答案可能是 `0`，`lo` 就要从 `0` 开始，别从 `1` 开始。

### 2.3 check 函数的五种常见形态

| 形态 | 判定逻辑 | 代表题 | check 复杂度 |
|---|---|---|---|
| **贪心装桶** | 顺序遍历，装不下就换桶，数桶数 | 1011、410 | `O(n)` |
| **贪心邻接匹配** | 顺序扫描，满足条件就累计，断了就清零 | 1482、1552 | `O(n)` |
| **双指针计数** | 数"满足 `≤ x` 的对/子数组有多少个" | 719、786 | `O(n)` |
| **前缀和最值** | 转化成"是否存在长度 ≥ k 且和 ≥ 0 的段" | 644 | `O(n)` |
| **数学公式/构造** | 用闭式公式算"最小总消耗" | 1802、793 | `O(1)` / `O(log n)` |

**统一视角**：check 的本质是"**计数**"或"**存在性**"。要么数"满足条件的元素个数够不够 k"，要么判"能不能构造出一个满足约束的方案"。

### 2.4 边界与返回值的三种写法（按场景选）

**写法 A：first-true（最常用，`hi` 必须可行）**

```java
int lo = L, hi = R;              // 保证 check(hi) == true
while (lo < hi) {
    int mid = lo + (hi - lo) / 2;        // 下取整
    if (check(mid)) hi = mid;            // mid 可行 → 答案 ≤ mid，保留 mid
    else            lo = mid + 1;        // mid 不可行 → 答案 > mid，丢弃 mid
}
return lo;                                // 第一个可行值
```

**写法 B：带 ans 变量（`lo` 可以不可行，整体可能无解）**

```java
int lo = L, hi = R, ans = -1;
while (lo <= hi) {
    int mid = lo + (hi - lo) / 2;
    if (check(mid)) { ans = mid; lo = mid + 1; }   // 求最大可行
    else            { hi = mid - 1; }
}
return ans;                                       // -1 表示无解
```

**写法 C：last-true（求最大可行，注意上取整）**

```java
int lo = L, hi = R;              // 保证 check(lo) == true
while (lo < hi) {
    int mid = lo + (hi - lo + 1) / 2;    // ⚠️ 上取整，否则 lo=mid 死循环
    if (check(mid)) lo = mid;            // 可行 → 答案 ≥ mid，保留 mid
    else            hi = mid - 1;        // 不可行 → 答案 < mid
}
return lo;
```

**选择规则一句话**：
> 求"最小"用下取整 + `hi=mid`；求"最大"用上取整 + `lo=mid`。**取整方向和保留方向必须配套**，这是 1.3 那张表的直接应用。

### 2.5 实数二分

```java
double lo = L, hi = R;
for (int i = 0; i < 100; i++) {        // 固定迭代，不要用 while (hi - lo > eps)
    double mid = (lo + hi) / 2;
    if (check(mid)) hi = mid;          // 或 lo = mid，取决于单调方向
    else            lo = mid;
}
return (lo + hi) / 2;
```

**为什么用固定迭代而不是 eps？**

- `eps` 判断在浮点下可能永远不收敛（`hi - lo` 因为舍入误差卡在 `eps` 附近震荡）。
- 100 次迭代相当于区间缩小 `2^-100 ≈ 8e-31`，对任何 `double` 问题都足够。
- 迭代次数也可以按需算：`需要 log₂((R-L)/ε)` 次，再多给 10~20 次冗余。

**精度陷阱**：输出 `printf("%.6f")` 时，若答案是 `-1e-9`，会打印 `-0.000000`。需要 `if (Math.abs(ans) < 1e-9) ans = 0;` 或直接加 `1e-9` 后再取。

### 2.6 值域上界的估算（决定复杂度）

`O(n log C)` 里的 `log C` 取决于你怎么定 `hi`。定得离谱（比如 `hi = Integer.MAX_VALUE`）会白白多跑十几次 check。常用技巧：

- 用题目的**物理约束**定上界（`sum(piles)`、`max(nums)`）。
- 答案 = "每个元素最多取 `v`" 时，`hi = max(元素)`。
- 答案 = "总和 / 个数" 时，`hi = sum`。
- 实在不好估，用**倍增法**找上界：`hi = 1; while (!check(hi)) hi *= 2;` —— 只多花 `O(log C)` 次，且不用证明。

### 2.7 单调性失效的三种典型情况（反面教材）

**① check 里藏了非单调算子**

```java
// 错：想二分"最大 |a[i]-a[j]|"，但绝对值破坏了单调性
check(x) = 存在 i,j 使 |a[i]-a[j]| == x     // 既不单调也不连续，二分无意义
```

**② "最大化最小值"里，约束不是"越多越好"**

比如"选 k 个数使最小值最大"，如果约束是"必须恰好 k 个"且数据允许重复，则 `x` 增大不一定可行——需要先证明"`x` 可行 → `x-1` 可行"（这条通常成立，因为放宽阈值可以让原方案继续用）。

**③ check 用了全局可变状态且没重置**

```java
int cnt = 0;                    // 类成员，check 里累加
boolean check(int x) { ... cnt += ...; }   // ❌ 第二次调用被污染
```
正确做法：`check` 内部用局部变量，或者每次进入时重置。

### 2.8 二分答案 vs 直接 DP / 贪心

| 场景 | 直接解 | 二分答案 |
|---|---|---|
| 410 分割数组 | DP `O(n²m)` 或 `O(nm)` | 二分 + 贪心 `O(n log sum)` ✅ |
| 875 吃香蕉 | 没有好办法直接构造 | 二分 `O(n log max)` ✅ |
| 300 LIS | DP `O(n²)` | 二分 `O(n log n)` ✅（注意：这是"在 tails 上二分"，不是二分答案） |
| 求第 k 小 | 快速选择 `O(n)` 平均 | 二分 + 计数 `O(n log C)`（适用于值域小或不能随机访问） |

**结论**：当 `n` 大（`1e5`~`1e6`）且值域不大（`≤ 1e9`）时，`O(n log C)` 是甜点区；当值域巨大（`1e18`）但 `n` 小，要慎用（`log C` 到 60）。

### 3.1 LeetCode 704 · 二分查找（索引二分的"原点"）

**题意**：给定升序数组 `nums`（无重复）和目标值 `target`，存在返回下标，否则返回 `-1`。

**破题**：这是所有二分的定义式题目。它的价值不在"会做"，而在"能否把三种写法和不变量讲清楚"。

#### 解法一：闭区间 `[l, r]`（最符合直觉，推荐面试手写这版）

```java
public int search(int[] nums, int target) {
    int l = 0, r = nums.length - 1;        // 不变量：答案若存在，必在 [l, r] 内
    while (l <= r) {                       // 区间非空才继续
        int mid = l + (r - l) / 2;         // 下取整，防溢出
        if (nums[mid] == target) {
            return mid;
        } else if (nums[mid] < target) {
            l = mid + 1;                   // 排除 [l, mid]
        } else {
            r = mid - 1;                   // 排除 [mid, r]
        }
    }
    return -1;                             // 区间耗尽仍未命中
}
```

**为什么 `l <= r` 而不是 `l < r`？**
闭区间写法下 `l == r` 时区间还有 1 个元素没检查，必须进入循环。若写成 `l < r`，最后一个元素会被漏掉（这是 704 最高频的 WA 原因）。

**为什么 `mid ± 1`？**
因为 `nums[mid]` 已经被判定过、可以排除。留下它会浪费一次比较；更重要的是——留下的 `mid` 若成为新的边界，会让区间收缩变慢，配合下取整就可能死循环。

#### 解法二：左闭右开 `[l, r)`

```java
public int search(int[] nums, int target) {
    int l = 0, r = nums.length;            // r 是"越界位"，取不到
    while (l < r) {
        int mid = l + (r - l) / 2;
        if (nums[mid] < target)      l = mid + 1;    // 排除左半含 mid
        else if (nums[mid] > target) r = mid;        // 排除右半，mid 保留为潜在答案
        else                         return mid;
    }
    return -1;
}
```

注意这里的 `r = mid` 是**合法的**，因为 mid 已排除（`nums[mid] > target`），保留它不影响不变量；且 `[l, r)` 的 `r` 本身取不到，`r = mid` 表示"新的右开边界是 mid"，看起来"保留"其实"排除了"。**这正是开闭混用时最容易绕晕的地方。**

#### 解法三：只写 `lower_bound`，用一次比较判断命中

```java
public int search(int[] nums, int target) {
    int l = 0, r = nums.length;
    while (l < r) {
        int mid = l + (r - l) / 2;
        if (nums[mid] < target) l = mid + 1;
        else                    r = mid;
    }
    return (l < nums.length && nums[l] == target) ? l : -1;
}
```

这是**工程上最推荐**的写法：只有一个分支需要思考（`< target` 就往右），不会有"两个方向都写错"的风险。

#### 复杂度

| 指标 | 值 | 说明 |
|---|---|---|
| 时间 | `O(log n)` | 比较次数 `⌈log₂(n+1)⌉`；`n=10⁹` 时 30 次 |
| 空间 | `O(1)` | 迭代；递归版 `O(log n)` |
| 最好情况 | `O(1)` | 第一次就命中 |

#### 必测边界用例

```
[]                     → -1
[5],  target=5         → 0
[5],  target=1         → -1
[1,3,5,7], t=1         → 0      （左端点）
[1,3,5,7], t=7         → 3      （右端点）
[1,3,5,7], t=4         → -1     （插入缝隙）
[1,3,5,7], t=0/t=8     → -1     （越界）
[1,1,1,1], t=1         → 任一   （题设无重复，但变体有）
```

#### 面试追问链（704 的真实价值在这里）

| 追问 | 正解 |
|---|---|
| 数组有重复元素，要返回**第一个** target？ | T2 `lower_bound`：`a[mid] < x → l=mid+1; else r=mid` |
| 返回**最后一个**？ | T3 `upper_bound(x) - 1` |
| 不存在时返回**插入位置**？ | 直接 `return lower_bound(x)`（对应 35 题） |
| 数组无界（长度未知，只能 `get(i)`，越界抛异常）？ | 倍增确定上界 `hi`，再二分（对应 702 题 / 面试口头题） |
| 数组在磁盘上、长度 10 亿？ | 二分仍 `O(log n)` 但每次 mid 是一次随机 IO；实际用 B+ 树，扇出 300、3 层覆盖 2700 万，4 层 81 亿 |
| 数组是链表？ | 找 mid 要 `O(n/2)` 走指针，总 `O(n log n)`；用**跳表**才能 `O(log n)` |
| 只能比较"大于/小于"不能相等？ | 等价于 `lower_bound` 的判定式，仍可二分 |
| 要求返回所有 target 的范围？ | 34 题：两次二分 |

| 374 猜数字大小 | API 代替数组 | `guess(mid)` 三态 |
| 278 第一个错误版本 | 布尔单调 | `isBadVersion(mid)` |
| 367 有效的完全平方数 | 精确命中 | `mid*mid == num` |
| 852 山脉数组峰顶 | 单峰 | `nums[mid] < nums[mid+1] → 右` |

### 3.2 LeetCode 33 · 搜索旋转排序数组（半有序二分的范式）

**题意**：原本升序的**互不相同**数组在某个未知下标处被旋转（如 `[0,1,2,4,5,6,7]` → `[4,5,6,7,0,1,2]`），在 `O(log n)` 内找 `target`。

#### 破题：一句话

> **旋转数组任意切一刀，两半中至少有一半是完全有序的。**

先在有序的那一半里判断 `target` 是否落在区间内：
- **在** → 去那一半找；
- **不在** → 答案必在另一半。

于是每步仍然排除一半 → `O(log n)` 成立。

#### 图示推导

```
原始升序：   [ 0  1  2  4  5  6  7 ]
旋转 3 次：  [ 4  5  6  7 | 0  1  2 ]
              └─── 大段 ──┘└─ 小段 ─┘
下标：         0  1  2  3   4  5  6
                          ↑ pivot（最小值位置）

任取 mid，只有两种形态：

形态 A：mid 在"大段"内          形态 B：mid 在"小段"内
  l            mid        r        l        mid        r
  [4  5  6  7 | 0  1  2]           [4  5  6  7 | 0  1  2]
   └─有序段─┘  └──乱序──┘           └──乱序──┘ └─有序段─┘
  nums[l] <= nums[mid] 成立          nums[l] >  nums[mid] 成立
  → 左半 [l,mid] 完全有序            → 右半 [mid,r] 完全有序
```

**判定的充要性证明**：
- 若 `nums[l] <= nums[mid]`：假设 `[l, mid]` 跨过了 pivot，则 `nums[l]` 属于"大段"、`nums[mid]` 属于"小段"，必有 `nums[l] > nums[mid]`，与前提矛盾。故 `[l, mid]` 不跨 pivot，**完全有序**。∎
- 反之 `nums[l] > nums[mid]` 说明跨了 pivot，那么 `[mid, r]` 一定不跨 pivot（pivot 只在 `(l, mid]` 内），**完全有序**。∎

#### 代码

```java
public int search(int[] nums, int target) {
    int l = 0, r = nums.length - 1;
    while (l <= r) {
        int mid = l + (r - l) / 2;
        if (nums[mid] == target) return mid;

        if (nums[l] <= nums[mid]) {                    // 左半 [l, mid] 有序
            // target 落在有序段内 → 收缩到左半
            if (nums[l] <= target && target < nums[mid]) {
                r = mid - 1;
            } else {
                l = mid + 1;
            }
        } else {                                       // 右半 [mid, r] 有序
            if (nums[mid] < target && target <= nums[r]) {
                l = mid + 1;
            } else {
                r = mid - 1;
            }
        }
    }
    return -1;
}
```

**四个边界的写法必须精确**（这里错一个符号就 WA）：

| 分支 | 条件 | 原因 |
|---|---|---|
| 左半有序 | `nums[l] <= nums[mid]` | `<=` 不能改 `<`：`l==mid` 时（区间长度 1、2）左半只有一个元素，也是"有序"的 |
| target 在左半 | `nums[l] <= target && target < nums[mid]` | 左端点可取等（可能就是 `l`），`mid` 已判过不等于，故 `<` |
| target 在右半 | `nums[mid] < target && target <= nums[r]` | 右端点可取等（可能就是 `r`），`mid` 已判过，故 `>` |

> **记忆法**：两侧各有一个"闭端点"（`nums[l]` 和 `nums[r]`），用 `<=`；`nums[mid]` 已经比较过相等，用严格不等。

#### 复杂度

`O(log n)` 时间、`O(1)` 空间。每次循环只做常数次比较。

#### 解法二：先找 pivot（旋转点），再两段二分

```java
public int search(int[] nums, int target) {
    int n = nums.length;
    // 第一步：二分找最小值下标（即 pivot）
    int l = 0, r = n - 1;
    while (l < r) {
        int mid = l + (r - l) / 2;
        if (nums[mid] > nums[r]) l = mid + 1;   // 最小值在右半（不含 mid）
        else                     r = mid;       // 最小值在左半（含 mid）
    }
    int pivot = l;

    // 第二步：判断 target 在哪一段，在该段上做标准二分
    // 第一段 [0, pivot-1] 的值域是 [nums[0], nums[pivot-1]]（注意上界是 pivot-1，不是 pivot！）
    if (pivot == 0) {                                        // 未旋转，整体有序
        return bs(nums, 0, n - 1, target);
    }
    if (target >= nums[0] && target <= nums[pivot - 1]) {
        return bs(nums, 0, pivot - 1, target);
    }
    return bs(nums, pivot, n - 1, target);
}

private int bs(int[] a, int l, int r, int t) {
    while (l <= r) {
        int mid = l + (r - l) / 2;
        if (a[mid] == t) return mid;
        if (a[mid] < t) l = mid + 1; else r = mid - 1;
    }
    return -1;
}
```

**有一个真实的坑，务必注意**：第一段的值域上界是 `nums[pivot - 1]`，**不是 `nums[pivot]`**。因为 `nums[pivot]` 是**最小值**，恒有 `nums[pivot] < nums[0]`，写成 `target < nums[pivot]` 会让条件恒为 false，导致第一段的元素（如 `[1,2,3,4,5,6,7,0]` 里的 `2`）全部找不到。这个错误很隐蔽——因为它逻辑上"看起来"是在判断 `[nums[0], nums[pivot])` 这个区间，但那段区间的右端其实是 `pivot-1`。

**两种解法的对比**（面试可以主动说出来，是很强的加分项）：

| 维度 | 一次二分（判定有序段） | 两次二分（先找 pivot） |
|---|---|---|
| 比较次数 | 约 `log n` 次，每次 3~4 个判断 | 约 `2 log n` 次，每次 1 个判断 |
| 常数 | 稍大（分支复杂） | 稍小（逻辑简单） |
| 可读性 | 一般 | **更好**（拆成两个独立子问题），但"段值域判定"容易写错 |
| 扩展性 | 有重复元素时难处理 | 同样难，但可复用 `findMin` |
| 面试推荐 | ✅ 主流 | ✅ 可作为"更工程化"的备选答案 |

#### 高频追问

**Q：如果数组有重复元素（第 81 题）怎么办？**

当 `nums[l] == nums[mid] == nums[r]` 时，**无法判断**哪一半有序（因为"大段"末尾和"小段"开头可能同值）。此时只能 `l++`、`r--` 逐个跳过：

```java
public boolean search(int[] nums, int target) {
    int l = 0, r = nums.length - 1;
    while (l <= r) {
        int mid = l + (r - l) / 2;
        if (nums[mid] == target) return true;
        if (nums[l] == nums[mid] && nums[mid] == nums[r]) {   // 三值相同，无法判定
            l++; r--;
        } else if (nums[l] <= nums[mid]) {                    // 左半有序
            if (nums[l] <= target && target < nums[mid]) r = mid - 1;
            else l = mid + 1;
        } else {                                              // 右半有序
            if (nums[mid] < target && target <= nums[r]) l = mid + 1;
            else r = mid - 1;
        }
    }
    return false;
}
```

**最坏复杂度退化到 `O(n)`**：反例 `[1,1,1,1,1,1,3,1]`，`target=3`，每次都要 `l++/r--` 一个个跳。这是"信息不足 → 必须逐个检查"的必然结果，**不是算法写错了**。面试官问"能不能保证 O(log n)"，正确答案是"不能，因为有重复元素时信息论上就不够"。

**Q：为什么不能简单地"先找 target 的位置再判断"？** 因为"位置"和"值"的单调关系被旋转破坏了，只有"段内"才有单调性。

**Q：如果旋转了 0 次（完全有序）？** 代码依然正确：`nums[l] <= nums[mid]` 恒成立，退化为标准二分。

**Q：如果允许 `O(n)` 呢？** 直接线性扫描，但面试要的就是 `O(log n)`，别退让。

#### 相关题链

| 题号 | 差异 |

| 153 寻找旋转排序数组最小值 | 无重复，`O(log n)` |
| 154 寻找最小值 II | 有重复，最坏 `O(n)` |
| 81 搜索旋转数组 II | 有重复，最坏 `O(n)` |
| 33 | 无重复，`O(log n)` |

**153 模板（记住 `nums[mid] > nums[r]` 这个判定）**：

```java
public int findMin(int[] nums) {
    int l = 0, r = nums.length - 1;
    while (l < r) {
        int mid = l + (r - l) / 2;
        if (nums[mid] > nums[r]) l = mid + 1;   // 最小值严格在 mid 右侧
        else                     r = mid;       // nums[mid] 可能就是最小值
    }
    return nums[l];
}
```
为什么和 `nums[r]` 比而不是和 `nums[l]` 比？因为 `nums[r]` 一定在"小段"或 pivot 上，是**最可靠的右锚点**；而 `nums[l]` 在 `[l,mid]` 有序时无法判断 pivot 在哪。这是一个很值得在面试里讲出来的细节。

### 3.3 LeetCode 875 · 爱吃香蕉的珂珂（二分答案的最小可行范式）

**题意**：`piles[i]` 根香蕉，珂珂每小时选一堆、以速度 `k` 根/小时吃，若这堆不足 `k` 根则吃完这堆后**这一小时不再吃别的堆**（即每小时最多吃一堆，耗时 `ceil(piles[i] / k)` 小时）。求在 `h` 小时内吃完的最小 `k`。

#### 破题：为什么这题必须二分答案？

先问自己：能不能直接算出最优 `k`？

- 答案与"每一堆的余数分布"耦合：`ceil(p/k)` 是阶梯函数，`k` 增大时总时间不是线性下降，而是**阶梯式下降**。
- 没有闭式解，也没有单调的"每堆除一下取和"能反解出 `k`。

但只要给我一个 `k`，我 `O(n)` 就能算出总时间 → **典型的"判定容易、构造困难"** → 二分答案。

#### 第 2 步：单调性证明（面试必须口述）

设 `T(k) = Σ ceil(piles[i] / k)`。

> 对任意 `k ≥ 1`，有 `T(k) ≥ T(k+1)`。因为对每个 `i`，`ceil(p/k)` 是 `k` 的非增函数（`k` 变大，每堆耗时只会变短或不变）。有限个非增函数相加仍非增。∎

所以 `check(k) := T(k) ≤ h` 是**单调的**（`F...F T...T`）→ 求**第一个 true** → 用 T4（下取整 + `hi = mid`）。

#### 第 1、3、4 步：定答案、写 check、定边界

| 要素 | 值 | 说明 |
|---|---|---|
| 答案 `k` | 每小时吃几根 | 整数 |
| 下界 `lo` | `1` | 速度至少 1 根/小时（不能为 0，否则除零） |
| 上界 `hi` | `max(piles)` | 再快也没意义：超过最大堆后，每堆都是 1 小时，总时间 = `n` |
| `check(k)` | `Σ ceil(p/k) ≤ h` | `O(n)`，可提前 `break` |

**上界为什么是 `max(piles)` 而不是 `sum(piles)`？** 这是本题最容易被忽略的优化点：当 `k ≥ max(piles)` 时，`T(k) == n` 恒定不再变化，答案不可能超过 `max`。用 `max` 把 `log C` 从 `log(sum)`（约 40）压到 `log(max)`（约 30），而且逻辑更清晰。

#### 代码

```java
public int minEatingSpeed(int[] piles, int h) {
    int lo = 1;
    int hi = 0;
    for (int p : piles) hi = Math.max(hi, p);

    while (lo < hi) {
        int mid = lo + (hi - lo) / 2;
        if (canFinish(piles, mid, h)) {
            hi = mid;              // mid 可行 → 答案 ≤ mid（保留 mid）
        } else {
            lo = mid + 1;          // mid 不可行 → 答案 > mid
        }
    }
    return lo;
}

private boolean canFinish(int[] piles, int k, int h) {
    long hours = 0;                          // ⚠️ 必须 long
    for (int p : piles) {
        hours += (p + k - 1) / k;            // 向上取整，等价于 ceil(p / k)
        if (hours > h) return false;         // 早退，避免溢出与无效计算
    }
    return true;
}
```

#### 三个必须讲清楚的细节

**① `(p + k - 1) / k` 是向上取整的标准写法**

```java
ceil(p / k) == (p + k - 1) / k     // k > 0 且 p >= 0 时成立
```
证明：设 `p = qk + r, 0 ≤ r < k`。若 `r = 0`，`(qk + k - 1)/k = q`（因为 `qk + k - 1 < qk + k`），`ceil = q` ✓。若 `r > 0`，`p + k - 1 = qk + r + k - 1 ≥ (q+1)k` 且 `< (q+2)k`，故商为 `q+1`，`ceil = q+1` ✓。∎

**② 溢出分析（面试高频追问）**

- `piles.length ≤ 10⁴`，`piles[i] ≤ 10⁹`。
- 最坏 `hours = 10⁴ × 10⁹ = 10¹³`，**远超 `int` 上限 `2.1×10⁹`** → `hours` 必须是 `long`。
- `p + k - 1`：`p ≤ 10⁹`、`k ≤ 10⁹`，和约 `2×10⁹`，勉强在 `int` 内但已逼近上限，**用 `long` 更安全**（若题目放大到 `10⁹` 上限就可能爆）。
- 有了 `hours > h` 早退，即便不溢出也能省掉大部分计算。

**③ 为什么 `hi = max(piles)` 时 `check(hi)` 一定为 true？**

`T(max) = n`（每堆 1 小时），题设 `h ≥ piles.length`，所以 `n ≤ h` 恒成立 → `hi` 天然可行 → 可以用 T4（不需要额外判断无解）。

#### 复杂度

`O(n log maxP)`，其中 `maxP ≤ 10⁹` → 约 30 次扫描；`n = 10⁴` → 约 `3×10⁵` 次操作。空间 `O(1)`。

#### 追问

| 追问 | 回答要点 |
|---|---|
| 如果每小时可以吃**多堆**（不限制"一小时一堆"）？ | 变成 `ceil(sum/k) ≤ h`，答案 `= ceil(sum/h)`，无需二分 |
| 如果允许"这小时吃不完可以留到下一小时接着吃"？ | 同上，退化为总量除法 |
| 如果要求"必须整堆吃完才能换堆"（题目已隐含）？ | 就是本题的 `ceil` 逻辑 |
| 如果 `h < n`？ | 无解，返回 `-1`（本题约束排除了这种情况） |
| 能不能用数学直接求？ | 不能，`T(k)` 是阶梯函数，没有解析反函数 |

### 3.4 LeetCode 1011 · 在 D 天内送达包裹的能力（贪心 check 的范式）

**题意**：包裹必须**按给定顺序**装船，每天最多一趟，船载重为 `cap`，求在 `D` 天内运完的**最小** `cap`。

#### 破题

与 875 同构：

- 答案 `cap` 是整数 → 二分答案；
- `check(cap) = "按顺序装、每天装满能装的最大量，所需天数 ≤ D"`；
- 单调性：`cap` 越大 → 天数越少（非增）→ 求**第一个可行**。

**但与 875 有一个关键差别：下界不是 1，而是 `max(w)`。**
因为若 `cap < max(w)`，那一件包裹永远装不上——`check` 会返回 false，而 `lo` 若从 1 开始，二分会"穿过"一大片不可行区，浪费次数；更糟的是如果整个值域 `[1, max)` 全不可行且你没设对 `hi`，会返回错误结果。**`lo` 取下界"物理可行"值，是二分答案的基本功。**

#### 代码

```java
public int shipWithinDays(int[] weights, int days) {
    int lo = 0, hi = 0;
    for (int w : weights) {
        lo = Math.max(lo, w);      // 下界：必须能装下最重的一件
        hi += w;                   // 上界：一天全装完，必然可行（days >= 1）
    }

    while (lo < hi) {
        int mid = lo + (hi - lo) / 2;
        if (canShip(weights, mid, days)) hi = mid;
        else                             lo = mid + 1;
    }
    return lo;
}

private boolean canShip(int[] w, int cap, int days) {
    int need = 1, cur = 0;                 // 至少需要一天
    for (int x : w) {
        if (cur + x > cap) {               // 当前船装不下了
            need++;                        // 换新的一天
            cur = x;                       // 这件放到新船上
            if (need > days) return false; // 早退
        } else {
            cur += x;                      // 继续装
        }
    }
    return true;
}
```

#### 贪心 check 的正确性证明（面试可能让你证）

**命题**：给定 `cap`，"能装下的最少天数"可以由"每船尽量装满、保持顺序"的贪心求得。

**证明（交换论证）**：设最优方案第 1 天装了前 `j` 件，贪心装了前 `g` 件。由贪心定义 `g ≥ j`（贪心装到装不下为止）。把最优方案第 1 天改成前 `g` 件后，第 2 天起剩下的包裹变少（后缀更短），所需天数不会增加。归纳可得贪心天数 ≤ 最优天数；又贪心是合法方案，故相等。∎

**这个证明的关键前提是"顺序不可打乱"**——所以：

> **面试延伸（高价值）**：如果允许包裹**任意顺序**装船，问题就变成 **Bin Packing（装箱问题）**，是 **NP-hard**，不存在多项式最优解。正是"必须按顺序"这一条约束，让贪心成立、让二分答案可行。**这就是"题目为什么可解"的底层原因。**

#### 与 875 的结构对照（背这张表，同类题秒杀）

| 维度 | 875 珂珂 | 1011 运包裹 |
|---|---|---|
| 答案变量 | 速度 `k`（根/小时） | 载重 `cap` |
| 下界 `lo` | `1`（速度不能为 0） | `max(w)`（必须装得下最重的） |
| 上界 `hi` | `max(piles)`（每堆 1 小时） | `sum(w)`（一天全装） |
| check 的核心 | `Σ ceil(p/k) ≤ h` | 贪心数"天数 ≤ D" |
| check 复杂度 | `O(n)` | `O(n)` |
| 计数方式 | 直接求和 | 累加 + 超限换桶 |
| 总复杂度 | `O(n log max)` | `O(n log sum)` |
| 隐含约束 | 每小时只能吃一堆 | 必须按顺序装 |

#### 易错清单

1. `need` 初值必须是 `1` 而不是 `0`（非空数组至少要一天）。
2. `cur = x` 而不是 `cur = 0`（换船后当前包裹已经在船上）。
3. `hi = sum(w)`：若 `D == 1`，一个 `int` 求和可能溢出（`n=5×10⁴`、`w=10⁴` → `5×10⁸`，还在 `int` 内；但若题目放大就要 `long`）。
4. 早退条件 `need > days` 放在 `need++` 之后，否则会漏判。
5. `lo = max(w)`：写 `lo = 0` 或 `lo = 1` 会在某些用例上返回不可行的答案（当 `mid` 落在不可行区且 `check` 全 false 时，`lo` 会被推到 `mid+1`，虽然最终也会收敛，但 `hi` 的可行性前提被破坏）。

### 3.5 LeetCode 162 · 寻找峰值（"无序也能二分"的最佳例证）

**题意**：数组相邻元素互不相等，`nums[-1] = nums[n] = -∞`，返回**任意一个**峰值（严格大于左右邻居）的下标，要求 `O(log n)`。

#### 破题：不比较"大小"，比较"斜率"

标准二分比的是 `nums[mid]` 与 `target`。这里没有 `target`，比的是 **`nums[mid]` 与 `nums[mid+1]` 的方向**：

- `nums[mid] < nums[mid+1]` → 处于**上坡** → 峰值一定在 `mid` **右侧**（含 `mid+1`）
- `nums[mid] >= nums[mid+1]` → 处于**下坡或平台起点** → 峰值一定在 `mid` **左侧**（含 `mid`）

```
nums:  1   2   3   4   3   2   1
                   ↑ 峰值
       ─────上坡────┘└───下坡───

若 mid 落在上坡：  [ ... mid ↗ mid+1 ... ]  → 右侧必有峰（走到下降处即峰）
若 mid 落在下坡：  [ ... mid ↘ mid+1 ... ]  → 左侧必有峰（回走到上升处即峰）
```

#### 正确性证明（"为什么上坡右侧必有峰"）

**命题**：若 `nums[mid] < nums[mid+1]`，则区间 `[mid+1, n-1]` 内必存在峰值。

**证明**：考察 `nums[mid+1], nums[mid+2], …, nums[n-1]`。把 `nums[n]` 视作 `-∞`。
设第一个满足 `nums[k] > nums[k+1]` 的下标为 `k`（其中 `k ≥ mid+1`，`nums[n] = -∞` 保证这样的 `k` 必然存在）。
则 `nums[k]` 大于右邻居 `nums[k+1]`；又 `k` 是第一个下降点，说明 `nums[k-1] < nums[k]`（若 `k == mid+1`，则 `nums[mid] < nums[k]` 由前提给出）。故 `nums[k]` 是峰值。∎

对称地，"下坡左侧必有峰"同理（用 `nums[-1] = -∞`）。**两个方向都能保证不丢失峰值，因此每一步都能安全排除一半。**

#### 代码（8 行，但每个符号都有讲究）

```java
public int findPeakElement(int[] nums) {
    int l = 0, r = nums.length - 1;
    while (l < r) {
        int mid = l + (r - l) / 2;
        if (nums[mid] < nums[mid + 1]) {
            l = mid + 1;        // 上坡：峰值在右侧，mid 不可能是峰
        } else {
            r = mid;            // 下坡：峰值在左侧，mid 可能就是峰（必须保留）
        }
    }
    return l;                   // 收敛到唯一候选
}
```

**三个关键细节**：

| 细节 | 为什么 |
|---|---|
| `while (l < r)` 而非 `l <= r` | 收敛到单点即停止，返回 `l` 即可；用 `<=` 会在 `l == r` 时多算一次且 `mid+1` 越界 |
| `nums[mid + 1]` 不会越界 | 因为 `l < r` 保证 `mid = l + (r-l)/2 ≤ r - 1`，故 `mid + 1 ≤ r ≤ n-1` ✅ |
| `r = mid` 而不是 `mid - 1` | `nums[mid] >= nums[mid+1]` 时 `mid` 本身可能就是峰值，排除它会丢答案 |
| 不判断 `nums[mid-1]` | 只需要一个方向就够排除一半；判断两侧反而会引入"两侧都下坡"时不收敛的问题 |

#### 复杂度

`O(log n)` 时间、`O(1)` 空间。**注意：数组本身完全无序，这是"二分不依赖有序"的强证据。**

#### 追问链

**Q：为什么这题能二分，普通无序数组不能？**
因为这里二分需要的不是"全局有序"，而是"**局部斜率能排除一半**"的单调结构。162 的 `nums[i] < nums[i+1]` 构成一个"上坡/下坡"的二值结构，且边界是 `-∞`，保证沿着上坡走一定会遇到下降。

**Q：如果有平台（相邻相等）？**
162 题设保证互不相等。若有平台，`nums[mid] == nums[mid+1]` 时无法判定，需要先跳过平台（或题目改为"严格大于"并要求处理重复）。

**Q：找谷值（局部最小）？**

```java
while (l < r) {
    int mid = l + (r - l) / 2;
    if (nums[mid] > nums[mid + 1]) l = mid + 1;   // 下坡 → 谷在右
    else                           r = mid;        // 上坡 → 谷在左
}
return l;
```

**Q：如果要求返回**所有**峰值？**
退化为 `O(n)` 线性扫描（一个数组可能有 `O(n)` 个峰值，输出本身就 `O(n)`）。

**Q：二维版本（1901 寻找峰值 II）？**
二分**列**，在每列找最大值所在行 `r`，再看 `nums[r][mid]` 与 `nums[r][mid+1]`：

```java
public int[] findPeakGrid(int[][] mat) {
    int m = mat.length, n = mat[0].length;
    int l = 0, r = n - 1;
    while (l < r) {
        int mid = l + (r - l) / 2;
        int row = 0;
        for (int i = 0; i < m; i++) if (mat[i][mid] > mat[row][mid]) row = i;  // 该列最大值行
        if (mat[row][mid] < mat[row][mid + 1]) l = mid + 1;   // 右邻更大 → 峰在右
        else                                   r = mid;        // 否则峰在左
    }
    int row = 0;
    for (int i = 0; i < m; i++) if (mat[i][l] > mat[row][l]) row = i;
    return new int[]{row, l};
}
```
复杂度 `O(m log n)`（`n` 列二分 × 每列 `O(m)` 找最大）。正确性依赖"该列最大值所在行，若右邻更大则右侧必有峰"——和 162 的一维证明同构（把一维的"邻居"换成"列最大值"，相邻列最大值构成的序列仍是"上坡/下坡"结构）。

### 3.6 LeetCode 34 · 在排序数组中查找元素的第一个和最后一个位置（双边界二分）

**题意**：升序数组（**有重复**）中找 `target` 的起始和结束下标，不存在返回 `[-1, -1]`，要求 `O(log n)`。

#### 破题：这是 `lower_bound` / `upper_bound` 的标准考场

| 边界 | 定义 | 判定式 |
|---|---|---|
| 左边界 `L` | 第一个 `>= target` 的位置 | `a[mid] < target → l = mid+1`，否则 `r = mid` |
| 右边界 `R` | 第一个 `> target` 的位置 **减 1** | `a[mid] <= target → l = mid+1`，否则 `r = mid` |

**为什么"第一个 `> target` 减 1"就是最后一个 `target`？**
因为 `target` 的所有出现是连续的 `[L, R]`，`R+1` 恰好是第一个严格大于 `target` 的位置。∎

#### 代码（注意 `target+1` 的溢出陷阱）

```java
public int[] searchRange(int[] nums, int target) {
    int n = nums.length;
    int left = lowerBound(nums, target);
    if (left == n || nums[left] != target) {       // 不存在（注意顺序：先判越界，再取值）
        return new int[]{-1, -1};
    }
    int right = upperBound(nums, target) - 1;      // 不要写成 lowerBound(target + 1)！
    return new int[]{left, right};
}

/** 第一个 >= x 的下标，范围 [0, n] */
private int lowerBound(int[] a, int x) {
    int l = 0, r = a.length;
    while (l < r) {
        int mid = l + (r - l) / 2;
        if (a[mid] < x) l = mid + 1;
        else            r = mid;
    }
    return l;
}

/** 第一个 > x 的下标，范围 [0, n] */
private int upperBound(int[] a, int x) {
    int l = 0, r = a.length;
    while (l < r) {
        int mid = l + (r - l) / 2;
        if (a[mid] <= x) l = mid + 1;
        else             r = mid;
    }
    return l;
}
```

#### ⚠️ 为什么不能用 `lowerBound(target + 1)`？

```java
int right = lowerBound(nums, target + 1) - 1;   // ❌ 若 target == Integer.MAX_VALUE
```
`target + 1` 会**溢出成 `Integer.MIN_VALUE`**，`lowerBound` 直接返回 0，结果完全错。
这是本题最隐蔽的坑（也是 LeetCode 官方题解都特意提醒的点）。正确做法有两个：

1. 直接实现 `upperBound`（推荐，物理意义清晰）；
2. 用 `long` 传参：`lowerBound(nums, (long) target + 1)`。

**这道题同时是"防溢出"和"防边界"的双重考点**，很适合作为面试的第一题。

#### 为什么"先找到 target 再向两边扩展"不合格？

```java
// ❌ 最坏 O(n)
int idx = binarySearch(target);
int l = idx, r = idx;
while (l > 0 && nums[l-1] == target) l--;
while (r < n-1 && nums[r+1] == target) r++;
```
当数组全是 `target`（如 `[8,8,8,...,8]`）时，两边扩展要走 `O(n)` 步，整体退化为 `O(n)`。
**面试官几乎必问："你的复杂度真的是 O(log n) 吗？"** 这时必须回答"用两次二分分别定左右边界"。

#### 复杂度

`O(log n)` 时间（两次二分，`2⌈log₂(n+1)⌉` 次比较）、`O(1)` 空间。

#### 追问链

| 追问 | 回答 |
|---|---|
| `target` 出现次数？ | `upperBound(t) - lowerBound(t)` |
| 第一个 `>= t` 的数？ | `lowerBound(t)`，注意可能越界返回 `n` |
| 最后一个 `< t` 的数？ | `lowerBound(t) - 1`，可能为 `-1` |
| 第一个 `> t` 的数？ | `upperBound(t)` |
| 只有一个元素？ | 逻辑天然覆盖（`l=0, r=1` 一次循环即收敛） |
| 数组为空？ | `lowerBound` 返回 0，`left == n == 0` → `[-1,-1]` ✅ |
| 能不能只写一个函数？ | 可以，用 `cmp` 参数化：`lowerBound(x, strict)`，`strict=true` 时判定 `<=` |
| 数据量 10 亿在磁盘？ | 每次 mid 是一次随机页读取，`log₂(10⁹)=30` 次 IO；实际用 B+ 树降到 3~4 次 |

**参数化统一写法（工程最佳实践）**：

```java
/** strict=false → 第一个 >= x；strict=true → 第一个 > x */
private int bound(int[] a, int x, boolean strict) {
    int l = 0, r = a.length;
    while (l < r) {
        int mid = l + (r - l) / 2;
        boolean goRight = strict ? (a[mid] <= x) : (a[mid] < x);
        if (goRight) l = mid + 1; else r = mid;
    }
    return l;
}
```

## 4. 知识点延伸

### 4.1 三分查找（求单峰极值）

二分找"边界"，三分找"极值"。前提是函数在区间上**严格单峰**（先增后减，或先减后增）。

```java
double l = L, r = R;
for (int i = 0; i < 100; i++) {
    double m1 = l + (r - l) / 3;
    double m2 = r - (r - l) / 3;
    if (f(m1) < f(m2)) l = m1;      // 极值在 [m1, r]
    else               r = m2;      // 极值在 [l, m2]
}
return f((l + r) / 2);
```

**三分 vs 二分的选择**：

| 场景 | 用什么 | 原因 |
|---|---|---|
| 求第一个可行（布尔单调） | 二分 | 谓词只有 true/false，三分无从比较 |
| 求单峰函数的极值 | 三分 | 需要比较两点函数值判断"哪侧有峰" |
| 离散单峰（数组） | 二分（162 式） | 用 `nums[mid]` vs `nums[mid+1]` 判断斜率，比三分少一次求值 |
| 可行性单调的最优化 | 二分答案 | 三分只能求函数极值，不能处理"约束可行域" |

**重要区别**：三分要求函数**可求值**（能算 `f(x)`），二分答案只要求**可判定**（能算 `check(x)` 的真假）。后者弱得多，所以二分答案的适用范围广得多。

### 4.2 二分 vs 快速选择 vs 堆（求第 k 大）

| 方案 | 时间 | 空间 | 前提 | 适用 |
|---|---|---|---|---|
| 排序后取 | `O(n log n)` | `O(1)`~`O(n)` | 无 | 一次性、要全部有序 |
| 小顶堆维护 k 个 | `O(n log k)` | `O(k)` | 无 | 数据流 / k 很小 |
| 快速选择（partition） | `O(n)` 平均，`O(n²)` 最坏 | `O(1)` | 可原地修改 | 静态数组，允许打乱 |
| **二分答案 + 计数** | `O(n log C)` | `O(1)` | 值域小、能 `O(n)` 计数 | 值域有界（如分数、距离） |
| 两个有序数组第 k 小 | `O(log min(m,n))` | `O(1)` | 两数组有序 | 中位数题（第 4 题） |

**为什么"求第 k 小"有时必须用二分答案？**
因为快速选择要**随机访问并交换元素**。如果元素不能移动（比如是矩阵中的数对距离、是两个数组的比值），就只能"数一数 ≤ x 的有多少个"，这时二分答案是唯一选择 → 719、786 都是这个套路。

### 4.3 二分 + LIS：`O(n log n)` 的经典改造

LIS 的 DP 是 `O(n²)`。改成"在 tails 数组上二分"，降到 `O(n log n)`。

```java
public int lengthOfLIS(int[] nums) {
    int[] tails = new int[nums.length];   // tails[L] = 所有长度 L+1 的递增子序列中，末尾元素的最小值
    int len = 0;
    for (int x : nums) {
        int l = 0, r = len;               // 在 tails[0, len) 中找 lower_bound(x)
        while (l < r) {
            int mid = l + (r - l) / 2;
            if (tails[mid] < x) l = mid + 1;
            else                r = mid;
        }
        tails[l] = x;                     // 替换（或追加）
        if (l == len) len++;              // 扩展到新长度
    }
    return len;
}
```

**为什么正确（这是最容易讲不清的地方）**：

1. `tails` 数组**天然严格递增**（归纳：每次把 `tails[l]` 降到 `x`，而 `tails[l-1] < x`、`tails[l+1] > x` 保持不变）。
2. `len` 是"当前能构成的最长递增子序列长度"，最小值 `tails[L]` 越小，后续接元素的潜力越大 → **贪心保持每个长度上的最小末尾**。
3. 对 `x` 找 `lower_bound`：`x` 能接在长度 `l` 的序列后面形成长度 `l+1`（因为 `tails[l-1] < x`），所以把 `tails[l]` 更新为 `x` 是"同长度下更优的末尾"。

> 注意：**这不是二分答案**，是"维护一个有序数组并在其上二分"。很多资料混为一谈，面试时可以主动澄清，显得理解更深。

### 4.4 结构内二分：权值树状数组上找第 k 小

二分不只发生在数组上，也发生在**树结构**上。经典场景：动态插入 + 查询第 k 小。

```java
// tree 是权值树状数组（tree[i] 维护区间和），下标 1..n 对应值域
int kth(int k) {
    int pos = 0, sum = 0;
    for (int i = LOG; i >= 0; i--) {         // LOG = 最高位，如 20（覆盖 1e6）
        int nxt = pos + (1 << i);
        if (nxt <= n && sum + tree[nxt] < k) {   // 跳过：左子树不够 k 个
            pos = nxt;
            sum += tree[nxt];
        }
    }
    return pos + 1;
}
```

**原理**：树状数组的 `tree[i]` 恰好维护 `(i - lowbit(i), i]` 这一段的和。按二进制从高位往低位"拼"位置，等价于在**树状数组的隐式二叉结构上二分**——这是"二分 + 数据结构"的典型结合，也是字节/阿里 Hard 题的常见考点（动态中位数、带修第 k 小）。

**注意**：每次 `kth` 是 `O(log n)`，比"二分答案 + 查询 `O(log n)`"的 `O(log²n)` 更优。**这说明"二分的位置选得好，能把 log² 压成 log"。**

### 4.5 二分 + DP / 双指针 / 前缀和

| 组合 | 形态 | 代表题 |
|---|---|---|
| 二分 + **贪心** | check 用贪心装桶/匹配 | 1011、410、1482、1552 |
| 二分 + **双指针计数** | check 数"差值 ≤ x 的对数" | 719、786 |
| 二分 + **前缀和** | check 转成"是否存在长度 ≥ k 且和 ≥ 0 的段" | 644（最大平均子段和） |
| 二分 + **DP** | check 是"能不能用 m 段覆盖" | 410 的 DP 版、813（最大平均值分组） |
| 二分 + **最短路/并查集** | check 是"只走 ≤ x 的边能否连通" | 778、1631（最小体力消耗路径） |
| 二分 + **拓扑/二分图** | check 是"能不能 2-染色" | 886 |

**"二分 + 图"是个常被忽略的套路**：把"最大边权的最小值"这类问题（如"最小化路径上的最大边"）转化成"只保留权值 ≤ x 的边，问 s 到 t 是否连通"，`check` 用 BFS/DFS/并查集，整体 `O((n+m) log C)`。

### 4.6 常数优化：为什么真实系统不用二分

二分是 `O(log n)` 的比较次数最优解，但**在实际硬件上并不最快**，原因有三：

**① 缓存不友好（cache miss 主导）**
二分每次 `mid` 跳跃访问，几乎每次都是 cache miss（一次内存访问 ≈ 100ns，一次 cache 命中 ≈ 1ns）。`n = 10⁹` 时 30 次访问约 30 次 miss。

- **Eytzinger 布局**：把有序数组按"完全二叉树的 BFS 序"重排，使二分的前几层访问落在连续内存里，可被预取。实测快 **1.5~3 倍**。
- **分块二分**：先按 block 二分定位块，再块内线性/二分，减少随机访问。

**② 分支预测失败**
`if (a[mid] < key)` 的分支结果随机，现代 CPU 预测失败代价约 15~20 cycle。
- **无分支写法**：用条件传送（`cmov`）：`l = key > a[mid] ? mid+1 : l;`（Java 里靠三元运算，效果有限；C++ 里靠 `?:` 或 SIMD）。

**③ 树高 vs 扇出**
二分是"二叉"，树高 `log₂n`。B 树把扇出提到几百，树高降到 `log₃₀₀n`，**用一次页读取换掉 log 层的比较**。

> **面试话术**："算法书上二分是 `O(log n)` 最优，但工程上数据库用 B+ 树而不是二分，因为瓶颈是 IO 次数而不是比较次数；把二叉树换成 300 叉树，树高从 30 降到 3~4，IO 减少一个数量级。"

### 4.7 二分在真实系统里的九种用法（面试加分素材）

| 场景 | 怎么用二分 | 关键点 |
|---|---|---|
| **git bisect** | 在"好提交…坏提交"区间二分，每次编译/测试 | `O(log n)` 次验证定位引入 bug 的 commit；`10000` 个提交仅需 14 次 |
| **B+ 树索引** | 页内二分定位 slot，页间按 key 导航 | MySQL/InnoDB 3~4 层覆盖十亿行 |
| **SSTable / LSM** | 稀疏索引 + block 内二分 | RocksDB 先在 index block 二分，再 block 内二分 |
| **日志定位** | 按时间戳在有序日志/分片文件上二分 | 找"故障发生前后 5 分钟"的日志 |
| **限流/容量压测** | 二分**并发数**或 **QPS**，找 P99 突变的拐点 | 这就是"系统的最大安全负载"，本质是单调谓词 |
| **灰度发布** | 二分流量比例，找到故障率突增的最小比例 | 5%→10%→20%→… 用二分代替逐档试探 |
| **批大小/超时调优** | 吞吐-延迟曲线单峰，二分/三分找最优 batch size、超时阈值 | Kafka producer batch、RPC timeout |
| **版本回滚定位** | 二分版本号区间，找"第一个坏版本" | 与 git bisect 同构 |
| **数据同步/对账** | 二分定位"第一条不一致"的记录（按主键有序） | 金融对账常用：先比总数，再二分定位差异区间 |

### 4.8 库函数对照与坑

| 语言 | API | 语义 | 坑 |
|---|---|---|---|
| **Java** | `Arrays.binarySearch(a, key)` | 命中返回**任意**一个下标 | 有重复元素时**不保证是第一个**；未命中返回 `-(插入点) - 1` |
| Java | `Collections.binarySearch(list, key)` | 同上 | 链表上调用是 `O(n log n)`（`get(i)` 是 `O(n)`） |
| Java | `TreeMap.ceilingKey / floorKey / higherKey / lowerKey` | `>= / <= / > / <` 的最近 key | 红黑树 `O(log n)`，比手写二分更"结构内" |
| Java | `TreeSet.ceiling / floor` | 同上 | 支持动态插入 |
| **C++** | `lower_bound / upper_bound / equal_range` | 标准语义 | 返回迭代器；对 `set` 用成员函数才 `O(log n)` |
| **Python** | `bisect_left / bisect_right / insort_left` | 同 lower/upper | `bisect_right(x)` = 第一个 `> x` |
| **Go** | `sort.Search(n, f)` | 返回**第一个** `f(i)==true` 的 `i` | 最优雅的抽象：直接把"二分"定义成"找第一个 true"，即 T4 模板 |

**`Arrays.binarySearch` 的返回值公式**（考点）：

```java
// 未命中时：return -(insertionPoint) - 1
// 所以 insertionPoint = -(returnValue) - 1
int pos = Arrays.binarySearch(a, x);
int insert = (pos >= 0) ? pos : -(pos + 1);
```

**为什么是 `-(insert) - 1` 而不是 `-insert`？**
因为 `insert` 可能为 `0`，`-0 == 0` 无法与"命中下标 0"区分。加 `-1` 保证未命中时返回值恒为负数。这是 JDK 里一个很小的设计细节，但面试问到时能答出来很加分。

**`sort.Search` 的抽象为什么值得学**：
```go
// Go 的实现就是把"二分"抽象成"在 [0,n) 上找第一个满足 f 的下标"
func Search(n int, f func(int) bool) int {
    i, j := 0, n
    for i < j {
        h := int(uint(i+j) >> 1)
        if !f(h) { i = h + 1 } else { j = h }
    }
    return i
}
```
它把"索引二分"和"二分答案"统一成同一个函数——这正是本文第 1 章强调的认知：**二分 = 单调谓词上找边界**。

### 5.2 逐题精讲

#### 题 1｜手写 `lower_bound` + 统计出现次数（★★★）

**面试形态**：不给你题目，直接说"写一个函数，在一个有序（可能有重复）数组里返回 `target` 第一次出现的位置，不许用 `Arrays.binarySearch`"。这是字节一面最经典的"开胃菜"。

**考察点**：区间开闭是否自洽、返回值是否可能越界、能否解释"为什么返回 l 是对的"。

**推导**：`lower_bound` 的判定式是 `a[mid] < x`。这个式子把整个数组分成两段：

```
[ 全部 < x ][ 全部 >= x ]
             ↑
          lower_bound 的答案
```
`l` 的物理含义是"**严格小于 x 的元素个数**"，所以 `l ∈ [0, n]`，天然可以等于 `n`（全部小于 x 时）。

**代码**：

```java
/** 第一个 >= x 的下标；不存在时返回 n */
public int lowerBound(int[] a, int x) {
    int l = 0, r = a.length;              // 左闭右开，r 是"越界位"
    while (l < r) {
        int mid = l + (r - l) / 2;
        if (a[mid] < x) l = mid + 1;      // mid 太小，答案在右侧
        else            r = mid;          // mid 可能是答案，保留
    }
    return l;
}

/** target 出现次数 */
public int count(int[] a, int target) {
    int left = lowerBound(a, target);
    if (left == a.length || a[left] != target) return 0;
    // 右界：第一个 > target
    int l = 0, r = a.length;
    while (l < r) {
        int mid = l + (r - l) / 2;
        if (a[mid] <= target) l = mid + 1;
        else                  r = mid;
    }
    return l - left;
}
```

**追问**：
- `l` 会不会越界？→ 会等于 `n`，调用方必须先判 `l == n`，这是本题最容易漏的边界。
- 为什么 `r = a.length` 而不是 `a.length - 1`？→ 因为答案可能就是 `n`（插入到末尾），左闭右开让 `n` 天然成为合法返回值。
- 如果数组降序？→ 把判定式取反（`a[mid] > x`），其余不动。

#### 题 2｜33 搜索旋转排序数组（★★★★）

见 **3.2** 的完整推导。这里补面试特有的三个追问：

**追问 A：`nums[l] <= nums[mid]` 的 `<=` 能不能换成 `<`？**
不能。当 `l == mid`（区间长度为 1 或 2 且 mid 落在左端点）时，`nums[l] == nums[mid]`，若用 `<`，会误判为"右半有序"，进而在错误的分支里搜索。**这个等号的必要性，80% 的候选人说不清。**

**追问 B：能不能先找 `target` 所在"段"的边界，再二分？**
可以，就是"先找 pivot 再两段二分"（见 3.2 解法二），比较次数约 `2 log n`，但可读性更好。**主动说出这个备选方案，是明显的加分项。**

**追问 C：如果数组有重复元素（81）？**
退化到 `O(n)`，并给出反例 `[1,1,1,1,3,1]`。**能主动指出"信息论上不够，必须逐个排除"**，说明你真的理解了二分的边界。

#### 题 3｜153 / 154 旋转数组最小值（★★★）

**为什么和 `nums[r]` 比而不是 `nums[l]`？**（这是本题的唯一考点，也是面试官真正想听的）

设 pivot 是最小值下标。考虑 `mid` 的两种情况：

| 情况 | `nums[mid]` 与 `nums[r]` 的关系 | 结论 |
|---|---|---|
| `mid` 在"大段"（pivot 右侧） | `nums[mid] > nums[r]` | 最小值在 `mid` 右侧（不含 mid） |
| `mid` 在"小段"（pivot 左侧或就是 pivot） | `nums[mid] <= nums[r]` | 最小值在 `mid` 左侧（**含 mid**） |

而如果和 `nums[l]` 比：`nums[l]` 一定在"大段"的开头（或 pivot），`nums[mid] < nums[l]` 只在 `mid` 落在"小段"时成立，一旦 `mid` 也在"大段"，`nums[mid] > nums[l]` 无法区分"mid 在 pivot 左边还是右边"。**`nums[r]` 是"最靠右、最接近 pivot"的锚点，信息量更大。**

```java
public int findMin(int[] nums) {
    int l = 0, r = nums.length - 1;
    while (l < r) {
        int mid = l + (r - l) / 2;
        if (nums[mid] > nums[r]) l = mid + 1;
        else                     r = mid;
    }
    return nums[l];
}
```

**154（有重复）**：`nums[mid] == nums[r]` 时无法判定，只能 `r--`（不能 `l++`，因为可能丢掉最小值）。

```java
if (nums[mid] > nums[r])      l = mid + 1;
else if (nums[mid] < nums[r]) r = mid;
else                          r--;        // 相等，缩小右界（安全）
```
**为什么 `r--` 安全？** 因为 `nums[r] == nums[mid]`，即使 `nums[r]` 是最小值，删掉它也不影响最小值的存在（`nums[mid]` 同值还在）。

#### 题 4｜4. 寻找两个正序数组的中位数（★★★★★）

**这是二分里"最像数学题"的一道，也是终面区分度最高的题之一。**

**破题：不要"找中位数"，要"切一刀"**

中位数的作用是**把两个数组分成左右两半，使左半元素个数 == 右半（或多 1）**，且 `max(左) <= min(右)`。

设数组 A 长 `m`、B 长 `n`，总左半需要 `totalLeft = (m + n + 1) / 2` 个元素。
在 A 上切 `i` 刀（左半取 A 的前 `i` 个），则在 B 上必须切 `j = totalLeft - i` 刀。

```
A:  A[0] ... A[i-1] | A[i] ... A[m-1]
B:  B[0] ... B[j-1] | B[j] ... B[n-1]
    └── 左半 totalLeft 个 ──┘└── 右半 ──┘

合法的切分 ⟺ max(A[i-1], B[j-1]) <= min(A[i], B[j])
            （四个边界用 ±∞ 兜底）
```

**为什么可以二分 `i`？** 因为 `i` 增大时 `A[i-1]` 变大、`A[i]` 变小，`j` 相应减小。定义谓词：

```
P(i) := (A[i-1] <= B[j])      （左半 A 的最大值不超过右半 B 的最小值）
```
`P` 关于 `i` **单调**（`i` 越大越容易失败），所以可以二分找"第一个使切分合法的 `i`"。

**为什么在"较短"的数组上二分？** 为了让 `j` 始终落在 `[0, n]` 内（否则切分越界），同时把搜索区间压到 `min(m,n)`。

**代码（推荐，`O(log min(m,n))`）**：

```java
public double findMedianSortedArrays(int[] a, int[] b) {
    if (a.length > b.length) return findMedianSortedArrays(b, a);   // 保证 a 更短
    int m = a.length, n = b.length;
    int totalLeft = (m + n + 1) / 2;
    int l = 0, r = m;

    while (l <= r) {
        int i = l + (r - l) / 2;                 // A 左半取 i 个
        int j = totalLeft - i;                   // B 左半取 j 个

        int aL = (i == 0) ? Integer.MIN_VALUE : a[i - 1];
        int aR = (i == m) ? Integer.MAX_VALUE : a[i];
        int bL = (j == 0) ? Integer.MIN_VALUE : b[j - 1];
        int bR = (j == n) ? Integer.MAX_VALUE : b[j];

        if (aL > bR) {                           // A 左半的最大值太大 → i 切多了
            r = i - 1;
        } else if (bL > aR) {                    // B 左半的最大值太大 → i 切少了
            l = i + 1;
        } else {                                 // 合法切分
            if ((m + n) % 2 == 1) return Math.max(aL, bL);
            return (Math.max(aL, bL) + Math.min(aR, bR)) / 2.0;
        }
    }
    throw new IllegalArgumentException("inputs must be sorted");
}
```

**四个边界值的兜底为什么用 `MIN/MAX_VALUE`？**
当 `i == 0`（A 的左半为空）时，`aL` 不存在，应视为 `-∞`（任何值都不大于它）；`i == m` 时 `aR` 不存在，视为 `+∞`。这样四个比较式在所有极端情况下都成立，**不需要额外的 if 分支**——这是本题代码能写得又短又稳的关键。

**复杂度**：`O(log min(m, n))` 时间（每次循环区间减半）、`O(1)` 空间。

**另一条路：找第 k 小（递归减半）**

```java
public int kth(int[] a, int al, int ar, int[] b, int bl, int br, int k) {
    int la = ar - al + 1, lb = br - bl + 1;
    if (la > lb) return kth(b, bl, br, a, al, ar, k);    // 保证 a 短
    if (la == 0) return b[bl + k - 1];                   // a 空了，直接取 b
    if (k == 1)  return Math.min(a[al], b[bl]);

    int i = Math.min(la, k / 2), j = k - i;              // 各看前 k/2 个
    if (a[al + i - 1] <= b[bl + j - 1])                   // a 的前 i 个不可能是第 k 小
        return kth(a, al + i, ar, b, bl, br, k - i);
    return kth(a, al, ar, b, bl + j, br, k - j);
}
```
**核心思想**：比较 `a[al + i - 1]` 与 `b[bl + j - 1]`（各是"前 k/2 个"里的最后一个）。较小的一方，其前 `i`（或 `j`）个元素**全部不可能**是第 k 小（因为至少有 `k` 个元素不大于它们），整段丢弃，`k` 相应减少。每次 `k` 减半 → `O(log k)`。

**两种解法对比**：

| 维度 | 切分法 | 第 k 小递归 |
|---|---|---|
| 复杂度 | `O(log min(m,n))` | `O(log(m+n))` |
| 代码量 | 短，但要处理 4 个 ±∞ | 稍长，但逻辑线性 |
| 边界难度 | 中（切分方向易反） | 中（k-i / k-j 的配套） |
| 面试推荐 | ✅ 首选 | ✅ 备选/追问时说 |

**高频追问**："如果两个数组长度都是 `10⁸`，还能做吗？"——能，`log₂(10⁸) ≈ 27` 次，无压力。**"如果数据在磁盘上？"**——每次 `a[i]`、`b[j]` 都是随机页读，但只有 ~27 次，完全可以接受；**这正是二分在"大数组 + 慢存储"场景下的天然优势。**

#### 题 5｜410 分割数组的最大值（★★★★）

**题意**：把非负数组分成 `m` 个**连续**子数组，使"各段和的最大值"最小。

**破题**：典型 minimax → 二分答案。

| 要素 | 值 |
|---|---|
| 答案 `x` | "每段和的上限" |
| 单调性 | `x` 越大，越容易用 ≤ m 段分完（非增的段数） |
| 下界 | `max(nums)`（单元素成段） |
| 上界 | `sum(nums)`（一整段） |
| check | 贪心：`cur + x > cap` 就另起一段，数段数 `≤ m` |

**为什么贪心是最优的？**（交换论证）要让段数最少，每一段都应"尽可能长"。若最优解第一段停在 `j`，贪心停到 `g ≥ j`，把第一段延长到 `g` 后剩余元素更少，段数不增。归纳即可。∎

```java
public int splitArray(int[] nums, int m) {
    long lo = 0, hi = 0;
    for (int x : nums) { lo = Math.max(lo, x); hi += x; }

    while (lo < hi) {
        long mid = lo + (hi - lo) / 2;
        if (canSplit(nums, mid, m)) hi = mid;
        else                        lo = mid + 1;
    }
    return (int) lo;
}

private boolean canSplit(int[] nums, long cap, int m) {
    int cnt = 1;
    long cur = 0;
    for (int x : nums) {
        if (cur + x > cap) {
            cnt++;
            cur = x;
            if (cnt > m) return false;
        } else {
            cur += x;
        }
    }
    return true;
}
```

**复杂度** `O(n log sum)`。

**追问**：
- 如果是"分成**恰好** m 段"且允许空段？→ 题目通常要求非空，本题语义下 `cnt ≤ m` 即可，因为可以把某些段再拆开得到恰好 m 段（元素非负且 m ≤ n 时成立）。
- 如果元素可能为负？→ **贪心失效**（多装不一定更好，段和的上限不再单调有效）。这是"非负"这个前提的真正用途，很多人没意识到。
- 与 1011 的关系？→ 完全同构（1011 的"天数"= 这里的"段数"，1011 的"载重"= 这里的"段和上限"）。

#### 题 6｜1482 制作 m 束花所需的最少天数（★★★★）

**题意**：`bloomDay[i]` 是第 `i` 朵花开放的天数，需要 `m` 束、每束 `k` 朵**相邻**的花。求最少等几天。

**破题**：二分"天数"。

| 要素 | 值 |
|---|---|
| 答案 `x` | 等待天数 |
| 单调性 | 天数越多，开的花越多 → 能做的花束越多 |
| 下界 | `min(bloomDay)`（这天才有花开） |
| 上界 | `max(bloomDay)`（所有花都开了；若此时还不够就无解） |
| check | 顺序扫描：花开了就连续计数，凑够 `k` 就成一束并清零，断了就清零 |

```java
public int minDays(int[] bloomDay, int m, int k) {
    if ((long) m * k > bloomDay.length) return -1;   // ⚠️ 必然无解，且防 long 溢出

    int lo = Integer.MAX_VALUE, hi = 0;
    for (int d : bloomDay) { lo = Math.min(lo, d); hi = Math.max(hi, d); }

    while (lo < hi) {
        int mid = lo + (hi - lo) / 2;
        if (canMake(bloomDay, m, k, mid)) hi = mid;
        else                              lo = mid + 1;
    }
    return canMake(bloomDay, m, k, lo) ? lo : -1;
}

private boolean canMake(int[] bloom, int m, int k, int day) {
    int bouquets = 0, flowers = 0;
    for (int b : bloom) {
        if (day >= b) {
            flowers++;
            if (flowers == k) { bouquets++; flowers = 0; }   // 凑够一束，立即清零
        } else {
            flowers = 0;                                     // 断了，前面攒的作废
        }
    }
    return bouquets >= m;
}
```

**细节三连**：
1. `m * k` 可能溢出（`m, k ≤ 10⁶`），必须转 `long` 比较。
2. 每朵花只贡献 **1 朵**（不是 `day - bloomDay[i]` 朵）——这是最容易想错的地方：花开了就是开了，摘走就没了。
3. `flowers = 0` 的时机：凑够一束后必须清零，否则会把"跨束"的花算进去。

**复杂度** `O(n log maxDay)`。

#### 题 7｜1552 两球之间的磁力（★★★★）

**题意**：`position` 是球筐位置，放 `m` 个球，使"任意两球的最小距离"**最大**。这是 maxmin 的教科书题。

**破题**：二分"最小距离 `d`"，check 是"能否放下 m 个球且两两距离 ≥ d"。

| 要素 | 值 |
|---|---|
| 答案 `x` | 最小间距 `d` |
| 单调性 | `d` 越大越难放下（可行 → 更大也可能可行，但最终会失败）→ 求**最后一个可行** |
| 下界 | `1` |
| 上界 | `max - min`（最多两个球在两端） |
| check | 排序后贪心：第一个放在最左，之后每个只要距上一个 ≥ d 就放 |

```java
public int maxDistance(int[] position, int m) {
    Arrays.sort(position);
    int n = position.length;
    int lo = 1, hi = position[n - 1] - position[0];

    while (lo < hi) {
        int mid = lo + (hi - lo + 1) / 2;       // ⚠️ 上取整（求最大可行）
        if (canPlace(position, m, mid)) lo = mid;        // 可行 → 答案 ≥ mid
        else                            hi = mid - 1;
    }
    return lo;
}

private boolean canPlace(int[] p, int m, int d) {
    int cnt = 1, last = p[0];
    for (int i = 1; i < p.length && cnt < m; i++) {
        if (p[i] - last >= d) { cnt++; last = p[i]; }
    }
    return cnt >= m;
}
```

**贪心正确性**（为什么要"第一个放最左"）：把第一个球放最左，等价于给后续所有球留出最大空间；任何其他方案都可以"左移第一个球"而不减少可行性。之后的每个球都放在"满足距离的最左位置"，同理不劣。∎

**⚠️ 上取整的必要性**：若写成 `mid = lo + (hi-lo)/2` 配 `lo = mid`，当 `hi = lo + 1` 时 `mid = lo`，`lo = mid` 不动 → **死循环**。这是本题最经典的 WA/TLE 原因，也是 1.3 那张表的直接应用。

**复杂度** `O(n log n + n log(max-min))`（排序 + 二分）。

#### 题 8｜1802 有界数组中指定下标处的最大值（★★★★）

**题意**：构造长度 `n` 的正整数数组，元素和 ≤ `maxSum`，相邻元素差的绝对值 ≤ 1，且 `nums[index]` 尽可能大。求 `nums[index]` 的最大值。

**破题**：二分 `nums[index] = x`，check 是"在 `x` 固定时，能构造出的**最小**总和是否 ≤ `maxSum`"。

**为什么是"最小总和"？** 因为约束只有"总和不能超过"，所以只要**最省的构造**能塞进 `maxSum`，就一定存在合法数组；反之若最省的都超了，则任何构造都超。这就是"取极值构造"的标准手法。

**最省构造**：从 `index` 向两侧各"每步减 1"，减到 1 后保持 1（因为必须正整数）。

```
x = 5, index = 2, n = 8
下标:  0   1   2   3   4   5   6   7
值:    3   4   5   4   3   2   1   1
                ↑ index
左边长度 2，从 4 递减到 3；右边长度 5，5→4→3→2→1→1（触底后补 1）
```

**闭式求和公式**（关键）：

```java
/** 长度为 len 的"从 peak-1 开始每步减 1、最小为 1"的序列和 */
private long decSum(long peak, int len) {
    if (len <= 0) return 0;
    if (peak > len) {
        // 不触底：peak-1, peak-2, ..., peak-len   （最后一项 >= 1）
        return (peak - 1 + peak - len) * len / 2;
    } else {
        // 触底：peak-1, ..., 1 共 (peak-1) 项，剩下 (len-(peak-1)) 项都是 1
        return (peak - 1) * peak / 2 + (len - (peak - 1));
    }
}
```

**验算**（`peak=5, len=2`）：`5 > 2` → `(4 + 3) * 2 / 2 = 7`，实际 `4+3=7` ✅
（`peak=5, len=5`）：`5 > 5` 不成立 → 走 else：`4*5/2 + (5-4) = 10 + 1 = 11`，实际 `4+3+2+1+1 = 11` ✅
（`peak=1, len=3`）：else → `0 + (3-0) = 3`，实际 `1+1+1=3` ✅

```java
public int maxValue(int n, int index, int maxSum) {
    long lo = 1, hi = maxSum;                 // lo=1 天然可行（全 1，和 = n <= maxSum）
    while (lo < hi) {
        long mid = lo + (hi - lo + 1) / 2;    // 上取整
        if (need(n, index, mid) <= maxSum) lo = mid;
        else                               hi = mid - 1;
    }
    return (int) lo;
}

private long need(int n, int index, long peak) {
    return peak + decSum(peak, index) + decSum(peak, n - index - 1);
}
```

**复杂度** `O(log maxSum)`（check 是 `O(1)`），非常优雅——这是"check 用闭式公式"的典型。

**追问**："如果约束改成相邻差 ≤ 2？"→ 把"每步减 1"改成"每步减 2"，公式里的等差步长改一下即可，**二分框架完全不动**。这体现了"二分答案的框架不变，只换 check"的价值。

#### 题 9｜719 找出第 k 小的数对距离（★★★★★）

**题意**：`nums` 中所有数对 `|nums[i] - nums[j]|`（`i < j`）里，第 `k` 小的值。

**破题**：这是"值域二分 + 计数"的标杆题。关键是意识到：**你不需要"构造出第 k 小"，只需要"数一数 ≤ x 的对有多少个"。**

| 要素 | 值 |
|---|---|
| 答案 `x` | 第 k 小的距离值 |
| 单调性 | `x` 越大，"距离 ≤ x 的对数"越多（非减）→ 求**第一个使 count ≥ k 的 x** |
| 下界 | `0`（可能有相等元素） |
| 上界 | `max - min` |
| check | 排序 + 双指针，`O(n)` 数出"距离 ≤ x 的对数" |

**check 的推导**（排序后，对每个右端点 `j` 数左端点数）：

```
排序后 a[0..n-1]，固定 j，需要 a[j] - a[i] <= d  →  a[i] >= a[j] - d
设 left 是第一个满足 a[left] >= a[j]-d 的下标
则 i ∈ [left, j-1] 全部合法 → 贡献 (j - left) 对
```

因为 `j` 递增时 `a[j]-d` 递增，`left` 只增不减 → 双指针 `O(n)`。

```java
public int smallestDistancePair(int[] nums, int k) {
    Arrays.sort(nums);
    int n = nums.length;
    int lo = 0, hi = nums[n - 1] - nums[0];

    while (lo < hi) {
        int mid = lo + (hi - lo) / 2;
        if (countLE(nums, mid) >= k) hi = mid;   // 第一个 count >= k
        else                         lo = mid + 1;
    }
    return lo;
}

/** 数出距离 <= d 的数对个数 */
private int countLE(int[] a, int d) {
    int cnt = 0, left = 0;
    for (int j = 1; j < a.length; j++) {
        while (a[j] - a[left] > d) left++;
        cnt += j - left;                 // ⚠️ 不是 j - left + 1
    }
    return cnt;
}
```

**两个必须说清的细节**：

1. **`cnt += j - left` 而不是 `j - left + 1`**：因为 `i < j`，`i` 最大只能到 `j-1`，共 `j - left` 个。
2. **`cnt` 的规模**：`n ≤ 10⁴` → 最多约 `5×10⁷` 对，`int` 放得下；若 `n = 10⁵` 就要 `long`。

**复杂度**：`O(n log n + n log(max-min))`，`log(10⁶) ≈ 20`，非常快。

**追问**："为什么不能用快速选择？"——因为"数对距离"不是数组里的元素，无法 partition；只能"数个数"。**这一句回答能直接证明你真的理解'为什么二分答案在某些场景不可替代'。**

**姊妹题**：786 第 K 个最小的素数分数（同样是"值域二分 + 计数"，但要用浮点或交叉相乘比较）。

#### 题 10｜644 最大平均子段和（长度 ≥ k）（★★★★★）

**题意**：数组 `nums`，找长度 **≥ k** 的连续子数组，使其平均值最大。

**破题**：平均值最大 → 实数二分 + **0/1 分数规划**。这是二分里最"数学"的一类，属于 SP/算法岗终面题。

**核心变换**（这一步是整个解法的心脏）：

> 判断"是否存在长度 ≥ k 的子数组，其平均值 ≥ `avg`"
> ⟺ 判断"是否存在长度 ≥ k 的子数组，其 `(元素和 - avg × 长度) ≥ 0`"
> ⟺ 令 `b[i] = a[i] - avg`，判断"是否存在长度 ≥ k 的子数组，`b` 的子段和 ≥ 0"

**为什么这个变换成立？** 平均值 `≥ avg` ⟺ `Σa[i] / len ≥ avg` ⟺ `Σ(a[i] - avg) ≥ 0`。**把"平均"变成"前缀和"，这是所有平均值/比率类问题的通用技巧。**

**check 的实现**（前缀和 + 维护历史最小值）：

```java
/** 是否存在长度 >= k 的子数组平均值 >= avg */
private boolean feasible(int[] a, int k, double avg) {
    int n = a.length;
    double[] pre = new double[n + 1];
    for (int i = 0; i < n; i++) pre[i + 1] = pre[i] + a[i] - avg;

    double minPre = 0;                        // pre[0..i-k] 的最小值
    for (int i = k; i <= n; i++) {
        minPre = Math.min(minPre, pre[i - k]);   // 时间窗正好 i-k，保证长度 >= k
        if (pre[i] - minPre >= 0) return true;   // 存在长度 >= k 且和 >= 0
    }
    return false;
}
```

**`minPre` 的时间窗为什么是 `i - k`？**
要求子段长度 ≥ k，则左端点 `j` 必须满足 `i - j ≥ k`，即 `j ≤ i - k`。所以对每个 `i`，要维护 `pre[0..i-k]` 的最小值 → 先更新 `minPre`（把 `pre[i-k]` 纳进来），再判 `pre[i] - minPre ≥ 0`。**顺序反了就会漏掉恰好长度 k 的情况。**

```java
public double findMaxAverage(int[] nums, int k) {
    double lo = Double.MAX_VALUE, hi = -Double.MAX_VALUE;
    for (int x : nums) { lo = Math.min(lo, x); hi = Math.max(hi, x); }

    for (int it = 0; it < 100; it++) {         // 实数二分：固定 100 次
        double mid = (lo + hi) / 2;
        if (feasible(nums, k, mid)) lo = mid;  // 可行 → 答案 >= mid
        else                        hi = mid;
    }
    return lo;
}
```

**复杂度**：`O(n × 100)`，`n = 10⁴` → `10⁶` 次，秒过。

**追问链**：

| 追问 | 回答 |
|---|---|
| 为什么不用 `while (hi - lo > 1e-5)`？ | 浮点比较可能因舍入误差不收敛；固定迭代更稳 |
| 如果要求"长度**恰好** k"？ | 去掉 `minPre` 的滑动窗口，直接 `pre[i] - pre[i-k]` 比较 |
| 如果要求"平均值**最接近**某值"？ | 变成两个单调性相反的二分，或者直接枚举 |
| 0/1 分数规划的一般形式？ | 求 `max Σ(a[i]x[i]) / Σ(b[i]x[i])`，二分 `λ` 后判 `max Σ(a[i]-λb[i])x[i] ≥ 0` |

**这套"二分 + 0/1 分数规划"的能力迁移极强**：最优比率生成树、最大密度子图、最优比率环，本质都是同一招。

#### 题 11｜300 最长递增子序列的 `O(n log n)`（★★★★）

见 **4.3** 的完整解释。面试要点只有三个：

#### 题 12｜69 / 367 平方根 / 完全平方数（★★★）

**69 x 的平方根（向下取整）**——值域二分 + 防溢出的经典组合：

```java
public int mySqrt(int x) {
    long lo = 0, hi = x, ans = 0;
    while (lo <= hi) {
        long mid = lo + (hi - lo) / 2;
        if (mid * mid <= x) { ans = mid; lo = mid + 1; }   // 记录最后一个可行
        else                { hi = mid - 1; }
    }
    return (int) ans;
}
```

**为什么用 `long`？** `x` 最大 `2³¹-1`，`mid` 最大约 `46341`，`mid*mid` 会溢出 `int`（`46341² ≈ 2.147×10⁹ > 2.147×10⁹`，恰好卡在边界）。**这道题是"判断乘法溢出"的标准考点。**

**更优雅的防溢出写法**（把乘法换成除法）：

```java
if (mid <= x / mid) { ans = mid; lo = mid + 1; }   // 等价于 mid * mid <= x，但不会溢出
```
注意 `mid == 0` 时要特判（除零）。

**上界优化**：`x ≥ 4` 时答案 ≤ `x/2`，可以用 `hi = x/2 + 1` 减少几次迭代。

**367 完全平方数**：判定型，`mid*mid == num` 且注意 `num = 0/1` 的边界。

**实数版（面试常问"求平方根保留 6 位小数"）**：

```java
public double sqrt(double x) {              // x >= 0
    double lo = 0, hi = Math.max(1.0, x);    // 注意 x < 1 时上界要取 1
    for (int i = 0; i < 100; i++) {
        double mid = (lo + hi) / 2;
        if (mid * mid < x) lo = mid;
        else               hi = mid;
    }
    return (lo + hi) / 2;
}
```
**坑点**：`x < 1`（如 `0.25`）时，`sqrt(x) > x`，所以 `hi = x` 会让区间不含答案。必须 `hi = max(1, x)`。**这个细节能区分"背模板"和"真理解"。**

#### 题 13｜278 第一个错误的版本（★★）

```java
public int firstBadVersion(int n) {
```

#### 题 14｜793 阶乘函数后 K 个零（★★★）

**题意**：`f(n)` = `n!` 末尾零的个数，求满足 `f(n) == k` 的 `n` 的个数。

**第一步：算 `f(n)`**

```java
long zeros(long n) {          // 末尾零 = 因子 5 的个数
    long c = 0;
    while (n > 0) { n /= 5; c += n; }
    return c;
}
```
**为什么是数 5 而不是 10？** 因为 `2` 的个数远多于 `5`，瓶颈是 `5`。`f(n) = ⌊n/5⌋ + ⌊n/25⌋ + ⌊n/125⌋ + …`。复杂度 `O(log₅n)`。

**第二步：发现关键性质**

`f(n)` 是**非减的阶梯函数**，且每次"跳 5"——因为 `⌊n/5⌋` 每 5 个 `n` 增加 1。所以：

> **`f(n)` 的每个取值要么出现 5 次，要么一次都不出现**（被跳过）。

因此答案只能是 **`0` 或 `5`**。

**第三步：两次二分求"出现次数的上下界"**

```java
public int preimageSizeFZF(int k) {
    return (int) (firstGE(k + 1) - firstGE(k));
}

/** 最小的 n，使 zeros(n) >= t */
private long firstGE(long t) {
    long l = 0, r = 5L * (t + 1);         // 上界足够：zeros(5t) >= t
    while (l < r) {
        long mid = l + (r - l) / 2;
        if (zeros(mid) >= t) r = mid;
        else                 l = mid + 1;
    }
    return l;
}
```

**为什么 `r = 5(t+1)` 够？** `zeros(5t) = t + ⌊t/5⌋ + … ≥ t`，所以 `5t` 一定满足 `>= t`，取 `5(t+1)` 有冗余。这比取 `Long.MAX_VALUE` 少跑约 30 次二分。

**复杂度**：`O(log²k)`（两次二分 × 每次 `O(log k)` 算 `zeros`）。**能想到"答案只能是 0 或 5"这一步，是本题的区分点。**

#### 题 15｜1283 使结果不超过阈值的最小除数（★★★）

```java
public int smallestDivisor(int[] nums, int threshold) {
    int lo = 1, hi = 0;
    for (int x : nums) hi = Math.max(hi, x);

    while (lo < hi) {
        int mid = lo + (hi - lo) / 2;
        if (sumDiv(nums, mid) <= threshold) hi = mid;
        else                                lo = mid + 1;
    }
    return lo;
}

private long sumDiv(int[] a, int d) {
    long s = 0;
    for (int x : a) {
        s += (x + (long) d - 1) / d;        // 向上取整
        if (s > Integer.MAX_VALUE) return s;  // 早退（结果一定 > threshold）
    }
    return s;
}
```

**与 875/1011 的关系**：完全同构（`d` ↔ 速度/载重，"和" ↔ 时间/天数）。**三道题只要掌握一道，另两道 5 分钟就能写完**——这正是"题型归纳"的价值。

**边界前提（别忽略）**：题设 `threshold >= nums.length`，所以取 `d = max(nums)` 时 `Σ ceil(x/d) = n <= threshold` 恒成立 → `hi` 天然可行，不需要特判无解。**如果 `threshold < n`，问题无解**（每件至少贡献 1），此时必须先返回 `-1`，否则二分答案会给出一个不满足约束的值。这就是 2.2 第 4 步"`hi` 必须天然可行"的实例。

### 5.3 面试口述模板（30 秒把思路讲清楚）

被问"说说你的思路"时，按这五句走，面试官会觉得你"有方法论"：

```
① 定类型：这是「索引二分」还是「二分答案」？
   信号：数组有序/半有序/单峰 → 索引二分；"最小化的最大值" → 二分答案。

② 定不变量：我维护区间 [l, r]，保证答案一定在里面。

③ 定判定：mid 位置我能拿到什么信息？（比较大小 / 斜率 / 可行性）
   这个信息怎么排除一半？

④ 定收缩：mid 下取整 → 更新必须动右界（r=mid）或左界 +1；
   上取整 → 必须动左界（l=mid）或右界 -1。所以不会死循环。

⑤ 定边界：返回 l 还是 ans？hi 是否天然可行？答案可能是 0 或 n 吗？

⑥ 报复杂度：索引二分 O(log n)；二分答案 O(n log C)，C 是值域，约 30 次扫描。
```

**主动补一句加分的话**："我先说三个我要特别小心的点：`mid` 溢出、循环终止条件、边界返回值。写完我会用空数组、单元素、全相同、答案在两端这四组用例验一遍。"

### 7.4 一页记忆卡片（打印贴屏幕）

```
┌──────────────────────────────────────────────────────────┐
│  二分三条铁律                                             │
│  ① mid 下取整 → 只能 r=mid 或 l=mid+1                     │
│     mid 上取整 → 只能 l=mid 或 r=mid-1                    │
│  ② 闭区间 [l,r]：l<=r；左闭右开 [l,r)：l<r，r 初值 n      │
│  ③ mid = l + (r-l)/2，绝不写 (l+r)/2                      │
├──────────────────────────────────────────────────────────┤
│  二分答案四步                                             │
│  定答案 → 证单调 → 写 check(可早退/无副作用) → 定边界       │
│  求最小：下取整 + hi=mid；求最大：上取整 + lo=mid         │
│  hi 必须可行；lo 取物理下界                               │
├──────────────────────────────────────────────────────────┤
│  判定口诀                                                 │
│  有序看索引，最优看单调，实数看精度                        │
│  出现"最小化的最大值/在 D 天内/至少/容量" → 二分答案      │
└──────────────────────────────────────────────────────────┘
```
