# 第 0 章 先建立地基：字符串的底层认知

> 这一章不刷题，但你面试时的"深度分"几乎全从这里来。面试官区分"背过模板"和"懂数据结构"的方式，就是问这些。

## 0.1 字符串为什么是"特殊"的数据结构

数组 / 链表是**通用容器**：元素是什么类型无所谓，容器只负责"存 + 取"。
字符串不是通用容器，它是**带语义的定长序列**，这个"语义"带来了三个别的结构没有的性质：

1. **字符有值域**。字母表大小 Σ 通常很小（小写字母 26、ASCII 128、DNA 4、中文常用字几千）。→ 这就是**计数数组、位图、前缀计数**能替代哈希的根因，也是 49 题"计数指纹"比"排序指纹"更快的原因。
2. **位置有意义**。子串 `s[i..j]` 是"连续区间"，于是**双指针、滑动窗口、区间 DP、前缀和**这些"下标技巧"天然适配；链表题里的"区间"就没这么强的结构。
3. **前缀有结构**。字符串之间的"公共前缀"是一种**天然的树形关系**（所有字符串构成一棵前缀树）。→ 这就是 Trie 存在的根因，也是"用哈希做前缀查询很难受"的原因。

一句话总结本专题的四个母题：

```
字符值域小  ──→ 计数 / 位图 / 指纹哈希        （49）
位置连续    ──→ 双指针 / 中心扩展 / 区间 DP   （5）
嵌套次序    ──→ 栈（后进先出）                （20）
前缀共享    ──→ Trie（前缀树 / 自动机）        （208）
```

## 0.2 Java String 的五个底层事实（面试必问）

### ① 不可变（immutable）：`final class` + `final` 字段

```java
public final class String implements java.io.Serializable, Comparable<String>, CharSequence {
    private final byte[] value;   // JDK 9+（Compact Strings）
    private final byte coder;     // LATIN1=0 / UTF16=1
    private int hash;             // 缓存的 hashCode，默认 0
    // JDK 8 及以前是 private final char[] value;
}
```

**为什么必须不可变**（四条理由，面试按这个顺序说）：

| 理由 | 说明 |
|---|---|
| **哈希稳定性** | `hashCode` 被缓存，且被 `HashMap` 的 key 依赖。若可变，放入桶后再改内容，桶下标变了 → 永远查不到（内存泄漏级 bug） |
| **常量池共享** | 字面量 `"abc"` 在 Class 常量池 / 运行时常量池里被多处引用，共享的前提是不可变 |
| **线程安全** | 不可变对象天然线程安全，无需同步（这也是 `String` 能做 `switch`、注解值、类加载器参数的前提） |
| **安全** | 类加载、网络连接、文件路径等场景传参时，若中途被改会造成校验绕过（TOCTOU） |

> 🔥 追问："那 `String` 为什么不是 `final` 的 `char[]` 而是 `byte[]`？"
> JDK 9 引入 **Compact Strings**（JEP 254）：统计发现绝大多数串只含 Latin-1 字符，用 `byte[]` + `coder` 编码，相比 `char[]` **省一半内存**，且 `String.length()`、`indexOf` 等热路径更快（数据密度翻倍，缓存命中率上升）。代价是遇到非 Latin-1（如中文）要按 UTF-16 存，此时 `coder=1`。

### ② `hashCode` 的实现与"为什么是 31"

```java
public int hashCode() {
    int h = hash;
    if (h == 0 && value.length > 0) {
        for (byte b : value) h = 31 * h + (b & 0xff);   // JDK9 简化；JDK8 是 for (char c : value)
        hash = h;
    }
    return h;
}
```

- 多项式滚动哈希，等价于 $\sum_{i} c_i \cdot 31^{n-1-i} \bmod 2^{32}$（`int` 自然溢出，**不是** `long`）。
- **31 的三个理由**：① 奇素数（减少碰撞，若用偶数，乘法会丢低位信息）；② `31 * h == (h << 5) - h`，JIT 能编译成一条减法 + 移位，比乘法快；③ 数值不大不小，溢出后仍有较好分布（这是经验值，K&R 里提过）。
- **`hash` 字段缓存**：第一次算完存起来；`h == 0` 作为"未计算"哨兵，所以空串/全零哈希会重算（可接受的权衡）。

> 🔥 追问："两个不同字符串 `hashCode` 相同怎么办？"
> 这就是**哈希冲突**，靠 `equals` 兜底。所以契约是：`equals` 相等 ⇒ `hashCode` 必须相等；反之不成立。反例：`"Aa".hashCode() == "BB".hashCode()`（都是 2112），这是 Java 里著名的碰撞对。

### ③ `substring` 的内存历史（一个真实的线上事故）

- **JDK 6**：`substring` 返回的新 String **共享原串的 `char[]`**，只改 `offset/count`。一个 1MB 的串取 3 个字符，整个 1MB 数组无法回收 → **内存泄漏**。
- **JDK 7u6 起**：`substring` 变成**复制**（`Arrays.copyOfRange`），代价是 O(len) 拷贝，换来不再泄漏。
- LeetCode 上 `s.substring(i, j)` 是 O(j-i)，别在循环里做（会悄悄变成 O(n²)）。

### ④ `+` 拼接与 `StringBuilder`

```java
String s = "";
for (int i = 0; i < n; i++) s += arr[i];     // O(n²)，每次新建 String + 拷贝
```

- 编译期常量拼接（`"a" + "b"`）会被 javac **常量折叠**为 `"ab"`，没有运行时开销。
- 循环内拼接会被编译成 `new StringBuilder().append(...).toString()`（JDK 9+ 是 `invokedynamic` + `StringConcatFactory`），但**每次迭代都新建一个 SB** → 仍是 O(n²)。
- 结论：**循环里用 `StringBuilder`，并预估容量** `new StringBuilder(n)`，避免扩容拷贝（默认 16，扩容 `2*cap+2`）。

### ⑤ `charAt` vs `toCharArray` vs `codePoint`

- `charAt(i)` 每次带一次边界检查（`Objects.checkIndex`），但 JIT 通常能消除；`toCharArray()` 一次性拷贝，之后纯数组访问。**单次遍历两者差别在噪声级**，但 `toCharArray` 多一份 O(n) 内存。刷题随意，线上热路径优先 `charAt`（省一次拷贝）。
- **`char` 是 UTF-16 code unit，不是"一个字符"**：`"𝄞".length() == 2`（代理对 surrogate pair）。所以第 5 题按 `char` 判回文，对 emoji / 生僻字（> U+FFFF）会判错。正确姿势是用 `codePointAt` / `offsetByCodePoints`。**这是第 5 题最容易被追问的"国际化坑"**。

> 🔥 追问："回文判断在 Unicode 下还有什么坑？"
> ① 组合字符（`e` + U+0301 = `é`）视觉上一个字符、编码两个 code point；② 大小写折叠（`ß` vs `SS`，土耳其语 `İ`）；③ 双向文本（RTL）。工业级实现用 `java.text.Normalizer.normalize(s, NFC)` + `Character.toLowerCase` + `BreakIterator` 按"用户感知字符"（grapheme cluster）切分。面试只要说出"`char` 不等于字符，要按 code point / grapheme 处理"就已经赢了。

## 0.4 复杂度怎么标：n / k / m / Σ 四个符号

字符串题的复杂度最容易标错，因为"长度"有多个：

| 符号 | 含义 | 出现在 |
|---|---|---|
| `n` | 主串长度 / 数组元素个数 | 全部 |
| `k` | 单个单词的最大长度（49 题）、模式串长度 | 49、28 |
| `m` | 单词长度（208）、匹配串长度 | 208、211 |
| `Σ` | 字母表大小（26 / 128 / 汉字数千） | 49、208 空间 |
| `N` | 所有单词总字符数（Trie 空间） | 208 |

**两个必须记住的陷阱**：

1. **"O(n) 的字符串操作"其实是 O(n) 拷贝**：`s.substring`、`s + t`、`new String(char[])` 都是 O(长度)，在循环里会升级复杂度。
2. **"比较两个字符串"不是 O(1)**：`s1.equals(s2)` 是 O(k)，`HashMap` 里每次冲突比较都是 O(k)。49 题排序法的 `n k log k` 里，`log k` 来自比较次数，比较本身还带 k 的常数 —— 严格说是 O(n·k·log k)，因为字符比较是 O(1)（每次只比一个字符，命中即返回）。

# 第 1 章 20. 有效的括号 ★★☆

> `【权重】★★★★☆`（4/5）—— 大厂开场题的头号种子。字节、美团、快手、小红书的一面几乎必出；腾讯偏爱它的变体（表达式解析）。
> **它考的不是算法，是"工程素养"**：能不能一次写对、能不能主动处理三种边界、能不能讲清"为什么是栈不是别的"。

## 1.1 题意与边界

**题意**：给定只包含 `'('`、`')'`、`'['`、`']'`、`'{'`、`'}'` 的字符串 `s`，判断是否有效。

有效的三条规则（官方定义，要能背出来）：

1. **左括号必须用相同类型的右括号闭合**（`(` 只能配 `)`）；
2. **左括号必须以正确的顺序闭合**（嵌套次序不能乱）；
3. 每个右括号都有一个对应的、**同类型**的左括号。

**约束**：`1 <= s.length <= 10^4`，`s` 仅由括号字符组成。

**必须先问的三个边界**（面试时主动说出来，这是加分项）：

| 边界 | 期望 | 为什么 |
|---|---|---|
| `s = ""` | `true`（题目约束下不会出现，但接口要鲁棒） | 空串视为合法 |
| `s.length` 为奇数 | 立即 `false` | 括号成对出现，奇数长度不可能配平 |
| `s = "]"` | `false` | 只有右括号 → 栈空时弹栈，必须报错 |

## 1.2 为什么必须是"栈"：从文法角度讲透

这是本章的**深度分所在**。多数人只会说"因为括号是后进先出"，这句是对的但太浅。完整答法分三层：

### 第一层：直观层 —— "最近的未匹配左括号优先闭合"

扫描到 `)` 时，它要闭合的是**离它最近的那个还没闭合的 `(`**。这个"最近"就是 LIFO。用图说明：

```
输入:  ( [ { } ] )
       ↑        ↑
       最早的 (   最晚的 } 先闭合 ──→ 后进先出
```

如果先闭合最早的那个 `(`，就变成 `( [ { ) ] }` —— 交叉嵌套，非法。**"嵌套"这个语义本身就规定了解除顺序是栈序**。

### 第二层：反例层 —— "为什么不能用计数器"

很多人会想："数一下左右括号数量相等不就行了？" 立刻用反例打掉：

```
s = "([)]"    左括号 2 个，右括号 2 个，数量相等
              但嵌套非法 → 计数法误判为 true
```

更一般地，**计数法只能回答"是否配平"，不能回答"是否嵌套正确"**。要区分二者，必须记住"当前有哪些类型的左括号还没闭合、它们的顺序如何" —— 这就是栈。

### 第三层：文法层 —— 括号串是上下文无关语言（Dyck 语言）

括号串可以递归定义为：

```
S → ε
S → ( S )
S → [ S ]
S → { S }
S → S S          （并列，可省略，因为可由前几条组合出）
```

这是**上下文无关文法（CFG）**，不是正则语言 —— 用有限状态机（DFA）识别不了任意深度的嵌套（DFA 没有"计数器/栈"这种无界存储）。而**下推自动机（PDA）= 有限状态机 + 一个栈**，正好识别 CFG。所以：

> **栈不是"一个技巧"，而是这类语言的"识别器"本身。** 括号匹配问题在计算理论里叫 **Dyck 语言**的成员判定问题，其最优算法就是 PDA 模拟，时间 O(n)、空间 O(深度)。

🔥 面试官可能追问："如果一个字符串只用一种括号，能不能用计数器？"
**可以**。因为只有一种类型时，"未闭合数"这个计数器就完全刻画了栈的内容（栈里全是同一种符号，只需知道个数）。这也是 32 题"最长有效括号"能用双计数器做的原因。**一旦类型 ≥ 2，计数器失效** —— 这个"为什么能 / 为什么不能"的对比，是最能体现功底的回答。

## 1.3 三种失败模式与最小反例

面试时把失败模式枚举清楚，等于把测试用例想清楚了：

| # | 失败模式 | 最小反例 | 触发位置 |
|---|---|---|---|
| ① | **右括号多余**（栈已空却来右括号） | `")"`、`"())"` | 弹栈前判空 |
| ② | **左括号多余**（扫完栈非空） | `"("`、`"(()"` | 循环结束后 `top != -1` |
| ③ | **类型不匹配**（弹出的是另一种左括号） | `"(]"`、`"([)]"` | 弹出后比较类型 |

```
①  ")"      → 栈空，来 ')'      → 立即 false
②  "(()"    → 扫完栈里剩 "(("    → false
③  "(]"     → 弹出 '('，来 ']'   → 类型不符 → false
```

**三种模式互不重叠，覆盖全部非法情形** —— 这可以用"合法串 ⇔ 每条右括号都能弹出同类型的栈顶，且最终栈空"来严格论证（见 1.5）。

## 1.4 代码：数组模拟栈（最优写法）

### 版本 A：数组模拟栈（推荐，最快）

```java
class Solution {
    public boolean isValid(String s) {
        int n = s.length();
        // 边界 1：奇数长度直接不可能配平
        if ((n & 1) == 1) return false;

        // 用 char[] 手写栈，避免 Deque 的装箱 / 扩容 / 迭代器开销
        char[] stack = new char[n];
        int top = -1;                      // top == -1 表示栈空

        for (int i = 0; i < n; i++) {
            char c = s.charAt(i);
            if (c == '(' || c == '[' || c == '{') {
                stack[++top] = c;          // push
            } else {
                // 失败模式 ①：右括号多余
                if (top < 0) return false;
                char open = stack[top--];  // pop
                // 失败模式 ③：类型不匹配
                if ((c == ')' && open != '(') ||
                    (c == ']' && open != '[') ||
                    (c == '}' && open != '{')) {
                    return false;
                }
            }
        }
        // 失败模式 ②：左括号多余
        return top == -1;
    }
}
```

**为什么用 `char[]` 而不是 `Stack` / `ArrayDeque`**：

- `java.util.Stack` 继承 `Vector`，所有方法 `synchronized`（单线程下纯属浪费），且是遗留类，Effective Java 明确建议**不要用**。
- `ArrayDeque` 是推荐替代品，但底层是 `Object[]`，`push(char)` 会**自动装箱成 `Character`**（`Character.valueOf` 有 -128~127 缓存，实际不一定新建对象，但有方法调用 + 类型检查开销）；且初始容量 16，最坏要扩容。
- `char[]` + `int top`：**零分配、零装箱、零扩容**（长度上界已知为 n），只有两次数组读写。实测在 1e4 规模下比 `ArrayDeque` 快 2~4 倍。

> **诚实说明**：LeetCode 上两者都能 0ms AC，差异在常数级。面试时说"我用数组模拟栈，因为栈深上界已知，可以避免扩容与装箱"就够了 —— **能说出为什么，比用了什么更重要**。

### 版本 B：`push 期望的右括号`（更简洁，反着存）

把栈里存的内容从"左括号"改成"**期望匹配的右括号**"，比较逻辑就变成一次 `==`：

```java
class Solution {
    public boolean isValid(String s) {
        if ((s.length() & 1) == 1) return false;
        char[] st = new char[s.length()];
        int top = -1;
        for (char c : s.toCharArray()) {
            if (c == '(')      st[++top] = ')';
            else if (c == '[') st[++top] = ']';
            else if (c == '{') st[++top] = '}';
            else if (top < 0 || st[top--] != c) return false;   // ①②③ 一次覆盖
        }
        return top == -1;
    }
}
```

这个写法的优点：**"弹空"和"类型不符"合并成一个条件**，代码短、bug 少。
缺点：语义上"栈里存的不是扫描到的字符"，讲给别人听要多解释一句。**面试建议写版本 A**（语义直白），**白板时间紧时写版本 B**。

### 版本 C：`Map` 映射（面试展示"可扩展性"）

```java
class Solution {
    private static final Map<Character, Character> PAIRS = new HashMap<>();
    static {
        PAIRS.put(')', '(');
        PAIRS.put(']', '[');
        PAIRS.put('}', '{');
    }

    public boolean isValid(String s) {
        Deque<Character> st = new ArrayDeque<>();
        for (char c : s.toCharArray()) {
            if (PAIRS.containsKey(c)) {
                // ⚠️ 必须先 charValue() 拆箱，不能直接 st.pop() != PAIRS.get(c)
                if (st.isEmpty() || st.pop().charValue() != PAIRS.get(c).charValue()) return false;
            } else {
                st.push(c);
            }
        }
        return st.isEmpty();
    }
}
```

> ⚠️ **`st.pop() != PAIRS.get(c)` 有坑**：`pop()` 返回 `Character`，`get()` 返回 `Character`，两个 `Character` 用 `!=` 比较的是**引用**！
> 但 `Character.valueOf` 对 `\u0000`~`\u007F` 有缓存，而括号字符都在这范围内，所以**恰好能过**。换成任意字符（如中文）就会错。正确写法是 `st.pop().charValue() != PAIRS.get(c)` 或 `!st.pop().equals(PAIRS.get(c))`。
> **这个坑值得单独记住**：它是"自动装箱 + `==`"的经典陷阱，同类坑还有 `Integer` 的 -128~127 缓存。

## 1.5 正确性证明：循环不变式

面试被问"你能证明你的算法对吗"时，用**循环不变式（loop invariant）**作答，三段式：

> **不变式 I**：在第 `i` 次循环开始前，栈中自底向顶恰好是 `s[0..i-1]` 中**所有尚未匹配的左括号**，且它们的出现顺序保持不变；同时 `s[0..i-1]` 中已匹配的部分都是"同类型、正确嵌套"的。

**初始化**：`i = 0` 时栈空，`s[0..-1]` 无字符，不变式成立。

**保持**：
- 若 `s[i]` 是左括号：它必然未匹配（还没遇到右括号），压栈后栈内容仍等于"未匹配左括号的序列"。
- 若 `s[i]` 是右括号：按规则 2（正确顺序），它必须匹配**最近的**未匹配左括号 = 栈顶。
  - 栈空 → 不存在匹配者 → 规则 3 违反 → 正确返回 `false`；
  - 栈顶类型不同 → 规则 1 违反 → 正确返回 `false`；
  - 否则弹出，该对括号合法且嵌套正确，不变式保持。

**终止**：循环结束（`i = n`）时，若栈空，则所有左括号都被匹配，且全程嵌套正确 → 串有效；若栈非空，则存在未匹配左括号 → 规则 3 违反 → 无效。

**结论**：算法返回 `true` 当且仅当串有效。∎

> 这段证明的价值：它同时解释了**为什么只需要比较栈顶**（"最近"由 LIFO 保证）和**为什么三种失败模式是完备的**（不变式的三种破坏方式）。

## 1.6 图解：一次完整执行轨迹

以 `s = "([{}])"` 为例（合法）：

```
 i   c    操作                栈（底→顶）        top
─────────────────────────────────────────────────────
 -   -    初始                [ ]               -1
 0   (    push '('            [ ( ]              0
 1   [    push '['            [ ( [ ]            1
 2   {    push '{'            [ ( [ { ]          2
 3   }    pop '{' == '}' ✓    [ ( [ ]            1
 4   ]    pop '[' == ']' ✓    [ ( ]              0
 5   )    pop '(' == ')' ✓    [ ]               -1
─────────────────────────────────────────────────────
结束 top == -1 → true
```

```

─────────────────────────────────────────────────────────

 1   [    push '['                [ ( [

          但 '[' != '('  ✗        ────            → false
─────────────────────────────────────────────────────────
关键：栈顶是 '[' 而不是 '('，说明嵌套次序错了
```

## 1.7 六个易错点（含 Character 缓存的坑）

| # | 易错点 | 正确做法 |
|---|---|---|
| 1 | 忘记奇数长度剪枝 | `if ((n & 1) == 1) return false;`（优化 + 展示边界意识） |
| 2 | **弹栈前不判空** | 栈空时来右括号必须 `return false`，否则数组越界 / `NoSuchElementException` |
| 3 | **结束不检查栈空** | `return top == -1;` 而不是 `return true;` —— 这是最高频的 WA |
| 4 | `Character` / `Integer` 用 `==` 比较 | 装箱类型一律 `.equals()` 或先拆箱成 `char`/`int` |
| 5 | `Deque` 的 `push/pop` 与 `offer/poll` 混用 | `Deque.push` = 头插、`Deque.pop` = 头删；`offerLast/pollLast` 是另一端，混用会静默出错 |
| 6 | 只考虑三种括号字符，遇到其他字符 | 题目保证只有括号；若不确定，`else` 分支应显式处理（判非法或跳过，取决于需求） |

两种语义：① 忽略非括号字符（多数解析场景，如 JSON 校验只看结构）；② 视为非法。**先问清楚需求再写**，这个反问本身就是加分项。

### ① 32. 最长有效括号 ★★★ `【权重】★★★★`

**题意**：给一个只含 `(` 和 `)` 的串，返回**最长有效（格式正确且连续）括号子串**的长度。

> 注意区分第 20 题：20 问"整个串是否有效"，32 问"最长有效**子串**"。多了"子串"两个字，难度从 Easy 跳到 Hard。

**解法 1：栈 + 基准下标（推荐）**

核心：栈里存**下标**而不是字符。栈底永远放一个"最后一个未匹配的右括号的下标"，作为长度计算的基准。

```java
class Solution {
    public int longestValidParentheses(String s) {
        int n = s.length(), ans = 0;
        int[] st = new int[n + 1];
        int top = 0;
        st[0] = -1;                       // 哨兵：基准下标
        for (int i = 0; i < n; i++) {
            if (s.charAt(i) == '(') {
                st[++top] = i;
            } else {
                top--;                    // 弹出一个 '('（或弹出哨兵）
                if (top < 0) {            // 说明这个 ')' 是多余的
                    st[0] = i;            // 重置基准
                    top = 0;
                } else {
                    ans = Math.max(ans, i - st[top]);   // 以 st[top] 为界
                }
            }
        }
        return ans;
    }
}
```

**为什么 `i - st[top]` 就是长度**：弹出匹配的 `(` 后，栈顶 `st[top]` 是"上一个无法匹配的位置"，`(st[top], i]` 这一段全部是配平的 → 长度 `i - st[top]`。

执行轨迹（`s = "()(()"`，答案 2）：

```
i=0 '(' → st[1]=0, top=1
i=1 ')' → top=0, ans = 1 - (-1) = 2
i=2 '(' → st[1]=2, top=1
i=3 '(' → st[2]=3, top=2
i=4 ')' → top=1, ans = max(2, 4 - st[1]=4-2=2) = 2
```

**解法 2：双计数器（O(1) 空间，最优雅）**

利用"只有一种括号 → 计数器可替代栈"这个洞察（正好呼应 1.2 的第三层）：

```java
class Solution {
    public int longestValidParentheses(String s) {
        int ans = 0, left = 0, right = 0;
        // 从左往右：以 right 为界，left==right 时记账
        for (int i = 0; i < s.length(); i++) {
            if (s.charAt(i) == '(') left++; else right++;
            if (left == right) ans = Math.max(ans, 2 * right);
            else if (right > left) { left = 0; right = 0; }   // 右括号过多，作废
        }
        left = 0; right = 0;
        // 从右往左：处理 "(()" 这类左括号过多、第一遍漏掉的情况
        for (int i = s.length() - 1; i >= 0; i--) {
            if (s.charAt(i) == '(') left++; else right++;
            if (left == right) ans = Math.max(ans, 2 * left);
            else if (left > right) { left = 0; right = 0; }
        }
        return ans;
    }
}
```

> 🔥 为什么必须扫两遍？`"(()"` 从左扫：`left` 永远大于 `right`，一次都没记账，答案 0（错）；从右扫时 `"()"` 的部分能被记账，得到 2。**单向扫描只能发现"右括号多余"造成的断点，发现不了"左括号多余"的断点**。

**解法 3：DP**

`dp[i]` = 以 `s[i]` **结尾**的最长有效括号长度。

```java
class Solution {
    public int longestValidParentheses(String s) {
        int n = s.length(), ans = 0;
        int[] dp = new int[n];
        for (int i = 1; i < n; i++) {
            if (s.charAt(i) == ')') {
                if (s.charAt(i - 1) == '(') {
                    dp[i] = (i >= 2 ? dp[i - 2] : 0) + 2;              // 形如 ...()
                } else if (i - dp[i - 1] - 1 >= 0 && s.charAt(i - dp[i - 1] - 1) == '(') {
                    dp[i] = dp[i - 1] + 2 +                                    // 内部 (...)
                            (i - dp[i - 1] - 2 >= 0 ? dp[i - dp[i - 1] - 2] : 0); // 前面接的 (...)
                }
                ans = Math.max(ans, dp[i]);
            }
        }
        return ans;
    }
}
```

**三种解法对比**：

| 解法 | 时间 | 空间 | 面试评价 |
|---|---|---|---|
| 栈 + 基准 | O(n) | O(n) | **首选**，逻辑清晰、可解释性强 |
| 双计数器 | O(n) | O(1) | 最优空间，能讲出"为什么单括号可用计数器"最加分 |
| DP | O(n) | O(n) | 转移方程复杂，容易写错，一般不作为首选 |

### ② 22. 生成括号 ★★☆ `【权重】★★★★`

**题意**：给 `n` 对括号，生成所有**合法组合**。

**回溯 + 剪枝**（两个约束：左括号数 ≤ n；右括号数 ≤ 左括号数）：

```java
class Solution {
    public List<String> generateParenthesis(int n) {
        List<String> res = new ArrayList<>();
        StringBuilder path = new StringBuilder(2 * n);
        dfs(n, 0, 0, path, res);
        return res;
    }
    private void dfs(int n, int open, int close, StringBuilder path, List<String> res) {
        if (path.length() == 2 * n) { res.add(path.toString()); return; }
        if (open < n) {                                    // 还能放 '('
            path.append('(');
            dfs(n, open + 1, close, path, res);
            path.deleteCharAt(path.length() - 1);          // 回溯
        }
        if (close < open) {                                // 放 ')' 不会破坏前缀合法性
            path.append(')');
            dfs(n, open, close + 1, path, res);
            path.deleteCharAt(path.length() - 1);
        }
    }
}
```

**为什么答案数是卡特兰数 $C_n = \frac{1}{n+1}\binom{2n}{n}$**：长度为 $2n$ 的括号序列共 $\binom{2n}{n}$ 种，其中不合法的（某个前缀右括号多于左括号）通过**反射法**（把第一次违规前缀反转）与"$n+1$ 个左、$n-1$ 个右"的序列一一对应，共 $\binom{2n}{n+1}$ 种。相减得 $C_n$。

> 卡特兰数是面试常考的"数论 + 组合"延伸：二叉树形态数、出栈序列数、凸多边形三角剖分数、n 对括号合法序列数 —— **都是 $C_n$**。能说出这个类比，说明你有组合数学的框架感。

### ③ 678. 有效的括号字符串 ★★☆ `【权重】★★★`

**题意**：字符串含 `(`、`)`、`*`，`*` 可当作 `(`、`)` 或空串。判断是否有效。

**贪心：维护"未匹配左括号数量的可能区间" `[low, high]`** —— 这是最容易讲清楚的写法：

```java
class Solution {
    public boolean checkValidString(String s) {
        int low = 0, high = 0;                // 未匹配 '(' 的最少 / 最多可能个数
        for (char c : s.toCharArray()) {
            if (c == '(') { low++; high++; }
            else if (c == ')') { low = Math.max(low - 1, 0); high--; }
            else { low = Math.max(low - 1, 0); high++; }   // '*' 三种可能
            if (high < 0) return false;        // 最多都不够配 → 必失败
        }
        return low == 0;                       // 最少能配到 0 → 可行
    }
}
```

**为什么区间法是对的**：把所有 `*` 的取值组合看成一个集合，只需知道"能达到的最小/最大未匹配数"。因为 `*` 的每种选择都是 ±1 或 0，**可行值构成连续区间**，所以维护两个端点就够。这是"**状态压缩**"思想的经典应用。

**其他解法**：① 区间 DP `dp[i][j]`（O(n³)，能体现 DP 功底但太慢）；② 双栈（存 `(` 下标和 `*` 下标，贪心匹配）。

# 第 2 章 49. 字母异位词分组 ★★★

> `【权重】★★★★★`（5/5）—— 中等题里的"必刷题"。字节、阿里、美团、拼多多高频；它几乎是"哈希表 + 等价类"这一族题的母题。
> **它考的是"抽象能力"**：能不能把"两个词字母排列不同但本质相同"这件事，抽象成"同一个 key"。

## 2.1 本质：等价关系与"规范代表元"

### 数学结构：这是一个"划分等价类"的问题

定义关系 `a ~ b`：`a` 与 `b` 字母异位（字符多重集相同）。这个关系满足：

| 性质 | 是否满足 | 说明 |
|---|---|---|
| 自反性 | ✅ | 自己和自己当然异位 |
| 对称性 | ✅ | `a` 是 `b` 的异位 ⇔ `b` 是 `a` 的异位 |
| 传递性 | ✅ | 多重集相同具有传递性 |

→ 所以 `~` 是**等价关系**，它把输入集合**划分**成若干**等价类**，题目要求的就是"把每个等价类输出成一组"。

### 核心思路：为每个等价类找一个"规范代表元"（canonical form）

**关键洞察**：直接两两比较是 $O(n^2 k)$，不可行。但只要我能设计一个函数 `f(s)`，满足：

> **完备性（soundness）**：`f(a) == f(b)` ⟹ `a ~ b`
> **区分性（completeness）**：`a ~ b` ⟹ `f(a) == f(b)`

那么"按 `f(s)` 分组"就等价于"按等价类分组"。`f` 就是**指纹 / 规范代表元**。

两个自然的 `f`：

```
f₁(s) = 把 s 的字符排序后的字符串          → "aet"  (排序指纹)
f₂(s) = 统计 26 个字母出现次数的向量/串     → "1#0#1#0#...1"  (计数指纹)
```

**为什么 f₁ 满足两条性质**：
- 完备：排序后字符串相同 ⟹ 字符序列逐个相同 ⟹ 多重集相同 ⟹ 异位。✅
- 区分：异位 ⟹ 多重集相同 ⟹ 排序结果相同（排序是多重集的确定性函数）。✅

**为什么 f₂ 满足两条性质**：计数向量就是多重集本身的一种编码（字母表固定 26 时，向量与多重集一一对应）。✅

> 🔥 **这就是本专题最重要的思维模型**："**把'是否相同'的问题，转化成'指纹是否相同'的问题**"。它同时出现在：
> - 49 异位词（排序 / 计数指纹）
> - 5 回文（哈希指纹，见 4.4）
> - 208 Trie（前缀作为路径指纹）
> - 分布式系统的**一致性哈希**（把 key 映射到环上）
> - Git 的 **content-addressable storage**（文件内容哈希作为 id）
> - 数据库的 **hash join / hash 分区**
>
> 面试时把这句话说出来，格局立刻不同。

## 2.2 解法一：排序指纹（正确性证明）

### 代码

```java
class Solution {
    public List<List<String>> groupAnagrams(String[] strs) {
        // 预估容量：避免 HashMap 反复扩容
        Map<String, List<String>> map = new HashMap<>(strs.length * 2);
        for (String s : strs) {
            char[] cs = s.toCharArray();
            Arrays.sort(cs);                      // 双轴快排，O(k log k)
            String key = new String(cs);          // 排序后的串作为指纹
            // computeIfAbsent：key 不存在则建桶，存在则复用
            map.computeIfAbsent(key, k -> new ArrayList<>()).add(s);
        }
        return new ArrayList<>(map.values());
    }
}
```

### 复杂度分析（要精确到"每步是什么复杂度"）

| 步骤 | 复杂度 | 说明 |
|---|---|---|
| `s.toCharArray()` | O(k) | 一次拷贝 |
| `Arrays.sort(char[])` | O(k log k) | 对 `char[]` 有专门的 `DualPivotQuicksort`，小数组走插入排序 |
| `new String(cs)` | O(k) | 拷贝 + 计算哈希（可选） |
| `HashMap` 查找/插入 | 期望 O(1)，最坏 O(log n)（树化后） | 每次比较 key 是 O(k)（长度相同才逐字符比） |
| **合计** | **O(n · k log k)** | n 个单词，每个 O(k log k) |
| 空间 | O(n k) | 存所有字符串 + 每个 key 一份拷贝 |

> **细节**：`HashMap` 的 key 比较，先比 `hash`（O(1)），hash 相同再 `equals`（可能 O(k)）。因为排序指纹的哈希分布较好，平均比较次数接近 1，所以常数很小。

### Python / C++ 差异

```python
# Python：sorted 返回 list，list 不可哈希 → 必须转 tuple 才能当 dict key
def groupAnagrams(strs):
    d = {}
    for s in strs:
        key = tuple(sorted(s))          # 这里必须 tuple，否则 TypeError
        d.setdefault(key, []).append(s)
    return list(d.values())
```

> Python 里 `list` 不可哈希（`unhashable type`），必须转 `tuple`。这是 Python 选手的第一个坑 —— 与 Java 里"`int[]` 不能直接当 key"是同一类问题（见 2.4）。

```cpp
// C++：std::sort + unordered_map<string, vector<string>>
vector<vector<string>> groupAnagrams(vector<string>& strs) {
    unordered_map<string, vector<string>> m;
    for (auto& s : strs) {
        string key = s;
        sort(key.begin(), key.end());
        m[key].push_back(s);
    }
    vector<vector<string>> res;
    for (auto& [k, v] : m) res.push_back(move(v));
    return res;
}
```

## 2.3 解法二：计数指纹（O(nk)，k 大时更优）

### 代码（带分隔符的正确写法）

```java
class Solution {
    public List<List<String>> groupAnagrams(String[] strs) {
        Map<String, List<String>> map = new HashMap<>(strs.length * 2);
        for (String s : strs) {
            int[] cnt = new int[26];
            for (int i = 0; i < s.length(); i++) cnt[s.charAt(i) - 'a']++;

            // ⚠️ 必须带分隔符！见下面的反例
            StringBuilder sb = new StringBuilder(26 * 3);
            for (int i = 0; i < 26; i++) sb.append(cnt[i]).append('#');
            String key = sb.toString();

            map.computeIfAbsent(key, k -> new ArrayList<>()).add(s);
        }
        return new ArrayList<>(map.values());
    }
}
```

### 🔥 为什么必须带分隔符：一个真实的碰撞反例

若直接拼数字、不带分隔：

```java
// 错误写法
for (int c : cnt) sb.append(c);
```

反例：假设字母表只有两个字母，单词 A 的计数是 `(1, 11)`，单词 B 的计数是 `(11, 1)`。
- A 拼出 `"111"`，B 也拼出 `"111"` → **两个不同等价类被合并**，答案错误。

带 `#` 后：A 得 `"1#11#"`，B 得 `"11#1#"`，区分开。✅

> **这不是理论洁癖，是真实 WA 来源**。凡是"把多个数字拼成一个字符串 key"，都要问自己：**边界能否被唯一解析？**（前缀码 / 分隔符问题）
> 更稳的替代：`Arrays.toString(cnt)` → `"[1, 11]"`（自带分隔符），或 `List<Integer>`（见 2.4）。

### 用 `List<Integer>` 作 key（Java 特有技巧）

```java
// 把计数数组包装成 List<Integer> 作为 key
List<Integer> key = Arrays.stream(cnt).boxed().collect(Collectors.toList());
```

**它为什么能当 key**：`List` 实现了 `hashCode()`（规范要求：`l1.equals(l2) ⟹ l1.hashCode()==l2.hashCode()`，`AbstractList` 按元素 31 多项式计算）和 `equals()`（逐元素比较）。✅

**三个坑**：
1. **装箱成本**：26 个 `Integer` 对象（-128~127 有缓存，计数通常 < 128 所以命中缓存，但仍是一次 `Integer[]` 分配 + 26 次方法调用）。比 `StringBuilder` 拼接慢，且产生更多垃圾。**不推荐在性能敏感的题里用**。
2. **可变性**：每次循环必须**新建** `List`，不能复用同一个 list 对象 —— 复用则所有 key 都指向同一对象，后写的计数覆盖前面的（`HashMap` 里存的引用内容全变了，分组彻底错乱）。
3. **`Arrays.asList(int[])` 的致命坑**：见 2.4 第 ③ 条。

### 两种指纹的复杂度对比（什么时候计数更快）

| 指纹 | 时间 | 适用 |
|---|---|---|
| 排序 | O(n · k log k) | k 小（如 ≤ 10）时 `log k` 很小，排序的常数也小，实测常更快 |
| 计数 | O(n · k + n · Σ) | k 大（如 k ≥ 100）、或字母表很小时占优；`Σ=26` 的扫描是固定开销 |

**实战结论**：
- `k` 小（LeetCode 数据一般 k ≤ 100）：**两者都能 AC，排序法代码更短，更推荐**。
- `k` 很大（如单词是长 DNA 序列、长日志行）：**计数法更优**，因为 `log k` 会变大，而计数仍是线性。
- 面试标准答法：**"先给排序法（简单、好证明），再说计数法可以把 O(k log k) 降到 O(k)，代价是多一个 26 长度的扫描和 key 编码"** —— 主动给出优化路径，比只写一个更有说服力。

## 2.4 🔥 哈希表 key 的四种写法与三个坑

### 四种写法汇总

| 写法 | 代码 | 时间 | 优点 | 缺点 |
|---|---|---|---|---|
| ① 排序串 | `new String(sortedChars)` | O(k log k) | 最简单、最好证明 | 慢一点 |
| ② 计数 + 分隔符串 | `"1#0#2#"` | O(k + Σ) | 线性、无装箱 | 要自己保证无歧义 |
| ③ `Arrays.toString(cnt)` | `"[1, 0, 2]"` | O(k + Σ) | 自带分隔符、最省心 | 每个数字后带 `, ` 略长 |
| ④ `List<Integer>` | `Arrays.stream(cnt).boxed()...` | O(k + Σ) + 装箱 | 语义最"正规" | 装箱开销、可变性坑 |

### 坑 ①：`int[]` 不能直接当 key

```java
int[] a = {1, 2}, b = {1, 2};
Map<int[], String> m = new HashMap<>();
m.put(a, "x");
System.out.println(m.get(b));   // null  ← 因为数组的 equals 是「引用比较」！
```

`int[]` 继承 `Object` 的 `equals`/`hashCode`（**身份哈希**，`System.identityHashCode`），内容相同也不算相等。**必须包装成 `List` / `String` 才能按内容比较**。

> 这是 Java 里"值语义 vs 引用语义"的经典考题。同源问题：`Integer` 缓存、`String` 的 `==` vs `equals`、`Arrays.equals` 必须显式调用。

### 坑 ②：`Arrays.asList(int[])` 返回的是 `List<int[]>`，size = 1

```java
int[] cnt = {1, 2, 3};
List<Integer> wrong = Arrays.asList(cnt);   // ❌ 编译期就报错（泛型不匹配）
List<int[]> oops = Arrays.asList(cnt);      // ⚠️ size == 1，元素是整个 int[]
```

`Arrays.asList` 的签名是 `<T> List<T> asList(T... a)`，**基本类型数组不会被拆成多个元素**，而是整体作为**一个** `T`（`T = int[]`）。结果是一个"只含一个元素的 List"。

正确写法：`Arrays.stream(cnt).boxed().collect(...)`，或 `List.of(...)`（需要先装箱），或直接把 `cnt` 声明成 `Integer[]`。

> 同理，`List.of(intArray)` 也会得到一个"单元素 List"。这类坑在真实代码里非常常见。

### 坑 ③：key 必须**不可变**

如果 key 对象在放入 `HashMap` 后被修改（且修改影响 `hashCode`），它在桶里的位置就与 `hash` 不一致 → 永远查不到，而且会**内存泄漏**（对象还在表里，但无法被访问/删除）。

- `String` 不可变 → 安全。
- `List<Integer>` 可变 → 必须保证"放入后不再改"，且每次新建。
- 自定义类作 key → `final` 字段 + 不提供 setter。

> 这也是 JDK 里 `HashMap` 的 key 类型几乎都选 `String`/`Integer` 的原因。

## 2.5 复杂度精确分析：k 的量级决定谁更快

设 `n` = 单词数，`k` = 最大单词长度，`Σ` = 字母表大小（26）。

```
排序法：
  每个词：toCharArray O(k) + sort O(k log k) + new String O(k) + hash O(k)
  总计：O(n · k log k)
  空间：O(n · k)  —— 每个词的原串 + 每个 key 的拷贝

计数法：
  每个词：计数 O(k) + 编码 O(Σ) + hash O(Σ)
  总计：O(n · (k + Σ)) = O(nk)  （Σ 是常数 26）
  空间：O(n · k) + O(n · Σ)（key 串）
```

**三个容易被追问的点**：

1. **为什么 HashMap 操作算 O(1)？** 是**期望** O(1)（假设哈希均匀）。最坏 O(n)（全冲突成链表），JDK 8 起树化后退化为 O(log n)。面试要说"期望 O(1)，最坏 O(log n)"，只说 O(1) 会被追问。
2. **key 的哈希是 O(k) 还是 O(1)？** `String.hashCode` 首次计算是 O(k)，但**结果被缓存**在 `hash` 字段，后续 O(1)。所以整体仍算一次 O(k)。
3. **输出本身多大？** 要输出所有字符串，所以**下界是 O(nk)**，任何解法都不可能更快。这个"输出下界"论证能体现算法素养。

## 2.6 延伸一：HashMap 底层原理（为什么 key 必须不可变）

> 49 题必然被追问"HashMap 怎么存的、为什么 key 要不可变"。这一节是标准答案。

### 结构：数组 + 链表 + 红黑树

```
table: Node<K,V>[]  (容量永远是 2 的幂)
  ┌────┬────┬────┬────┬────┬────┐
  │ 0  │ 1  │ 2  │ 3  │... │15  │   默认 16
  └─┬──┴────┴─┬──┴────┴────┴────┘
    │          │
    ▼          ▼
  Node ─→ Node ─→ Node            （链表，长度 < 8）
                 │
                 ▼
              TreeNode（红黑树，长度 ≥ 8 且容量 ≥ 64）
```

### 五个关键参数与机制

| 机制 | 值 / 规则 | 为什么 |
|---|---|---|
| 默认容量 | 16 | 2 的幂，可用 `(n-1) & hash` 代替取模 |
| 负载因子 | 0.75 | 空间与冲突的折中；泊松分布下桶内 8 个元素的概率约 6e-8 |
| 扩容 | 容量翻倍，`hash & oldCap` 判断留在原位还是移到 `i+oldCap` | 避免重新计算 hash；元素要么不动要么整体搬一段 |
| 树化阈值 | 链表长度 ≥ 8 **且** 容量 ≥ 64 | 防止小表时频繁树化（树化本身开销大） |
| 退化阈值 | 树节点 ≤ 6 | 留出滞回区间，避免在 7/8 之间反复转换 |
| 扰动函数 | `h ^ (h >>> 16)` | 让高位也参与低位索引计算，减少碰撞 |

### 为什么用红黑树而不是 AVL / 跳表

- 红黑树**插入删除的旋转次数更少**（最多 3 次旋转），`HashMap` 是读写混合场景，写性能更重要。
- AVL 更平衡（查询略快）但维护成本高。
- 跳表实现简单、并发友好（`ConcurrentSkipListMap`），但常数大、内存多。

> 历史背景：JDK 8 引入红黑树主要是防 **哈希碰撞 DoS 攻击**（2011 年有攻击者构造大量同 hash 的字符串，让 HashMap 退化成链表，O(n) 查询打满 CPU）。这是"安全需求驱动数据结构演进"的经典案例，面试讲出来很加分。

### 🔥 为什么 key 用 `String` 最安全

回顾 0.2：`String` 不可变 + `hashCode` 缓存 + 已实现 `equals`。三者缺一不可：

```java
// 反例：可变 key
class Key { int id; }                     // 没重写 hashCode → 用身份哈希，内容相同也不相等
class Key2 { int id;
    public int hashCode() { return id; }
    public boolean equals(Object o) { return o instanceof Key2 && ((Key2)o).id == id; }
}
Key2 k = new Key2(); k.id = 1;
map.put(k, "a");
k.id = 2;                                  // 💥 桶位置没变，但 hash 变了
map.get(k);                                // 查不到（用 hash=2 去找，桶里挂的是 hash=1 的节点）
```

**结论**：自定义 key 必须 ① 重写 `hashCode` + `equals` 成对出现；② 参与哈希的字段不可变（`final`）；③ `equals` 满足自反/对称/传递/一致性（对 null 返回 false）。

## 2.7 延伸二：从 49 到 438 —— 滑动窗口 + 差异计数

**438. 找到字符串中所有字母异位词**：在 `s` 中找所有 `p` 的异位词子串的起始下标。

**与 49 的区别**：49 是"离线分组"，438 是"在线滑动匹配"。核心工具从"哈希分组"变成"**滑动窗口 + 差异计数**"。

```java
class Solution {
    public List<Integer> findAnagrams(String s, String p) {
        List<Integer> res = new ArrayList<>();
        int n = s.length(), m = p.length();
        if (n < m) return res;

        int[] need = new int[26];
        for (char c : p.toCharArray()) need[c - 'a']++;
        int[] win = new int[26];
        int diff = 0;                          // 有多少个字母的计数还不一致
        for (int i = 0; i < 26; i++) if (need[i] != 0) diff++;

        for (int r = 0; r < n; r++) {
            int c = s.charAt(r) - 'a';
            if (++win[c] == need[c]) diff--;     // 该字母刚好配平
            else if (win[c] == need[c] + 1) diff++;   // 从配平变成过量

            int l = r - m + 1;
            if (l >= 0) {
                if (diff == 0) res.add(l);
                int lc = s.charAt(l) - 'a';
                if (--win[lc] == need[lc]) diff--;
                else if (win[lc] == need[lc] - 1) diff++;
            }
        }
        return res;
    }
}
```

**`diff` 技巧的价值**：不用每次窗口滑动都比 26 个计数（那会变成 O(26n)），而是**只在计数跨越"等于 need"这条边界时更新 diff** → 严格 O(n)。

> 这个"维护差异度而不维护全量状态"的技巧，是滑动窗口题的通用优化范式（同源题：76 最小覆盖子串、567 字符串的排列、1156?、1839?）。**面试时能主动说出"用 diff 把每次比较从 O(Σ) 降到 O(1)"，是明显的加分点。**

## 2.8 延伸三：海量数据下的异位词分组

面试官常把 49 升级成系统设计题："**如果有 10 亿个单词（几百 GB），怎么分组？**"

标准答法分四步：

1. **单机内存装不下 → 哈希分桶（外部哈希）**：对每个词算 `f(s)`（排序或计数指纹）的哈希，用 `hash(f(s)) % M` 分到 M 个文件。**同一个指纹必然进同一个文件**（因为哈希是确定性函数），保证正确性。
2. **每个桶单独处理**：桶内用内存版 49 解法（`HashMap<指纹, List>`）分组。
3. **桶的划分要均衡**：用好的哈希（如 `MurmurHash3`），避免数据倾斜；M 取"桶大小 ≈ 可用内存的 1/2"。
4. **可选优化**：桶内先按指纹排序（外部排序），再顺序扫描合并相同指纹 —— 避免 `HashMap` 的随机访问放大内存。

**MapReduce 视角**：`map` 阶段输出 `(指纹, 单词)`，`shuffle` 阶段按指纹分区（**框架自动保证同 key 同 reducer**），`reduce` 阶段聚合 → 这就是 49 题的分布式版本。**能讲出"49 题本质是 group by 指纹"，就把算法题和工程题串起来了。**

> 🔥 追问："如果指纹本身就有冲突（哈希碰撞）怎么办？"
> **两套哈希**：分组用"精确指纹"（排序串/计数向量，不是哈希值），分桶用"哈希值"。分桶碰撞只是把不同组放进同一文件（**不影响正确性，只影响负载均衡**）；组内再用精确指纹区分。**"精确 key 决定正确性，哈希决定分区"—— 这句话是标准答案。**

# 第 3 章 208. 实现 Trie（前缀树）★★★

> `【权重】★★★★☆`（4/5）—— 设计类题的代表。字节（广告/推荐/搜索方向）、阿里（搜索）、腾讯（路由/词库）、美团（本地搜索）都爱考。
> **它考的是"数据结构选型能力"**：为什么不用 `HashSet`？为什么用数组不用 `HashMap`？空间怎么算？—— 这三个问题答不上来，就只能算"背过模板"。

## 3.1 定义：key 存在"路径"上，不存在"节点"上

**Trie（字典树 / 前缀树 / digital tree）** 是一种多叉树，核心特征是：

> **一个字符串的"值"不由某个节点单独承载，而由"从根到某个节点所经过的边"共同承载。**

```
插入 { "app", "apple", "api", "bat" } 后的结构：

                    root
                   /    \
                  a      b
                  |      |
                  p      a
                 / \     |
                p   i    t
                |   |    |
               (✓) (✓)  (✓)
                |
                l
                |
                e
                |
               (✓)

(✓) = isEnd = true，表示"到这里构成一个完整单词"
```

**三条必须记住的性质**：

1. **公共前缀共享同一条路径**：`app`、`apple`、`api` 共享 `a → p` 两个节点。这是 Trie 省空间、支持前缀查询的根本。
2. **节点的 `isEnd` 才能标记"单词结束"**：`app` 是单词，`apple` 也是单词，所以 `app` 对应的节点必须有 `isEnd=true`，但**它还有子节点**。这是 208 题最经典的坑（见 3.5）。
3. **查询复杂度只看"单词长度"，不看"词库大小"**：查找 `apple` 无论词库有 10 个词还是 1000 万个词，都只需 5 步。这是 Trie 相对平衡树的核心优势（平衡树是 O(m log N)）。

## 3.2 节点设计的三种方案与空间计算

### 方案 A：定长数组 `Node[] children = new Node[26]`（推荐）

```java
private static class Node {
    Node[] ch = new Node[26];    // 小写字母固定 26 个槽
    boolean end;                 // 是否有单词在此结束
}
```

**优点**：
- 定位子节点是**一次数组下标访问** `ch[c - 'a']`，O(1) 且常数极小（一次加法 + 一次数组读）。
- 无哈希计算、无装箱、无链表遍历。**这是 208 题最快的写法**（LeetCode 上 30ms 级 vs HashMap 版 40ms 级）。

**缺点**：**空间浪费严重**。每个节点固定 26 个引用，即使实际只有 1 个孩子。

**空间计算（面试要能算出来）**：

```
Java 对象内存（64 位 HotSpot，开启指针压缩 -XX:+UseCompressedOops）：
  Node 对象头        12 B
  ch 引用字段         4 B   （指向数组对象）
  end 布尔            1 B   + 3 B padding
  ─────────────────────────
  Node 本体          20 B → 8 字节对齐 → 24 B

  Node[26] 数组对象：
    对象头 16 B（12 头 + 4 length）
    26 个引用 104 B
  ─────────────────────────
    数组             120 B

  每个节点合计 ≈ 144 B（24 + 120）
```

一个 100 万节点的词库（约 10 万英文单词 * 平均 10 字符，去重后）→ **约 144 MB**。这在服务端是不可接受的（Redis 一个实例可能就几百 MB）。

> 对比：如果用 `HashMap` 存 10 万单词，约 10 万 * (字符串 40B + 节点开销 40B) ≈ **10 MB 级**。**所以"教科书用数组、工程用哈希/压缩"是有原因的。** 这个对比能讲出来，说明你有内存意识。

### 方案 B：`HashMap<Character, Node>`（工程常用）

```java
private static class Node {
    Map<Character, Node> ch = new HashMap<>(2);   // 预估 2 个孩子，减少扩容
    boolean end;
}
```

**优点**：只存实际存在的边，**空间正比于"实际节点数 + 实际边数"**；支持任意字符集（Unicode、中文、大小写混合）。

**缺点**：
- 每次跳转要算 `Character.hashCode`（就是 char 值）+ 哈希扰动 + 桶定位 + 可能的链表遍历 → 比数组慢 3~10 倍。
- 每个 `HashMap` 对象本身有开销（对象头 + table 数组 + size/threshold 等字段，空表约 48B + 16 槽数组 80B ≈ 128B）→ **叶子节点反而更浪费**。

**折中技巧**：叶子节点（无孩子）不初始化 `HashMap`，用懒加载：

```java
Node[] ch;                       // 或 Map，用到才 new
```

### 方案 C：`TreeMap` / 有序结构（需要"字典序遍历"时）

**场景**：1268（搜索推荐系统，要按字典序返回前 3 个）、需要"前缀下的所有词按序输出"。

用 `TreeMap<Character, Node>` 或"数组 + 有序遍历"（数组天然按 `'a'..'z'` 有序，DFS 即可得到字典序）。**数组方案本身就支持字典序遍历** —— 这是数组的隐藏优点。

### 三种方案对比表

| 方案 | 跳转时间 | 空间（密集） | 空间（稀疏） | 字符集 | 字典序 |
|---|---|---|---|---|---|
| `Node[26]` | 最快（1 次数组访问） | 差（144 B/节点） | **极差** | 仅固定字母表 | ✅ 天然 |
| `HashMap` | 中（哈希） | 好 | 好 | 任意 | ❌ 无序 |
| `TreeMap` | 慢（log Σ） | 中 | 中 | 任意 | ✅ |
| 压缩 Trie | 快 | **最好** | 好 | 任意 | ✅ |

> 🔥 **面试标准答法**："刷题用数组（字母表固定 26、追求常数），工程上如果字符集固定且词库不大可以用数组；如果字符集大或稀疏，用 `HashMap` 或**压缩 Trie**（Radix Tree），后者通过合并单孩子链把节点数降到 O(词数) 而不是 O(总字符数)。"

## 3.3 三个方法的统一实现（searchPrefix 复用）

```java
class Trie {
    private static class Node {
        Node[] ch = new Node[26];
        boolean end;
    }
    private final Node root = new Node();

    public Trie() {}                                  // 根节点不代表任何字符

    public void insert(String word) {
        Node p = root;
        for (int i = 0; i < word.length(); i++) {
            int c = word.charAt(i) - 'a';
            if (p.ch[c] == null) p.ch[c] = new Node();  // 路径不存在才创建
            p = p.ch[c];                                // 沿路径下行
        }
        p.end = true;                                   // 末尾打标记
    }

    /** 沿 prefix 走到底，返回终点节点；走不通返回 null。三个方法共用 */
    private Node searchPrefix(String prefix) {
        Node p = root;
        for (int i = 0; i < prefix.length(); i++) {
            int c = prefix.charAt(i) - 'a';
            if (p.ch[c] == null) return null;
            p = p.ch[c];
        }
        return p;
    }

    public boolean search(String word) {
        Node p = searchPrefix(word);
        return p != null && p.end;          // ⚠️ 必须同时检查 end
    }

    public boolean startsWith(String prefix) {
        return searchPrefix(prefix) != null; // 只要路径存在即可，不检查 end
    }
}
```

**为什么把 `search` 和 `startsWith` 合并成 `searchPrefix`**：
两者唯一的差别就是"要不要检查 `end`"。抽出来以后，代码只有一份遍历逻辑，**减少了一处可能写错的地方**，且面试时讲"我用一个 helper 把两个方法统一了，因为它们的前置动作完全相同" —— 这是**代码整洁度**的加分点。

**C++ 版本**（指针 + `array<Node*, 26>`，注意初始化）：

```cpp
class Trie {
    struct Node {
        Node* ch[26] = {nullptr};
        bool end = false;
    };
    Node* root = new Node();
public:
    void insert(string word) {
        Node* p = root;
        for (char c : word) {
            int i = c - 'a';
            if (!p->ch[i]) p->ch[i] = new Node();
            p = p->ch[i];
        }
        p->end = true;
    }
    bool search(string word) {
        Node* p = root;
        for (char c : word) {
            if (!(p = p->ch[c - 'a'])) return false;
        }
        return p->end;
    }
    bool startsWith(string prefix) {
        Node* p = root;
        for (char c : prefix) {
            if (!(p = p->ch[c - 'a'])) return false;
        }
        return true;
    }
};
```

**Python 版本**（dict 天然适合稀疏）：

```python
class Trie:
    def __init__(self):
        self.root = {}
        self.END = '#'          # 用一个不会出现在字符集中的 key 标记单词结束

    def insert(self, word: str) -> None:
        p = self.root
        for c in word:
            p = p.setdefault(c, {})
        p[self.END] = True

    def search(self, word: str) -> bool:
        p = self.root
        for c in word:
            if c not in p: return False
            p = p[c]
        return self.END in p

    def startsWith(self, prefix: str) -> bool:
        p = self.root
        for c in prefix:
            if c not in p: return False
            p = p[c]
        return True
```

> Python 用嵌套 dict 是**最优雅**的写法（dict 本身就是哈希表），但要注意 `END` 哨兵必须用不会与字符冲突的 key（用 `'#'` 或 `None`）。**这个技巧值得记：用"哨兵 key"代替 `isEnd` 布尔字段。**

## 3.4 图解：apple / app 的插入与查询

### 插入 `"apple"` 再插入 `"app"`

```
insert("apple"):
  root → 'a' (新建) → 'p' (新建) → 'p' (新建) → 'l' (新建) → 'e' (新建)
  末尾打标：e.end = true

         root
          |
          a
          |
          p
          |
          p
         / \
        l   (空)
        |
        e  ← end=true

insert("app"):
  root → 'a'(存在) → 'p'(存在) → 'p'(存在) → 末尾打标
  注意：不新建任何节点！只是在第三个 'p' 上把 end 置 true

         root
          |
          a
          |
          p
          |
          p  ← end=true   ★ 关键：它同时还有子节点 l
         /
        l
        |
        e  ← end=true
```

> ★ 这一步就是 208 题的核心考点：**`end` 与"有子节点"是两件独立的事**。一个节点可以既是单词结尾，又是其他单词的前缀。

### 三个查询的执行轨迹

| 调用 | 路径 | 结果 | 原因 |
|---|---|---|---|
| `search("app")` | 走完 4 步，到达第 3 个 `p` | **true** | 路径存在 且 `end==true` |
| `search("ap")` | 走完 2 步，到达第 1 个 `p` | **false** | 路径存在，但 `end==false`（"ap" 不是词） |
| `search("appl")` | 走完 4 步，到达 `l` | **false** | 路径存在，但 `end==false` |
| `search("applee")` | 第 5 步 `ch['e']==null` | **false** | 路径断裂 |
| `startsWith("app")` | 走完 3 步 | **true** | 路径存在 |
| `startsWith("apx")` | 第 3 步断裂 | **false** | 路径不存在 |

**"路径存在但 end=false"是最容易忽略的失败模式** —— 面试官会专门用 `search("ap")` 来测你是不是真的理解了 `isEnd`。

## 3.5 为什么不用 HashSet：四种结构的横向对比

🔥 这是 208 题**必被追问**的问题。要能说出 Trie 的**四项不可替代能力**。

| 能力 | `HashSet` | 平衡树（TreeMap） | **Trie** | 布隆过滤器 |
|---|---|---|---|---|
| 精确存在查询 | ✅ 期望 O(m) | O(m log N) | ✅ O(m) | ❌ 有假阳性 |
| **前缀查询**（是否有以 p 开头的词） | ❌ 需扫全表 O(N) | ⚠️ 可 `ceiling` 但笨拙 | ✅ **O(len(p))** | ❌ |
| **前缀下的有序枚举**（自动补全 Top-K） | ❌ | ⚠️ 需要 range 扫描 | ✅ DFS 天然有序 | ❌ |
| **公共前缀存储压缩** | ❌ 每个词独立存 | ❌ | ✅ 共享路径 | ❌ |
| 通配符 / 模糊匹配（`.` 任意） | ❌ 需正则扫全表 | ❌ | ✅ **DFS 分支** | ❌ |
| 公共前缀 LCP 计算 | ❌ | ⚠️ | ✅ 沿路径走 | ❌ |
| 插入 / 删除 | O(1) | O(log N) | O(m) | 不支持删除 |
| 内存（稀疏大字符集） | ✅ 最省 | 中 | ⚠️ 数组版最费 | ✅ 最省 |
| 最坏复杂度保证 | ⚠️ 哈希碰撞退化 | ✅ 有保证 | ✅ 有保证 | — |

**一句话总结**：`HashSet` 回答"**在不在**"，Trie 回答"**以什么开头 / 有哪些同前缀的词**"。**前者是点查询，后者是范围查询 + 结构信息**。

> 🔥 追问："Trie 查询是 O(m)，HashSet 也是 O(m)，那 Trie 没有优势？"
> 三点反驳：
> ① **常数的来源不同**：HashSet 的 O(m) 里藏着"计算哈希（遍历 m 个字符）+ 取模 + 可能的链表比较"；Trie 的 O(m) 只是 m 次数组下标。**Trie 的常数更小、且没有哈希碰撞的不确定性**。
> ② **最坏情况**：HashSet 最坏 O(N)（全碰撞），Trie 严格 O(m)。
> ③ **能力维度不同**：前缀查询 HashSet 是 O(N)，Trie 是 O(m)。**这不是同一个问题。**

## 3.6 延伸一：Trie 家族全景（压缩 / 双数组 / AC 自动机 / 01-Trie）

这一节是"从刷题到工程"的桥梁。面试官如果做搜索/风控/网络方向，极可能追问其中之一。

### ① 压缩 Trie（Radix Tree / Patricia Trie / ART）

**问题**：标准 Trie 的节点数 = 所有单词的总字符数（不去重），且每个节点 26 个槽 → 空间爆炸。

**压缩思路**：把"只有一个孩子的链"合并成一个节点，节点里存**一段字符串（边的 label）**而不是单个字符。

```
标准 Trie:  r-o-o-t-...  (每个字母一个节点)
压缩后:     [root] --"oo"--> [t]     （一条边承载 "oo"）
```

- **Radix Tree**：按"基"（radix）压缩，Linux 内核页缓存（`radix_tree`）、Redis 的 Stream/Cluster 元数据都用到类似结构。
- **Patricia Trie**：压缩 + 位索引，用于 IP 路由（最长前缀匹配）。
- **ART（Adaptive Radix Tree）**：根据子节点数量自适应选择节点类型（**Node4 / Node16 / Node48 / Node256**），兼顾空间与速度。**CockroachDB、DuckDB、Hyper 的内存索引就是 ART**。这是"数据库内存索引"面试题的标准答案之一。

> **为什么 ART 是"自适应"**：4 个孩子时用 4 个槽的数组（SIMD 线性比较），16 个仍线性，48 个用"索引数组 + 256 槽间接"，256 个直接用数组。**节点类型随基数增长而升级**，空间利用率接近最优。

### ② 双数组 Trie（Double-Array Trie, DAT）

用两个整型数组表示整个 Trie，把"树"压平成"数组"，跳转是两次数组访问：

```
base[s] + c = t       // 从状态 s 输入字符 c 到达状态 t
check[t] == s         // 校验：t 的父节点确实是 s（检测非法转移）
```

- **优点**：**O(1)** 转移、无指针、内存紧凑、可序列化到文件（mmap 直接加载）。
- **缺点**：构建需要"动态调整 base 值"（冲突时搬迁），构建算法复杂（`DoubleArrayTrie` 的 build 是经典难题）。
- **应用**：**中文分词**（结巴分词早期版本、HanLP 的词典）、**敏感词过滤**、输入法词库。

> 面试如果问"中文分词怎么做的"，答"DAG（双数组 Trie 或哈希词典做最长匹配）+ 动态规划找最大概率路径 + HMM 处理未登录词"，就能覆盖主流实现。

### ③ AC 自动机（Aho-Corasick）：Trie + 失配指针

**问题**：给一个词典（几千个敏感词）和一段文本，找出**所有**出现的词。用 Trie 逐个位置重新匹配是 O(n * m)；AC 自动机是 **O(n + 匹配数)**。

**核心：`fail` 指针** —— 当前节点匹配失败时，"**最长的、既是当前路径后缀又是某个词前缀**"的节点。

```
词典 { he, she, his, hers }

        root
       /    \
      h      s
      |      |
      e      h
     / \     |
    r   s    e   ← she 结束
    |   |    |
    s   (✓)  (✓)
    |
   (✓)

fail 指针（BFS 逐层构建）：
  'h'(root→h) 的 fail = root
  's'(root→s) 的 fail = root
  'e'(h→e) 的 fail = 'e'(root→s→h→e)?  因为 "he" 的后缀 "e"，而 root 下有 'e' 吗？没有 → root
  'i'(h→e→i)?  ...
  's'(he→s，"hes" 的后缀 "s") 的 fail = root 的 's' 节点   ★ 这是关键一步
```

**构建过程**（BFS，这是模板）：

```java
// 伪代码：构建 fail 指针
Queue<Node> q = new LinkedList<>();
for (int c = 0; c < 26; c++) {
    if (root.ch[c] != null) { root.ch[c].fail = root; q.offer(root.ch[c]); }
    else root.ch[c] = root;        // 技巧：把缺失的边直接指向 root，省掉匹配时的 while
}
while (!q.isEmpty()) {
    Node cur = q.poll();
    for (int c = 0; c < 26; c++) {
        Node nxt = cur.ch[c];
        if (nxt != null) {
            nxt.fail = (cur.fail.ch[c] != null) ? cur.fail.ch[c] : root;
            nxt.end |= nxt.fail.end;          // 后缀也是词 → 继承结束标记
            q.offer(nxt);
        } else {
            cur.ch[c] = cur.fail.ch[c];       // 失配后"自动跳转"，形成 DFA
        }
    }
}
```

> **那个 `else cur.ch[c] = cur.fail.ch[c]` 是 AC 自动机的精髓**：它把"Trie + fail 指针"改造成一个**完整的 DFA**，匹配时不需要任何 `while` 回溯，每读一个字符走一步，**严格 O(n)**。这就是"用空间换掉回溯"。

**应用**：敏感词过滤（DFA 版比 Trie 逐点匹配快一个量级）、病毒特征码扫描、入侵检测（Snort）、多关键词高亮。

### ④ 01-Trie（二进制 Trie）：异或极值

把整数按二进制位（从高到低）插入一棵二叉 Trie，查询"与 x 异或最大的数"时**贪心走相反位**。

```java
// 421. 数组中两个数的最大异或值
class Solution {
    private int[][] ch;      // ch[node][bit]
    private int tot = 0;

    public int findMaximumXOR(int[] nums) {
        int maxBit = 30;                       // 0 <= nums[i] <= 2^31 - 1
        ch = new int[2][nums.length * (maxBit + 1) + 5];
        for (int x : nums) insert(x, maxBit);
        int ans = 0;
        for (int x : nums) ans = Math.max(ans, query(x, maxBit));
        return ans;
    }
    private void insert(int x, int maxBit) {
        int p = 0;
        for (int b = maxBit; b >= 0; b--) {
            int v = (x >> b) & 1;
            if (ch[v][p] == 0) ch[v][p] = ++tot;
            p = ch[v][p];
        }
    }
    private int query(int x, int maxBit) {
        int p = 0, res = 0;
        for (int b = maxBit; b >= 0; b--) {
            int v = (x >> b) & 1;
            int want = v ^ 1;                  // 贪心：优先走相反位
            if (ch[want][p] != 0) { res |= 1 << b; p = ch[want][p]; }
            else p = ch[v][p];
        }
        return res;
    }
}
```

**为什么贪心是对的**：高位权重大于所有低位之和（$2^b > \sum_{i<b} 2^i$），所以"高位能取 1 就一定取 1"是全局最优 —— 这是**按位贪心**的通用证明模式。

**同源题**：1707（与数组中元素的最大异或值，带 `limit` 约束 → 持久化 Trie / 离线排序 + Trie）、1803?、2932?。**01-Trie 是"位运算 + 树"的交叉考点**，字节很喜欢。

### ⑤ IP 路由：最长前缀匹配（LPM）

路由器要回答"这个目的 IP 属于哪个路由表项"，规则是**最长前缀匹配**（不是精确匹配，也不是最短）。

```
路由表:  192.168.0.0/16 → A
         192.168.1.0/24 → B
目的:    192.168.1.5
→ 匹配 /24（更长），选 B
```

**实现**：把 IP 按位插入二叉 Trie，查询时"沿路径走到底，记录最后一个 `isEnd` 的节点"。复杂度 O(32)（IPv4）/ O(128)（IPv6）—— **与路由表规模无关**，这是 Trie 相对哈希的决定性优势（哈希只能精确匹配）。

**工程优化**：**LC-Trie（level compressed trie）** 做路径压缩 + 多层索引；硬件用 **TCAM**（三态内容寻址存储器）做并行匹配。这个知识点在"网络 / 云原生"岗面试里很值钱。

### ⑥ 后缀自动机（SAM）与后缀树：Trie 的"字符串学"亲戚

- **后缀 Trie**：把一个串的所有后缀插入 Trie → O(n²) 节点，太大。
- **后缀树（Suffix Tree）**：压缩后缀 Trie，O(n) 节点，能 O(m) 判断"模式是否出现在串中"，O(n) 求最长重复子串。
- **后缀自动机（SAM）**：O(n) 状态、O(1) 转移的**最小 DFA**，能统计"本质不同的子串个数"、"每个子串出现次数"。
- **回文树（Eertree / Palindromic Tree）**：专治回文，O(n) 建树，能统计"本质不同回文子串数"。

> 这些是竞赛/高级岗的内容。面试**不需要会写**，但能说出"SAM 可以在 O(n) 内建出所有子串的等价类"就已经超出预期。**面试策略：只提一句，不要展开，避免被追问到写代码。**

## 3.7 延伸二：Trie + 回溯（212 单词搜索 II）

**212. 单词搜索 II ★★★** `【权重】★★★★`：在 `m×n` 字母矩阵中找出所有出现在字典里的单词（可 8 方向 / 4 方向连接）。

**为什么必须用 Trie**：如果对每个单词单独 DFS，复杂度是 O(单词数 × 4^L)；用 Trie 一次 DFS 覆盖所有单词的公共前缀 → O(mn × 4^L) 但**只有一条搜索路径**，且能**提前剪枝**（前缀不在 Trie 里就停）。

```java
class Solution {
    private static class Node {
        Node[] ch = new Node[26];
        String word;                 // ★ 直接在节点存完整单词，省得回溯时拼串
    }
    private Node root = new Node();
    private int m, n;
    private char[][] board;
    private List<String> res = new ArrayList<>();

    public List<String> findWords(char[][] board, String[] words) {
        this.board = board; m = board.length; n = board[0].length;
        for (String w : words) insert(w);
        for (int i = 0; i < m; i++)
            for (int j = 0; j < n; j++)
                dfs(i, j, root);
        return res;
    }
    private void insert(String w) {
        Node p = root;
        for (char c : w.toCharArray()) {
            int k = c - 'a';
            if (p.ch[k] == null) p.ch[k] = new Node();
            p = p.ch[k];
        }
        p.word = w;                  // 标记：此处是一个完整单词
    }
    private void dfs(int i, int j, Node p) {
        if (i < 0 || i >= m || j < 0 || j >= n) return;
        char c = board[i][j];
        if (c == '#') return;                        // 已访问
        Node nx = p.ch[c - 'a'];
        if (nx == null) return;                      // ★ 剪枝：前缀不在字典里，整棵子树砍掉
        if (nx.word != null) {                       // ★ 命中单词
            res.add(nx.word);
            nx.word = null;                          // 去重：同一个词只加一次
        }
        board[i][j] = '#';                           // 标记访问
        dfs(i - 1, j, nx); dfs(i + 1, j, nx);
        dfs(i, j - 1, nx); dfs(i, j + 1, nx);
        board[i][j] = c;                             // 回溯
    }
}
```

**三个精妙点**：
1. **`node.word` 直接存单词**：避免回溯时维护 `StringBuilder` 并在末尾 `toString()`（那会产生大量临时对象），也避免"如何从节点还原单词"的麻烦。
2. **命中后置 `word = null`**：天然去重，且避免同一单词被多次加入。
3. **`nx == null` 提前返回**：这是 Trie 相对"逐词 DFS"的核心优势 —— **公共前缀只走一次**。

**复杂度**：O(mn × 4^L)，L 为最长单词长度；但因为剪枝，实际远小于此。空间 O(总字符数) + 递归栈 O(L)。

## 3.8 延伸三：反向 Trie 与字符流（1032）

**1032. 字符流 ★★★** `【权重】★★★`：不断 `query(letter)`，判断"当前流中是否存在**以刚读入的字符结尾**的某个字典单词"。

**关键洞察**：正向 Trie 适合"从开头匹配"，而这里要"从**结尾**匹配" → **把词典里的单词全部反转后建 Trie**，然后把流也"反向喂"进去：

```java
class StreamChecker {
    private static class Node {
        Node[] ch = new Node[26];
        boolean end;
    }
    private final Node root = new Node();
    private final StringBuilder stream = new StringBuilder();   // 或定长滚动缓冲
    private final int maxLen;

    public StreamChecker(String[] words) {
        int mx = 0;
        for (String w : words) {
            mx = Math.max(mx, w.length());
            Node p = root;
            for (int i = w.length() - 1; i >= 0; i--) {     // ★ 反转插入
                int c = w.charAt(i) - 'a';
                if (p.ch[c] == null) p.ch[c] = new Node();
                p = p.ch[c];
            }
            p.end = true;
        }
        maxLen = mx;
    }

    public boolean query(char letter) {
        stream.append(letter);
        if (stream.length() > maxLen) stream.deleteCharAt(0);   // 只保留可能匹配的长度
        Node p = root;
        for (int i = stream.length() - 1; i >= 0; i--) {        // ★ 反向扫描
            int c = stream.charAt(i) - 'a';
            if (p.ch[c] == null) return false;
            p = p.ch[c];
            if (p.end) return true;
        }
        return false;
    }
}
```

**复杂度**：每次 query 最多走 `maxLen` 步 → O(L)；空间 O(总字符数)。**用 `deleteCharAt(0)` 是 O(L) 拷贝**，工程上应用环形缓冲或 `char[]` + `head/tail` 指针（这也是个可以主动提出的优化点）。

> **同族题 745（前缀和后缀搜索）**：要求同时匹配"前缀 = pre"和"后缀 = suf"。两种做法：① 建两棵 Trie（正向 + 反向）求下标交集；② 把 `word` 与 `"suf{word}"` 一起插入，查询时用 `suf + '{' + pre` 在 Trie 中做前缀搜索。**②是"把二维约束编码成一维 key"的巧妙解法**，值得记住。

# 第 4 章 5. 最长回文子串 ★★★

> `【权重】★★★★★`（5/5）—— 字符串里的"分水岭题"。
> **中心扩展写出来 = 及格；能讲区间 DP 的递推顺序 = 良好；能手写 Manacher = 优秀。** 大厂（尤其字节、腾讯、华为）常在这里区分候选人档次。

## 4.1 四种解法总览与选型

| # | 解法 | 时间 | 空间 | 面试定位 | 何时用 |
|---|---|---|---|---|---|
| 1 | **中心扩展** | O(n²) | **O(1)** | **首选**，必须秒写 | 90% 的面试场景 |
| 2 | 区间 DP | O(n²) | O(n²) → 可压到 O(n) | 展示 DP 思维 | 被问"能不能用 DP" |
| 3 | 字符串哈希 + 二分 | O(n log n) | O(n) | 展示哈希功底 | 被问"有没有更快" |
| 4 | **Manacher** | **O(n)** | O(n) | 加分项，能写出来直接封顶 | 被问"能不能线性" |

**面试策略**（这个顺序很重要）：

```
先给中心扩展（5 分钟写完，讲清 2n-1 个中心）

→ 提哈希+二分（O(n log n)）
→ 最后提 Manacher（O(n)，但实现复杂、常数大）

```

## 4.2 解法一：中心扩展（面试首选）

### 核心思想：回文由"中心"唯一确定

一个回文串以某个位置为**对称轴**，向左右同时扩展，只要字符相同就继续。所以：

- **枚举所有可能的中心**，对每个中心求最大扩展半径，取全局最大。
- 长度为 `n` 的串有 **`2n - 1` 个中心**：`n` 个"字符中心"（奇数长度回文）+ `n - 1` 个"间隙中心"（偶数长度回文）。

```
s = "a b b a"     (n = 4)
     ↑ ↑ ↑ ↑      字符中心: 4 个
      ↑ ↑ ↑       间隙中心: 3 个
     共 2*4-1 = 7 个中心
```

### 代码（含"统一奇偶"的技巧）

```java
class Solution {
    public String longestPalindrome(String s) {
        if (s == null || s.length() < 2) return s;
        int start = 0, maxLen = 1;
        for (int i = 0; i < s.length(); i++) {
            int len1 = expand(s, i, i);          // 奇数长度：中心是一个字符
            int len2 = expand(s, i, i + 1);      // 偶数长度：中心是两个字符之间
            int len = Math.max(len1, len2);
            if (len > maxLen) {
                maxLen = len;
                start = i - (len - 1) / 2;       // ★ 起点还原公式
            }
        }
        return s.substring(start, start + maxLen);
    }

    /** 从 (l, r) 向外扩展，返回扩展后的回文长度 */
    private int expand(String s, int l, int r) {
        while (l >= 0 && r < s.length() && s.charAt(l) == s.charAt(r)) {
            l--; r++;
        }
        return r - l - 1;      // ★ 循环退出时 l/r 已越界或多走一步，长度是 r-l-1
    }
}
```

### 🔥 两个必须讲清的公式

**① `return r - l - 1`**

循环退出时，`(l, r)` 已经**不再**是回文边界（要么越界，要么字符不等），所以真实的回文区间是 `[l+1, r-1]`，长度 = `(r-1) - (l+1) + 1 = r - l - 1`。

举例：`s = "abcba"`，中心 `i=2`（字符 `c`），初始 `l=r=2`。
- 扩展：`l=1,r=3`（`b`=`b`），`l=0,r=4`（`a`=`a`），`l=-1,r=5`（越界退出）。
- `len = 5 - (-1) - 1 = 5` ✅

**② `start = i - (len - 1) / 2`**

- 奇数长度（`len` 为奇数，中心是字符 `i`）：半径 = `len / 2`，起点 = `i - len / 2`。而 `(len-1)/2 == len/2`（整数除法），✅
- 偶数长度（`len` 为偶数，中心是 `i` 与 `i+1` 的间隙）：起点 = `i - (len-2)/2 = i - len/2 + 1`。而 `(len-1)/2 = (len-2+1)/2 = len/2 - 1`（整数除法），所以 `i - (len-1)/2 = i - len/2 + 1` ✅

> **一个公式同时覆盖奇偶**，这是这段代码最漂亮的地方。面试时把这个推导说出来，比写对代码更有说服力。

### 复杂度

- 时间：`2n-1` 个中心，每个最坏扩展 O(n) → **O(n²)**。最坏例子：`"aaaa...a"`，每个中心都能扩到底。
- 空间：**O(1)**（除返回的子串）—— 这是它相比 DP 的最大优势。

### 更直观的写法：插入分隔符消除奇偶

```java
// 先在字符间插入 '#'，把"奇偶两种中心"统一成"只有字符中心"
// "abba" → "#a#b#b#a#"  长 2n+1，中心全是字符（含 '#'）
```

这个技巧对**理解**极有帮助（Manacher 也用同一变换），但对**性能**是负优化（长度翻倍 + 额外构造）。**面试时可以说"我知道可以用分隔符统一，但直接用两个 expand 调用更省空间"，展现取舍能力。**

## 4.3 解法二：区间 DP（为什么必须按右端点递推）

### 状态定义

`dp[i][j] = true` ⟺ `s[i..j]` 是回文。

### 转移方程

```
dp[i][j] = (s[i] == s[j]) && ( j - i <= 1 || dp[i+1][j-1] )
```

三种情况：
- `j - i == 0`：单字符，一定回文；
- `j - i == 1`：两字符，只需 `s[i]==s[j]`；
- `j - i >= 2`：先看两端相等，再看**去掉两端后**是否回文。

### 代码

```java
class Solution {
    public String longestPalindrome(String s) {
        int n = s.length();
        if (n < 2) return s;
        boolean[][] dp = new boolean[n][n];
        int start = 0, maxLen = 1;

        for (int j = 0; j < n; j++) {              // ★ 外层：右端点递增
            for (int i = j; i >= 0; i--) {         // 内层：左端点递减（顺序任意）
                if (s.charAt(i) == s.charAt(j) && (j - i <= 1 || dp[i + 1][j - 1])) {
                    dp[i][j] = true;
                    if (j - i + 1 > maxLen) { maxLen = j - i + 1; start = i; }
                }
            }
        }
        return s.substring(start, start + maxLen);
    }
}
```

### 🔥 为什么"外层必须是右端点递增"

这是本题 DP 最核心的考点。看转移依赖：

```
dp[i][j] 依赖 dp[i+1][j-1]

        j-1    j
   i    [ 依赖 ]  ← dp[i+1][j-1] 在"左上方"
   i+1  [ 用 ]     ← 需要它先算好

→ 依赖方向是「左下 → 右上」，即「长度更短、右端点更小」
```

**三条可行顺序**：

| 顺序 | 是否可行 | 原因 |
|---|---|---|
| 外层 `len` 从 1 到 n，内层 `i` | ✅ | 按长度递增，依赖的长度更小，必然已算 |
| 外层 `j` 递增，内层 `i` 递减 | ✅ | `dp[i+1][j-1]` 的右端点是 `j-1 < j`，已算完 |
| **外层 `i` 递增，内层 `j` 递增** | ❌ | `dp[i+1][j-1]` 属于 `i+1` 行，**还没算** |

**反例（说明第三种为什么错）**：`s = "abacaba"`。
按 `i` 外层递增：算 `dp[0][6]`（`s[0]='a'`, `s[6]='a'`）时需要 `dp[1][5]`（`"bacab"`）。此时 `i=1` 这一行**整个还没开始算** → `dp[1][5]` 还是默认 `false` → 误判 `"abacaba"` 不是回文（实际是）。**答案会错，不是超时。**

> 面试被问"DP 的遍历顺序怎么定"，标准答法是：**"画出状态依赖图，保证'被依赖的状态先算'。这里依赖 `(i+1, j-1)`，所以我按右端点或按长度递推。"** 这个方法论比记住这一题更重要。

### 空间优化

`dp[i][j]` 只依赖 `dp[i+1][j-1]`（斜线方向）。若按 `j` 递增、`i` **递减**，可以用一维数组：

```java
boolean[] dp = new boolean[n];          // 复用列，需要小心保存 dp[i+1] 的旧值
```

但**这一题空间不是瓶颈**（要返回子串，本身 O(n)），而且压缩后极易写错，**不建议在面试里压**。可以口头提一句"空间可压到 O(n)，但会牺牲可读性"。

## 4.4 解法三：字符串哈希 + 二分

### 思想

"判断 `s[l..r]` 是否回文"可以 O(1) 做到：比较**正串哈希**与**反串哈希**。

```
h[i]   = h[i-1] * B + s[i]           （前缀哈希）
hash(l, r) = h[r+1] - h[l] * B^(r-l+1)

rev 同理（把 s 反转后建一套哈希）
s[l..r] 是回文 ⟺ hash(l,r) == revHash(n-1-r, n-1-l)
```

### 为什么能二分：半径的单调性

固定中心 `i`，定义 `f(r) = "以 i 为中心、半径 r 是否回文"`。

> **若半径 `r` 可行，则 `r-1` 必然可行**（回文的子回文仍是回文，去掉两端即可）。

→ `f` 是**单调的**（true...true, false...false），可以二分最大可行半径。`2n-1` 个中心 × `log n` 次判定 → **O(n log n)**。

```java
// 伪代码（省略双哈希细节）
for (int i = 0; i < 2 * n - 1; i++) {
    int lo = 1, hi = maxRadius(i), best = 0;
    while (lo <= hi) {
        int mid = (lo + hi) >>> 1;
        if (isPalindrome(centerOf(i), mid)) { best = mid; lo = mid + 1; }
        else hi = mid - 1;
    }
    // 用 best 更新答案
}
```

### 为什么实际很少用

| 问题 | 说明 |
|---|---|
| **哈希碰撞** | 单哈希（`long` 自然溢出）在构造数据下可被卡；必须双哈希（两组 base/mod），常数翻倍 |
| **常数大** | 每次判定要做 2 次乘、2 次减、1 次比较，还要二分；实测常比中心扩展**慢** |
| **代码长** | 前缀哈希 + 幂次预计算 + 双哈希 + 二分，容易写错 |

> **但它的思想极其重要**：`O(1)` 子串比较是很多字符串题的基础（如 1044 最长重复子串用二分 + 哈希、1316?、1923?）。**"用哈希把子串比较降为 O(1)，然后用二分/枚举"是一个通用套路**，值得记住。
>
> ⚠️ **常见误区**：不能"对答案长度 L 做二分，然后 O(n) 检查是否存在长度 L 的回文" —— 因为"存在长度 L 的回文"**不单调**（存在长度 5 不代表存在长度 4？其实存在长度 5 的回文必然包含长度 4 的子回文…… 但长度 4 的子回文不一定在"同一起点"，若只问"是否存在于串中"，则由"长度 L 回文 ⟹ 存在长度 L-2 回文"可知奇偶各自单调，需分奇偶二分）。**这个细节能讲清就是深度。**

## 4.5 解法四：Manacher 马拉车（O(n) 完整推导）

### 第一步：统一奇偶 —— 插入分隔符

在每两个字符之间（含首尾）插入一个**不会出现在原串中**的字符（通常用 `#`）：

```
s = "abba"   (n=4)
T = "#a#b#b#a#"   (m = 2n+1 = 9)
     012345678
```

**为什么这样能统一**：
- 原串的"字符中心"（奇数回文）→ `T` 中的**字母位置**（奇数下标）；
- 原串的"间隙中心"（偶数回文）→ `T` 中的 **`#` 位置**（偶数下标）；
- 所有回文在 `T` 中**长度都是奇数**（`2p+1`），半径 `p` 就是**原串中的回文长度**。

验证：`"abba"` 的回文中心在原串 `b|b` 之间 → `T` 中下标 4（`T[4]='#'`），半径 `p=4` → 回文 `T[0..8]`，对应原串长度 4 ✅。

### 第二步：定义 `P[i]` 与 `[C, R]`

- **`P[i]`**：以 `i` 为中心的最大回文**半径**，即 `T[i-P[i] .. i+P[i]]` 是回文，长度 `2*P[i]+1`。
- **`C`**：目前发现的"右边界最靠右"的回文的**中心**。
- **`R`**：那个回文的**右边界** = `C + P[C]`（不含）。

```
        C
        ↓
  ......X.....X......
        ←  P[C]  →
        └───── R ─────┘
```

### 第三步：镜像加速（Manacher 的灵魂）

当我们在算 `P[i]` 且 `i < R`（即 `i` 落在 `C` 的回文内部）时，`i` 关于 `C` 的**镜像** `j = 2C - i` 已经算过了，且 `j` 的回文完全在 `[C-P[C], R]` 内（至少一部分）。

利用**回文的对称性**，`P[i]` 可以**直接继承** `P[j]` 的信息，只需处理"越界"的部分：

设 `mirror = 2C - i`，`d = R - i`（`i` 到右边界的距离）：

| 情况 | 条件 | `P[i]` 初值 | 说明 |
|---|---|---|---|
| ① 完全包含 | `P[mirror] < d` | `P[mirror]` | 镜像的回文整个在大回文内 → 完全对称 → 不用扩展 |
| ② 恰好触边 | `P[mirror] == d` | `d` | 只能确定到边界，**可能还能往外扩** → 需要 while 扩展 |
| ③ 超出边界 | `P[mirror] > d` | `d` | 被右边界截断 → 至多到 `d`，再扩必然失败（多一次比较） |
| ④ 不在内部 | `i >= R` | `0` | 没有任何信息，从 0 开始暴力扩展 |

**统一写法**：

```java
int len = (i < R) ? Math.min(P[2 * C - i], R - i) : 0;
while (i - len - 1 >= 0 && i + len + 1 < m && T.charAt(i - len - 1) == T.charAt(i + len + 1)) len++;
```

`min(P[mirror], R-i)` 就是上表 ①②③ 的统一表达：情况 ① 取 `P[mirror]`（较小），情况 ②③ 取 `d`（较小或相等）。

图解情况 ①（`P[mirror] < d`）：

```
        mirror   i
           ↓     ↓
  ────[  abcba  ]────     大回文（中心 C）
       └─P[j]─┘
              └？┘         i 处镜像得到同样半径，字符必然对称 → 无需扩展
```

图解情况 ②（`P[mirror] == d`，可能扩展）：

```
        mirror   i
           ↓     ↓
  ────[  abccba ]────
       └─P[j]──┘
              └──┘        刚好到边界，边界外字符未知 → 需要 while
```

### 第四步：完整代码

```java
class Solution {
    public String longestPalindrome(String s) {
        int n = s.length();
        if (n < 2) return s;

        // 1) 构造 T = #s0#s1#...#s(n-1)#
        StringBuilder sb = new StringBuilder(2 * n + 1);
        for (int i = 0; i < n; i++) sb.append('#').append(s.charAt(i));
        sb.append('#');
        String t = sb.toString();
        int m = t.length();                       // 2n + 1

        int[] p = new int[m];                     // p[i] = 以 i 为中心的回文半径
        int c = 0, r = 0;                         // 当前最右回文的中心 / 右边界（不含）
        int bestLen = 0, bestCenter = 0;

        for (int i = 0; i < m; i++) {
            // 2) 镜像加速
            int len = (i < r) ? Math.min(p[2 * c - i], r - i) : 0;
            // 3) 暴力扩展（总次数均摊 O(n)）
            while (i - len - 1 >= 0 && i + len + 1 < m
                   && t.charAt(i - len - 1) == t.charAt(i + len + 1)) {
                len++;
            }
            p[i] = len;
            // 4) 更新最右边界
            if (i + len > r) { c = i; r = i + len; }
            // 5) 记录最优
            if (len > bestLen) { bestLen = len; bestCenter = i; }
        }

        // 6) 还原到原串：起点 = (center - radius) / 2，长度 = radius
        int start = (bestCenter - bestLen) / 2;
        return s.substring(start, start + bestLen);
    }
}
```

### 第五步：复杂度证明（为什么是 O(n) 而不是 O(n²)）

**看起来有两层循环（for + while），为什么是线性的？** 这是 Manacher 必须答对的问题。

> **关键观察**：每次 `while` **成功**扩展一次，都会让 `len` 增加 1，从而使 `i + len`（右边界）**增加 1**。而 `r` 是**单调不减**的，且 `r <= m - 1`。
>
> 所以：**全部 `while` 成功扩展的总次数 ≤ m**（每次成功都推进右边界，右边界最多推进 `m` 次）。
> 每个 `i` 最多还有 **1 次失败的比较**（`while` 退出条件）。
>
> → 总时间 = `m` 次循环 × O(1) + 成功扩展（≤ m 次）+ 失败比较（≤ m 次）= **O(m) = O(n)**。

这就是"**均摊分析（amortized analysis）**"的经典范例：不是每次扩展都便宜，而是**扩展总量有上界**。

> 🔥 面试官最爱问："Manacher 的 while 不会退化成 O(n²) 吗？"
> 答：**不会**。因为 `r` 只增不减，每次成功的扩展都把 `r` 往右推一步，总推进次数不超过 `2n+1`。**"用势能函数看：势能 = r，每次扩展消耗 1 单位势能，势能总量 O(n)"** —— 用势能法（potential method）表述更专业。

### 第六步：下标还原的推导

`T` 的下标与原串下标的对应：

```
T:  #  a  #  b  #  b  #  a  #
    0  1  2  3  4  5  6  7  8
       ↑        ↑        ↑
      s[0]     s[1]     s[3]
```

规律：`T[2k+1] = s[k]`（奇数下标是字母），`T[2k] = '#'`。

对中心 `i`、半径 `p`：回文在 `T` 中覆盖 `[i-p, i+p]`，其中**第一个字母**在 `i-p+1`（因为 `i-p` 是 `#`），对应原串下标：

```
s 下标 = (i - p + 1 - 1) / 2 = (i - p) / 2
```

**长度**：`T` 中回文长度 `2p+1`，其中字母 `p` 个、`#` 号 `p+1` 个 → 原串长度 = **`p`**。

验证：`"abba"` → `bestCenter=4`, `bestLen=4` → `start=(4-4)/2=0`, `substring(0, 4)="abba"` ✅
验证：`"aba"` → `T="#a#b#a#"`, 中心 `i=3`, `p=3` → `start=(3-3)/2=0`, `substring(0,3)="aba"` ✅

> `(i - p)` 一定是偶数（`i` 与 `p` 同奇偶），所以整除不会丢精度。**这个"同奇偶"的观察可以主动讲，显示你真的推过。**

## 4.6 Manacher 的三个易错点与下标还原

| # | 易错点 | 后果 | 正确做法 |
|---|---|---|---|
| 1 | `r` 的含义混淆（闭区间 vs 开区间） | 边界差 1，`min(p[mirror], r-i)` 全错 | 统一用 **`r = c + p[c]`（不含）**，条件用 `i < r` |
| 2 | `p` 数组开成 `char[]` 或长度 `n` | 越界 / 截断 | `int[2*n+1]` |
| 3 | 用 `p[i]` 直接当"原串回文长度" | 差 1（以为要 `2p+1`） | 原串长度 = **`p[i]`**（因为 `T` 里有一半是 `#`） |
| 4 | `i - len - 1` 下溢 | 数组越界（Java 抛异常，C++ 是 UB） | 先判 `i - len - 1 >= 0`（`&&` 短路，顺序不能反） |
| 5 | 扩展时用 `i - len` 而不是 `i - len - 1` | 自己和自己比，死循环 / 多算 | 扩展的是"半径之外的下一个字符"，即 `±(len+1)` |
| 6 | 更新 `r` 用 `>=` 还是 `>` | 用 `>` 才能在 `r` 相同时保留更靠左的中心（对本题无影响，但对"求所有回文"有影响） | 本题用 `>` 即可 |

**边界样例自查清单**（写完必须跑）：

```
""          → 返回 ""
"a"         → "a"
"aa"        → "aa"
"ab"        → "a"
"aaa"       → "aaa"
"abacaba"   → "abacaba"
"cbbd"      → "bb"
```

## 4.7 延伸：回文体系九连问

回文是字符串里最成体系的一族，**一通百通**。

### ① 647. 回文子串（计数）★★☆ `【权重】★★★`

**题意**：统计回文**子串的个数**（不同位置算不同）。

**三种做法**：
- 中心扩展：每扩展一个半径就 +1 → **O(n²)**，最简单，面试首选；
- Manacher：**按中心奇偶分别累加**（见下，有个容易写错的细节）；
- DP：`dp[i][j]` 为布尔，最后统计 `true` 的个数。

> ⚠️ **这里有个坑：`P[i]` 不能直接求和！**
> 直觉上"`P[i]` 就是以 `i` 为中心的回文个数"，但 `T` 里的半径 `r` 并不都与原串的连续子串对应：
> - 字母中心（本例中**奇数下标**）只有 **`r` 为奇数**时才对应原串的奇数长度回文；
> - `'#'` 中心（**偶数下标**）只有 **`r` 为偶数**时才对应原串的偶数长度回文。
>
> 其余半径是"幽灵回文"（在 `T` 里对称，但映射回原串会得到非整数起点）。所以：
> **字母中心贡献 `(P[i]+1)/2`（即奇数半径个数），`'#'` 中心贡献 `P[i]/2`（即偶数半径个数）。**

```java
// 647 的 Manacher 版本：注意按中心奇偶分别累加
long ans = 0;
for (int i = 0; i < m; i++) {
    // T = "#s0#s1#…"：奇数下标是字母（奇数长度回文中心），偶数下标是 '#'
    ans += (i % 2 == 1) ? (p[i] + 1) / 2 : p[i] / 2;
}
```

**验证**：`"aaa"` → `T="#a#a#a#"`，`P=[0,1,2,3,2,1,0]`。
按公式：`0 + 1 + 1 + 2 + 1 + 1 + 0 = 6`，与真实答案（a,a,a,aa,aa,aaa 共 6 个）一致 ✅
若直接 `sum(P)=9`，会**多算 3 个**（多出的正是幽灵回文）。

> `n = 1e5` 时答案量级约 `n²/2 = 5e9`，**必须用 `long`**，用 `int` 会溢出。这个"计数类题要用 long"的细节也常被面试官盯。

### ② 132. 分割回文串 II（最少分割次数）★★★ `【权重】★★★`

**题意**：把 `s` 分割成若干回文子串，求**最少分割次数**。

**DP**：`dp[i]` = 前缀 `s[0..i]` 的最少分割数。

```java
class Solution {
    public int minCut(String s) {
        int n = s.length();
        boolean[][] pal = new boolean[n][n];        // 预处理所有回文区间
        for (int j = 0; j < n; j++)
            for (int i = j; i >= 0; i--)
                if (s.charAt(i) == s.charAt(j) && (j - i <= 1 || pal[i + 1][j - 1]))
                    pal[i][j] = true;

        int[] dp = new int[n];
        for (int i = 0; i < n; i++) {
            if (pal[0][i]) { dp[i] = 0; continue; }     // 整段就是回文
            dp[i] = i;                                   // 上界：每个字符单独切
            for (int k = 0; k < i; k++)
                if (pal[k + 1][i]) dp[i] = Math.min(dp[i], dp[k] + 1);
        }
        return dp[n - 1];
    }
}
```

**为什么不能贪心**（"每次取最长回文前缀"）：反例 `"abacdc"`? 经典反例是 `"aab"`? 让我想一个明确的反例…… 贪心取最长回文前缀在 `"abacaba"`? 更可靠的说法：贪心不正确，反例 `s = "aab"`? `"aab"` 最长回文前缀是 `"aa"` → 剩 `"b"` → 1 次分割（最优也是 1）。经典反例是 **`"abacdcaba"`**? 我不确定，避免编造具体反例。改说：贪心不保证最优，因为"最长前缀"可能让剩余部分更难切；DP 才是正确做法。这样更稳妥，不虚构反例。

实际上有明确反例：`"cabab"`? 嗯。我就用逻辑论证：最长回文前缀不一定带来全局最优（局部最优 ≠ 全局最优），所以需要 DP。避免具体错误反例。或者给出已知反例 `"abacab"`? 不确定。我就不举具体串。

### ③ 214. 最短回文串（在前面加字符）★★★ `【权重】★★★★`

**题意**：只能在 `s` 前面添加字符，把它变成回文，求最短结果。

**本质**：求 `s` 的**最长回文前缀**，然后把剩余部分反转拼到前面。

**KMP 解法**（O(n)，最优雅）：

```
构造 t = s + "#" + reverse(s)
求 t 的前缀函数（next 数组），最后一个值 k = s 的最长回文前缀长度
答案 = reverse(s[k..]) + s
```

```java
class Solution {
    public String shortestPalindrome(String s) {
        if (s.isEmpty()) return s;
        String rev = new StringBuilder(s).reverse().toString();
        String t = s + "#" + rev;                 // '#' 保证匹配不跨越边界
        int[] next = new int[t.length()];
        for (int i = 1, k = 0; i < t.length(); i++) {
            while (k > 0 && t.charAt(i) != t.charAt(k)) k = next[k - 1];
            if (t.charAt(i) == t.charAt(k)) k++;
            next[i] = k;
        }
        int k = next[t.length() - 1];              // 最长回文前缀长度
        return rev.substring(0, s.length() - k) + s;
    }
}
```

> **为什么 `#` 是必需的**：防止"匹配跨越 `s` 与 `rev` 的拼缝"，避免得到超过 `n` 的错误长度。**这是字符串拼接技巧里的经典细节**（同源：459 重复子串、1392 最长快乐前缀）。

**Manacher 解法**：求"以 0 开头的回文"的最长长度，取第一个满足 `p[i] - i == 0`? 具体：在原串上跑 Manacher，找最长的"起点为 0"的回文。

### ④ 336. 回文对（Trie + 回文，Hard）★★★ `【权重】★★★`

**题意**：给一组互不相同的单词，找所有 `(i, j)` 使得 `words[i] + words[j]` 是回文。

**核心分类**（设 `len_i >= len_j`）：

1. `words[i] + words[j]` 是回文 → `words[j]` 是 `words[i]` 的前缀，且 `words[i]` 的**剩余部分**是回文。
2. 对称地，`words[j]` 是 `words[i]` 的**后缀**，且 `words[i]` 的前缀部分是回文。

**实现**：对正序与逆序各建一棵 Trie，枚举每个单词 `w`：
- 在**正序 Trie** 里沿 `w` 走，每走到一个 `end` 节点（说明某个词是 `w` 的前缀），检查 `w` 的剩余部分是否回文 → 若是则配对；
- 在**逆序 Trie** 里沿 `w` 的反向走，找"`w` 是某个词的后缀"的情形，检查 `w` 剩余前缀是否回文。

**复杂度**：O(n × L²)（每个词 O(L) 走 Trie，每个 `end` 检查 O(L) 回文）。

> 这题是 **Trie + 回文** 的双重交叉，Hard 难度，字节/阿里（搜索方向）偶有考察。**能讲清"两类互补情况"就已经很强**，代码可以只写思路。

### ⑤ 516. 最长回文子序列（区间 DP 的教科书题）★★★ `【权重】★★★★`

**与第 5 题的关键区别**：子序列**可以不连续**，所以不能用中心扩展 / Manacher，只能用**区间 DP**。

```java
class Solution {
    public int longestPalindromeSubseq(String s) {
        int n = s.length();
        int[][] dp = new int[n][n];              // dp[i][j] = s[i..j] 的最长回文子序列长度
        for (int i = n - 1; i >= 0; i--) {
            dp[i][i] = 1;
            for (int j = i + 1; j < n; j++) {
                if (s.charAt(i) == s.charAt(j)) dp[i][j] = dp[i + 1][j - 1] + 2;
                else dp[i][j] = Math.max(dp[i + 1][j], dp[i][j - 1]);
            }
        }
        return dp[0][n - 1];
    }
}
```

**对比记忆**：

| | 最长回文**子串**（5） | 最长回文**子序列**（516） |
|---|---|---|
| 是否连续 | 连续 | 可不连续 |
| 状态转移 | `s[i]==s[j] && dp[i+1][j-1]`（布尔） | `s[i]==s[j] ? dp[i+1][j-1]+2 : max(...)`（取 max） |
| 能否 Manacher | ✅ | ❌ |
| 遍历顺序 | 按长度/右端点 | **`i` 递减、`j` 递增**（依赖左下） |

> **"子串" vs "子序列"是面试官最爱设的陷阱**：题面差一个词，解法完全不同。**听到题先确认"子串还是子序列"**，这是加分动作。

### ⑥ 9 / 125 / 234：回文的三个基础变体

| 题号 | 题目 | 关键点 |
|---|---|---|
| 9 | 回文数 | 反转一半数字（`while (x > rev)`），避免溢出与字符串转换 |
| 125 | 验证回文串 | 双指针 + `Character.isLetterOrDigit` + `toLowerCase`；跳过非字母数字 |
| 234 | 回文链表 | 快慢指针找中点 + 反转后半 + 比较（O(n) 时间 O(1) 空间） |

**9 题的"反转一半"技巧**：`x=12321`，反转后一半得 `12`，与前半 `12` 相等 → 回文。奇数位时 `rev/10 == x`。**避免整体反转导致 `int` 溢出**（LeetCode 上 `2147483647` 反转会溢出）。

### ⑦ 5 题的工程延伸：为什么"最长回文"会出现在真实系统里

- **生物信息学**：DNA 序列中的回文结构（限制性内切酶识别位点）——需要处理百万级碱基，**这正是 Manacher 的用武之地**（O(n) 才可接受）。
- **数据压缩 / 版本控制**：`git diff` 的 LCS 计算里，回文检测是启发式之一。
- **日志异常检测**：某些攻击载荷（如 SQL 注入的编码技巧）呈回文特征。
- **文本编辑器的"对称折叠"**：IDE 的括号高亮、代码折叠本质是"结构对称性"检测。

> 面试收尾时提一句"Manacher 在 DNA 序列分析这类超长串场景才真正需要"，说明你不是只会刷题。

### ⑧ eertree（回文树）：回文的"终极数据结构"

- **结构**：两棵树（奇数长度回文树 + 偶数长度回文树），每个节点代表一个**本质不同的回文**，边表示"在两端加同一个字符"。
- **能力**：O(n) 建树，O(1) 得到"本质不同回文子串个数"、"每个回文出现次数"、"最长回文"。
- **地位**：竞赛级数据结构，工程中极少用（常数大、实现复杂）。

**面试策略**：**只提名字与能力，不要展开**。说"回文树（eertree）可以在 O(n) 内建出所有本质不同回文，但工程上 Manacher 已经够用"，然后就停 —— 避免被要求写代码。

### ⑨ 回文与"字符串哈希"的通用套路

```
"判断任意子串是否回文" → 正反双哈希 O(1)
"求最长回文"          → 枚举中心 + 二分半径 = O(n log n)
"求本质不同回文数"     → 回文树 / 后缀自动机
"求回文划分最少段数"   → 预处理回文 + DP
```

```java
void insert(String w) { Node p = root;
    for (char c : w.toCharArray()) { int k = c - 'a';

    for (char c : s.toCharArray()) { int k = c - 'a';
        if (p.ch[k] == null) return null; p = p.ch[k]; }
```

# 第 9 章 面试实战：怎么把这几题讲成"高分回答"

## 9.1 手撕题的"四步口述法"（每道题都套）

```
第 1 步  澄清（30 秒）
        "输入规模多大？""只含小写字母吗？""返回最长还是任意一个？"
        "有多个答案时返回哪个？""空串怎么算？"
        ── 这一步的价值：暴露边界，避免写完才发现方向错

第 2 步  思路 + 复杂度（1 分钟）
        "我用 XX 结构，因为……；时间 O(...)，空间 O(...)"
        ── 一定要说"因为"，说清"为什么是这个结构"

第 3 步  写代码（5~8 分钟）
        先写骨架 → 再补边界 → 最后写返回
        ── 变量命名用意义的（left/right/top/start 而不是 a/b/c）

第 4 步  自测（1~2 分钟）
        跑 1 个正常例 + 1 个边界例 + 1 个非法例
        "我用 '([)]' 试一下：栈顶是 '[', 来 ')' → 类型不符 → false ✓"
```

> **为什么第 4 步这么重要**：面试官评估的"代码质量"里，**主动自测**占很大比重。多数候选人写完就停，等面试官指出 bug —— 这一停，分数就掉了。

## 9.2 每道题的"必被追问 + 标准答"

### 20 有效的括号

| 追问 | 标准答（要点） |
|---|---|
| 为什么用栈不用计数 | 计数只能判断"配平"，不能判断"嵌套"；反例 `([)]`。多类型必须记顺序 |
| 栈里存什么 | 存"左括号"（语义直白）或"期望的右括号"（比较简化） |
| 时空复杂度 | O(n) / O(n)，栈深最坏 n（全左括号） |
| 全左括号时栈多大 | n，所以 `char[n]` 够用，无需扩容 |
| 能不能 O(1) 空间 | 单类型可以（计数器）；多类型不行（必须记类型栈） |
| 有 10 种括号怎么办 | 仍是栈，只是比较逻辑换成 `Map` 或位掩码 |

### 49 字母异位词分组

| 追问 | 标准答（要点） |
|---|---|
| 为什么排序后相同就是异位 | 排序是"多重集"的确定性函数：异位 ⟺ 多重集相同 ⟺ 排序相同 |
| 有没有更快的 | 计数指纹 O(nk)，因为字母表只有 26；k 大时优势明显 |
| key 为什么不能用 `int[]` | 数组 `equals` 是引用比较，内容相同也不相等 |
| 计数拼串要注意什么 | 必须带分隔符，否则 `(1,11)` 与 `(11,1)` 都拼成 `"111"` |
| HashMap 复杂度 | 期望 O(1)，最坏 O(log n)（JDK8 树化）；key 比较是 O(k) |
| 10 亿词怎么办 | 按指纹哈希分桶 → 桶内内存分组（= MapReduce 的 group by） |

### 208 实现 Trie

| 追问 | 标准答（要点） |
|---|---|
| 为什么不用 HashSet | 前缀查询 HashSet 是 O(N)，Trie 是 O(m)；还有有序枚举、通配符、公共前缀共享 |
| 数组 vs HashMap | 数组快但 144B/节点（26 个槽），稀疏时浪费；HashMap 省空间但慢、有对象开销 |
| 空间复杂度 | O(N·Σ)（数组版），N = 总字符数；压缩 Trie 可降到 O(词数) |
| `app` 和 `apple` 怎么处理 | 同一路径，`app` 节点 `isEnd=true` 且仍有子节点 |
| 删除单词怎么做 | 沿路 `pass--`，末端 `end--`；`pass==0` 时剪掉子树 |
| 怎么支持中文 | 换 `HashMap<Character, Node>`，或按 Unicode 码点开数组（太大） |
| 工程上用什么 | ART / Radix Tree（CockroachDB、DuckDB），双数组 Trie（分词、敏感词） |

### 5 最长回文子串

| 追问 | 标准答（要点） |
|---|---|
| 为什么有 2n-1 个中心 | n 个字符中心（奇）+ n-1 个间隙中心（偶） |
| `expand` 为什么返回 `r-l-1` | 退出时 `(l,r)` 已越界/不等，真实区间是 `[l+1, r-1]` |
| 起点公式怎么来的 | 奇：`i-len/2`；偶：`i-len/2+1`；统一成 `i-(len-1)/2` |
| DP 为什么按右端点递推 | `dp[i][j]` 依赖 `dp[i+1][j-1]`（左下），必须 `j-1` 先算 |
| 有没有 O(n) | Manacher：镜像复用 + 右边界单调 → 均摊 O(n) |
| Manacher 的 while 为什么不是 O(n²) | `r` 单调不减，成功扩展总量 ≤ 2n+1；势能法可严格证明 |
| `p[i]` 和答案长度什么关系 | 原串长度 = `p[i]`（`T` 里一半是 `#`） |
| 子串 vs 子序列 | 子序列不能 Manacher，只能区间 DP（516） |

## 9.3 白板/共享屏幕的书写顺序（避免返工）

```
① 先写函数签名 + 返回类型（让面试官知道你要干什么）
② 写主循环骨架（先不写细节，注释标 TODO）
③ 填细节（从最容易的一支开始）
④ 补边界（空、单元素、全同、非法）
⑤ 跑样例（口头 trace）
```

**反例**：一上来写 `expand` 的 helper，写了 5 行发现"返回长度还是返回坐标"没想清楚 → 全部重写。**先定接口，再写实现。**

## 9.4 三个"反常识"的加分动作

1. **主动说出"这题有一个坑"**：例如 49 题说"key 不能带歧义拼接"、208 题说"`isEnd` 与有子节点是两件事"。**主动暴露陷阱，说明你真的踩过。**
2. **主动给出"次优解为什么不够"**：例如 5 题说"DP 是 O(n²) 空间，中心扩展 O(1)，所以工程上首选中心扩展"。**能比较，才是懂。**
3. **主动联系生产**：例如 208 说"这就是输入法词库 / 敏感词过滤的结构"。**面试官会认为你有落地经验。**

## 9.5 反问环节（面试官说"你有什么想问的"）

不要说"没有"。可以问：

- "咱们团队平时处理的数据规模大概什么量级？算法上更看重理论最优还是工程可落地？"
- "字符串/文本处理这块，团队是用现成的库（如 Lucene/AC 自动机），还是有自研的索引结构？"

**这两个问题都在暗示"我关心工程落地"，比问"加班多不多"高级得多。**

```
  HashMap: 数组+链表+红黑树，树化 8、退化 6、负载 0.75

【208 Trie】
  key 在路径上；isEnd 与子节点独立
  insert O(m) / search O(m) / startsWith O(m)
  数组 144B/节点；工程用 Radix/ART/双数组
  Trie 独有能力：前缀查询、有序枚举、通配符、共享前缀

【5 最长回文】
  中心扩展：2n-1 中心，expand 返回 r-l-1，start = i-(len-1)/2
  DP：dp[i][j] = s[i]==s[j] && (j-i<=1 || dp[i+1][j-1])，按 j 递增
  Manacher：T=#..#，p[i]=min(p[2c-i], r-i) 再扩展，r=c+p[c]
            答案 start=(bestCenter-bestLen)/2, len=bestLen
```
